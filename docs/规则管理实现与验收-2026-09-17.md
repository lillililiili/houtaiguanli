# 规则管理实现与验收（2026-09-17）

## 页面与当前边界

后台“系统管理 → 规则管理”入口为 `/system/response-plans`。沿用确认的三分类列表设计：核实规则、反制规则、处置规则；每条通过弹窗配置判定项、条件值、持续满足时间及启用状态。同类已启用条件全部满足才是该类配置的通过语义，零启用为暂停。没有自动/人工选择，也没有多步向导。

新页面已实现真实配置保存、启停、统一生效设置、版本记录。**运行引擎尚未消费这组新配置**，接口固定返回 `NOT_CONNECTED`，页面显示实际边界。保存/启用不下发设备、不发送通知、不改变既有自动通知、人工反制或直接反制权限。反制授权仍由既有流程独立校验。

原文字预案和空域关联从页面“查看原处置预案与空域关联”进入 `/system/response-plans/legacy`，原表、API、发布版本和关联历史保留。业务前台仅更新空域页的后台操作指引。

初始只创建三个空配置组，不把设计稿阈值和动作写入业务库。核实判定项包括置信度、观测时效、多源一致性、有效来源数量、定位误差、身份关联和连续观测时长。反制判定项包括观测时效、设备、回执通道、任务冲突、风险等级、位置状态。处置判定项包括风险状态、依据时效、事件关联、风险等级、事实来源。目录说明的是配置语义，不表示数据与执行接入已完成。

统一设置支持全部监测区域或实际空域 ID、全天或每日指定时段（北京时间、支持跨午夜）、数据不足等待 0/5/15/30 秒。处置动作独立保存通知上级、汇集证据、持续跟踪、飞手提醒；飞手提醒保留短信和电话录音分别记录回执的语义。等待结束仍无结论应进入异常，不把未知当通过；这一运行语义有待后续引擎接入。

## 接口和权限

统一前缀 `/api/v1/automation-rule-groups/{category}`，分类为 `verify/counter/dispose`，返回标准 `{ok,data,error}`。接口如下：

| 方法与后缀 | 用途 |
| --- | --- |
| GET 空后缀 | 规则组、目录、版本、真实执行接入状态、可管理标志 |
| POST `/rules` | 新建规则 |
| PUT `/rules/{id}` | 编辑规则 |
| PATCH `/rules/{id}/enabled` | 启停规则 |
| PUT `/settings` | 保存本类生效设置 |
| GET `/history?page=1&size=20` | 分页变更记录 |

读接口要求 `responsePlans.read`，写接口要求 `responsePlans.auth`；全局规则配置要求账户数据范围为 ALL。范围不足明确 403，不默默授予全局管理权。原预案仍遵循自身组织、区域边界。

所有写接口须带 `Idempotency-Key` 和 `expected_version`。每组行锁串行写入，版本冲突/重复请求返回 409。同类判定项和名称唯一；条件值始终字符串，后端校验数值整数范围、固定值/枚举白名单、持续时间 0～60、空域实际存在、动作合法及时间格式。开始等于结束不当作全天，须明确选择全天。

写入、版本增加、前后快照、差异摘要和审计同一事务；无有效变化不增加版本。聚合读取局部使用 REPEATABLE_READ，防止读到旧组版本与新规则/范围的混合结果。前端丢弃过期响应，保存期间禁重复操作；409 或网络结果未知后废弃草稿并重新读取，失败不提示成功。

迁移 `V202609170040__automation_rule_configuration.sql` 仅追加配置组、条件、空域关联及变更历史表，并将原权限显示名改为规则管理。不改权限代码，不授予设备或反制权限。正常发布后启动服务由 Flyway 执行；本次仅隔离数据库验收，未重启现有运行实例。
