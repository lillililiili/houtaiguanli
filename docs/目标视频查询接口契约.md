# 目标视频查询接口契约

日期：2026-09-22。首批仅接内部模拟链路，真实现场视频源与转流未接入。

## 只读查询

`GET /api/v1/targets/{targetId}/video`，标准 Bearer 会话与 `ok/data/error` 信封。要求设备查看权限 `devices.read`（2026-10-06 起，原为 `devices.op`；看画面是只读，值班员可看光电画面，见 OBS-03；视频流资源 `/video/streams/{streamId}/{resource}` 同一口径；发起、暂停、结束跟踪仍要 `devices.op`）、目标读取资格和目标范围；有关联设备时同时检查该设备业务范围。未登录 401；权限不足 403；不可见/不存在目标沿用目标接口 404；服务读取失败保留错误，不包装成 NO_TASK。

响应字段：`target_id`、可选 `task_id/device_id/command_id`、`checked_at`（epoch 毫秒）、`status`、`playback_type`、`simulated`、面向用户的 `reason`。

| status | 含义 |
| --- | --- |
| NO_TASK | 目标无关联任务；`reason` 同时说明目标所在机构、区域的光电设备状况：没有光电设备、光电设备都不在线（停用、离线、异常或状态未知，附台数），或光电在线只是没在跟这个目标（2026-10-06 ZT-18） |
| QUEUED | 跟踪指令排队 |
| WAITING | 已发送/受理，等待有效完成回执 |
| ENDING / ENDED | 任务结束中/已结束，停止当前画面 |
| FAILED / TIMED_OUT | 执行失败/回执超时，不可播放 |
| RECEIPT_UNAVAILABLE | 任务关联指令或匹配回执不足 |
| NOT_INTEGRATED | 已确认跟踪但未满足明确模拟源条件；真实视频流未接入 |
| AVAILABLE | 明确模拟任务及有效模拟回执，允许现有模拟画布播放 |

`playback_type` 仅 NONE 或 SIMULATED_CANVAS。只有 AVAILABLE 返回 `simulated=true`；无任务时 task/device/command 字段省略。查询优先当前 OPEN/ENDING 任务，再取最新终态任务，排序稳定。

## 可播放依据

任务为 OPEN；begin_command_id 指向同设备 EO_BEGIN_TRACK 指令且 SUCCEEDED；target、指令和光电绑定均为 mock/replay，指令显式 simulated=true。设备回执必须属于该指令，receipt_kind=PROTOCOL_C、device_result_code=200，载荷 BeginTracking、edgeId、deviceId、taskId 和 codeStatus=200 均匹配。只检查业务系统已接收的回执，不由前端伪造成功。

查询不触发跟踪、反制、历史证据写入。已有真实协议回执不代表取得真实视频流；不猜测拉流地址或厂商协议。

## 前台生命周期

共享 TargetLiveVideo 消费接口；告警、反制办理、合法性研判原有入口复用，融合感知原占位按钮打开同组件。模拟画面持续标识“非设备实拍”。目标/任务变化、收起、离页、权限丢失、请求失败清理画面；取消请求并以代次校验拒绝迟到结果。设备跟踪任务不会因为收起页面而被结束。

## 验证

EoManualTrackApiTest 覆盖只读无写入、权限/范围、排队、待回执、无匹配/错误回执、模拟可播放、真实源未接、超时失败及终态。TargetVideoPostgresTest 在限定 advisory_verify_* 数据库随机 schema 重跑相同端点测试。前台 tools/targetVideoContract.test.cjs 验证响应门槛、目标/任务变化、权限和错误、迟到响应与卸载释放。上述结果仅证明内部模拟查询与画面生命周期，不是实际设备实拍验收。

## 2026-09-28 统一光电追踪状态与控制

告警、合法性研判、非气象风险共用目标级任务。页面 GET 只读；自动调度独立于页面生命周期。详细业务规则见[一期方案](光电自动追踪一期方案-2026-09-28.md)。本节与[当前视频接入契约](designs/acceptance-cleanup/video-integration.md)共同适用；上文 SIMULATED_CANVAS 为历史实现，当前视频播放以媒体服务契约为准。

- `GET /api/v1/targets/{targetId}/eo-tracking-status`：设备读取权限、目标读取资格及范围；关联任务还检查设备范围。返回 `target_id/status/message/auto_enabled/auto_paused/demand_reasons/task/allowed_actions`。`demand_reasons` 为 `{code,label}` 数组；可选 `task` 含 `task_id/status/origin/device_id/device_name/command_status`，`origin` 为 AUTO 或 MANUAL。
- 状态枚举：IDLE、WAITING_DEVICE、STARTING、TRACKING、LOST、ENDING、END_UNCONFIRMED、FAILED、PAUSED、BLOCKED、DISABLED、ENDED。TRACKING 要求当前任务的有效光电跟踪报告与新鲜目标/设备状态，旧开始成功回执不足以证明持续跟踪。视频可用性独立判定。
- `POST /api/v1/targets/{targetId}/eo-tracking-pause` 与 `eo-tracking-resume`：设备操作权限及目标/关联设备范围，必填 8–128 字符 `Idempotency-Key`，返回同状态对象。同用户同键不能跨目标或动作复用。暂停持久保存，并申请结束当前任务；恢复不改变全局开关，也不直接创建任务。
- 人工补跟踪沿用 `POST /api/v1/targets/{targetId}/eo-tracking-tasks`，安全重试也复用该接口。服务端重新校验当前位置、设备、权限和来源模式；暂停中的人工任务不清除自动暂停。
- `allowed_actions` 是 BEGIN、PAUSE、RESUME、RETRY 的子集。前端仅显示服务端允许的动作，读取失败隐藏动作；提交后重新读取。PAUSE 无活动任务时为“暂停自动追踪”，有活动任务时为“暂停并结束”。
- 旧 `POST /eo-tracking-tasks/{taskId}/end` 保留兼容，并持久暂停所属目标；旧任务结束请求不能结束新任务。发送或停止结果未知时不盲目重新开始，不自动释放占用。收起视频不调用结束接口。

追加迁移 202609280008 保存目标级暂停、幂等控制记录与任务来源；202609280009 保存任务报告水位。已有迁移和历史材料保持原样。

## 2026-10-06 跟踪画面截图、录像取证（ZT-39）

`POST /api/v1/targets/{targetId}/video/captures`，`multipart/form-data`，必填 `Idempotency-Key`。权限：与读取跟踪视频相同的设备查看权限 `devices.read` 和设备范围，加 `evidence:ingest`（写证据的门槛），目标及关联事件需在当前用户范围内。

- 字段：`file`（必填）、`kind_code`（`EO_STILL` 截图或 `EO_VIDEO` 录像）、`stream_id`（页面正在播放的流标识）、`event_id?`（告警事件，必须是该目标或其融合前目标的告警）、`capture_age_ms?`（截图或开始录像距提交时的毫秒数，0–600000）。其他字段 400。
- 只认当前跟踪任务（TRACKING 或回报刚过期的 LOST）正在登记的视频流：未跟踪 422 `EO_CAPTURE_NOT_TRACKING`；流未登记 422 `EO_VIDEO_NOT_AVAILABLE`（测试环境提示测试视频未推流，现场设备提示现场视频尚未接入平台）；流已换成新任务 422 `VIDEO_STREAM_NOT_CURRENT`。设备、任务、来源模式由服务端按任务核定，不收客户端声明。
- 文件按证据格式白名单校验（截图 JPG/PNG/WEBP，录像 MP4/WEBM），入库为证据：归属取事件（未带事件时取目标）；关联事件、目标和同组织区域的来源光电设备；`capture_provenance=EO_TRACKING_CAPTURE`，`source_device_id` 为跟踪设备；`captured_at` = 服务端当前时刻 − `capture_age_ms`，不依赖浏览器时钟。成功 201 返回证据详情；同键重放 409 `IDEMPOTENCY_REPLAY`。审计 `evidence_ingested`（detail 含任务号）。
- 前台：告警详情、融合感知、反制办理、合法性研判等页面的实时视频下方提供“截图取证”“开始录像/停止录像”（单段最长 1 分钟），仅在视频播放时可用，不能取证的原因在点击时说明；结果显示证据编号和关联对象，可跳转证据台账。截图与录像取自平台正在播放的画面（HLS 本身有数秒延迟），测试视频画面标注“测试视频画面，非现场”。
- 边界：设备协议 B 的拍照/摄像指令（30000/30001）只下发不回传文件，协议 C 无图像，现场光电视频流尚未接入平台；现场设备的截图、录像须待厂商提供图像/视频回传或拉流方式后再接，不猜造协议字段。

## 2026-10-06 模拟光电联动

- QA 默认启用自动追踪，并将 `app.eo-edge.auto-track-source-modes` 限定为 `replay`；真实来源不因 QA 开关被启用。状态查询、调度和排队发送均按目标来源模式检查。
- 设备监测展示光电占用任务，具备 `devices.op` 的人员可经既有结束接口停止任务。提交后保持占用，只有有效停止回执才能释放；目标退出当前列表不妨碍运维查看设备占用。
- 模拟器重启后收到结束指令，仅在平台当前任务 ID 完全匹配且状态为 ENDING 时回执。未知任务、其他活动任务、查询失败均不能伪造结束成功。
- 结束待确认恢复：授权操作员可再次调用同一任务的结束接口。后台只对原结束指令为 `TIMED_OUT/FAILED/CANCELLED/UNKNOWN` 的情况生成新停止指令；处理中仍返回原指令。任务继续 `ENDING` 并占用设备，直至同任务、同设备的有效停止回执；历史指令和操作者保留。管理端“重试结束跟踪”使用此契约。

### 停止超时后的自动恢复

- 后台持续核查已进入 `ENDING` 的任务，独立于页面、自动追踪开关和目标暂停状态；只完成既有停止请求，不自动恢复被暂停的目标。
- 自动重试仅适用于已支持按任务幂等停止的 `replay` 适配器；真实 `live` 设备保持人工核查，不凭未知协议保证重发。原开始和停止指令、当前绑定必须是同一设备及显式模拟来源，目标来源、单位和区域也必须匹配。
- 原停止指令为 `TIMED_OUT/FAILED`，失败后至少等待 30 秒，并收到失败之后的新鲜心跳、确认设备在线且 broker 启用后，才为同一当前任务生成新停止指令。取消、尚在发送、来源变化、离线或心跳过期均不自动重发。排队与实际发布前再次核对任务和来源，旧指令不能停止后续任务。
- `app.eo-edge.stop-retry.enabled` 默认 true；`max-attempts` 默认 3（0 关闭，上限 10）；`delay-millis` 默认 30000（最小 1000）。配置均位于 `app.eo-edge.stop-retry` 下。追加迁移 `202610070001` 在任务中持久保存重试次数与时间，服务重启不清零；原指令、操作者与回执保留，自动重试另记设备事件。
- 重试达到上限后仍保留占用，目标状态返回 `END_UNCONFIRMED`，`message` 明确提示已达上限及人工核查。迟到的有效停止回执仍可完成释放；心跳空闲、目标失联和超时本身均不是释放依据。视频流是否可用继续独立判定。
- 开始指令超时只按 `begin_command_id` 关联原任务；仅未发送且原任务仍为 `OPEN` 时可将原任务置为 `FAILED`。原任务已为 `ENDING` 时继续等待有效停止回执，原任务已结束时不得影响同设备的后续任务。此约束同时适用于真实和模拟来源。

## 2026-10-11 光电 AI 观测只读提示

`GET /api/v1/targets/{id}/eo-tracking-status` 和现有 `GET /api/v1/targets/{id}/video` 追加相同可选 `eo_fusion_observation`：

```json
{"eo_fusion_observation":{"status":"NONE","message":"尚无可用识别观测","observed_at":null}}
```

仅当前 OPEN 跟踪任务返回该摘要；无任务、ENDING 和历史任务返回 null。该字段从同设备、同来源、同任务的协议 C AI 原始观测读取，包括未建立有效 source link 的排除证据，不从设备在线状态或 `source_links` 缺失猜测。`observed_at` 为该任务最新 AI 观测的 ISO 时间；无 AI 为 null。

| status | 含义 |
| --- | --- |
| NONE | 当前任务尚无 AI 观测证据，跟踪回执不等于识别观测 |
| CURRENT | 最新 AI 已接受，当前任务关系仍有效，观测位于现用 `identity.short_lost_after_ms` 窗口内 |
| REJECTED | 最新 AI 缺可用位置或关联排除；当前任务关系变化也归待确认 |
| EXPIRED | 最新 AI 观测超出上述融合来源有效窗口，心跳／视频不续期 |
| UNKNOWN | 证据上下文缺失、不可解析或观测时间在未来，明确待确认 |

前台公共视频组件 `TargetLiveVideo` 从既有视频响应消费 `message` 展示 NONE、REJECTED、EXPIRED 或 UNKNOWN，融合感知直接复用，跟踪面板的子视频也复用；不追加前端读取请求，不在父跟踪面板重复提示。CURRENT 的贡献事实留在融合来源展示。视频状态、播放地址与媒体门禁保持，JSON 视频读取在既有权限校验后附加摘要；HLS 清单／分段与截图取证不附加该查询。旧接口没有该字段时不补造提示。该读取不触发跟踪、停止、重试或其他业务动作，不改变任务和视频的独立有效性。真实设备接入与现场效果仍待厂家报文和实测验证。
# 2026-10-12 人工跟踪占用恢复

后台持续性维护覆盖 `MANUAL` 与 `AUTO` 的 `OPEN` 任务。人工任务沿用现有位置与同任务成功回执、光电回报、心跳的持续性判断；自动启动开关关闭仍维护人工任务，但不按自动需求消失或自动暂停来取消有效人工任务。需要结束时保存停止原因并进入 `ENDING`，只有同任务成功停止回执才变为 `ENDED`、释放占用。停止超时继续既有受限恢复机制，不直接清空任务。

`GET /targets/{id}/eo-dispatch` 保持原字段结构；排队时 `message` 列出权限范围内设备名称、占用目标编号、当前跟踪或停止待确认状态。目标与设备权限、来源范围、受保护观察及切换确认不变。业务前台共享 `EoDispatchControls` 直接显示该字段，后台目前没有独立调度消费者。GET 不创建或停止任务。

## 2026-10-20 按设备读取 RAW / AI 双流

新增 `GET /api/v1/devices/{deviceId}/video`，保留目标级接口。要求 `devices.read` 和设备范围，设备须为 EO/OE；AI 额外复用目标读取资格、当前任务、匹配成功回执、设备来源、跟踪报告、心跳和目标身份连续性校验。GET 不发起、停止、切换跟踪或启动推流。

- 公共字段：`device_id/checked_at/status/playback_type/stream_kind/stream_id/playback_url/task_id/target_id/source_mode/simulated/reason/raw_stream/ai_stream/metadata`，未适用的可选字段按既有 JSON 规则省略。时间为 epoch 毫秒。`status=RAW|AI|UNAVAILABLE`，`playback_type=HLS|NONE`。未授权目标的任务和目标身份不返回。
- 无确认跟踪时仅选择设备 RAW；当前任务通过全部校验且独立 AI 媒体就绪时选择 AI。AI 等待、断流、失效或结束时只回落同设备 RAW，并返回原因；RAW 也不可用时返回 UNAVAILABLE。设备、来源或绑定停用、设备离线不播放。真实设备缺少正式视频适配器时明确不支持，不构造厂商地址或替换模拟视频。
- `raw_stream/ai_stream` 分别含可选 `stream_id/stream_kind/playback_url` 和 `video_status=NOT_CONFIGURED|WAITING|AVAILABLE|INTERRUPTED`。RAW 租约独立于任务；切换任务不销毁 RAW，旧 AI 租约及其帧失效。
- 媒体路径 `/api/v1/devices/{deviceId}/video/streams/{streamId}/{resource}` 每次校验会话、权限、设备、来源和当前选择的流。清单及分段沿用固定媒体源、资源文件白名单、受保护 `session` 和 no-store；拒绝任意 URL、重复参数、路径穿越和已失效流。RAW 不适用目标取证。

### 帧同步检测

AI 的 `metadata={status,device_id,stream_id,task_id,frames}`；RAW、无有效 AI 或无帧时 `status=NONE,frames=[]`。帧为 `{frame_timestamp,media_time_ms,detections}`，分别为生产帧 UTC 毫秒和实际编码媒体毫秒；帧缓存最多 30 秒/300 帧，每帧最多 32 个检测。生产方必须提供可核对的媒体时钟，播放器只有与实际播放帧匹配时才展示框和点击入口；没有可信时间映射时不得按“最新观测”猜测当前画面。当前 QA 编码时钟与媒体服务 UTC 的端到端一致性仍须浏览器对账，接口实现不代表完成该验收。

检测为 `{detection_id,bbox:{x,y,width,height},class_code?,confidence?,association_status,target_id?,association_id?,observation_id?}`。bbox 为原始画面归一化坐标，边界在 `[0,1]`，宽高大于零，confidence 为 `[0,1]`。`LINKED` 必须由已存同源、同设备、同任务的 EO_TRACKING 观测及实际 `target_source_link` 导出，观测与帧时间差不超过 2 秒，并通过现行目标读取资格；客户端不能声明 target_id 或 link_id。实际关联改变或权限消失后读为 `UNLINKED`，不会保留旧可点击目标。多检测无各自有效关联时只能显示未关联，不把全部框绑定给任务主目标。

### 受控 QA 生产方

仅 `((local & qa) | test) & !prod & !production`、`app.video.qa-enabled=true` 开放下列端点，要求 `devices.op`、`devices.read`、设备范围、已启用显式模拟设备和完全一致的现有 EO 来源绑定。AI 还要求当前已确认 TRACKING。此端点是本机模拟器生产方通道，不是厂商生产接入协议。

- `PUT /api/v1/local-interface-simulator/device-video-streams/{deviceId}`：空 body，申请或续租 RAW；`DELETE` 注销。返回服务器签发的 `stream_id/stream_path/stream_kind=RAW/device_id/source_mode/expires_at` 等；不接收视频 URL。原 `PUT/DELETE /video-streams/{taskId}` 保持，返回额外 `stream_kind=AI`。
- 两类租约 60 秒到期、进程重启失效；连续续租保留 UUID。设备来源身份改变或注销重建生成新 UUID。编码器重启 PTS 归零时必须注销重建流，不能在同一流回退时间。任务切换同时清空旧 AI 帧；RAW 独立保留。新增 RAW 登记/注销记录审计，帧不写业务历史。
- `GET /api/v1/local-interface-simulator/device-video-streams/{deviceId}/observation-associations?task_id=...`：返回 `{items:[{observation_id,observed_at,class_code,target_id}]}`，仅最近 5 秒同任务设备来源、已实际关联当前任务目标的观测，模拟器不得猜 ID。
- `PUT /api/v1/local-interface-simulator/device-video-streams/{deviceId}/frames`：`{stream_id,task_id,frame_timestamp,media_time_ms,detections:[{detection_id,x,y,width,height,class_code?,confidence?,observation_id?}]}`。只接收当前 AI 流；时间不在未来、距接收不超过 5 秒，UTC 与媒体时间均严格递增。检测编号不可重复，同一观测不能在同帧重复绑定；无效或来源不符的 observation_id 保持 UNLINKED。坏坐标返回 400 VIDEO_FRAME_INVALID，旧流、旧任务和时间回退返回 409 VIDEO_TASK_MISMATCH / VIDEO_FRAME_INVALID。只允许标准大写类别码，例如 UAV。

验证覆盖 `VideoStreamRegistryTest` 的双流隔离/租约/帧时间及 `QaVideoStreamApiTest` 的无任务 RAW、鉴权/范围、来源身份改变、有效任务 AI、实存多检测关联、重复与非法帧、关联撤销、媒体丢失与任务结束回落。后者由现有 `QaVideoStreamPostgresTest` 在受保护的隔离 PostgreSQL/PostGIS 库重跑；实际执行结果以本次测试报告为准。

### 指定设备的持久跟踪排队

设备窗口请求跟踪使用原 `POST /api/v1/targets/{targetId}/eo-dispatch`，请求体追加可选 `device_id`；指定相机忙时仍保存 WAITING 请求，后台只尝试该设备，不因其他相机空闲而替换。原无 `device_id` 请求继续原自动选设备行为。既有 `POST /eo-tracking-tasks` 指定设备是立即尝试，不承接忙时排队，不能替代本入口。

- 继续要求设备操作、目标读取、当前目标引导依据和设备范围；设备绑定须启用，并与目标来源模式及组织区域一致。等待期间每次调度重新检查请求人的现行资格及设备所属关系；资格或来源关系变化后明确失败，暂时忙或离线则继续等待可用，不切换其他设备。
- 确认切换时同时发送 `device_id` 和 `expected_task_id`，原任务必须属于该设备，继续等待原停止成功回执后启动同设备。请求不隐式打断忙设备；不带 `expected_task_id` 仅等待。
- 指定设备复用已有 `eo_dispatch_request.device_id` 列，不新增迁移；WAITING 的该列是选择限制，只有原 STOPPING 状态才持有切换预留。服务重启后仍从现有持久队列恢复。
- 原目标已有另一台设备任务时不把该任务冒充指定设备请求成功。相同幂等键改设备或改原任务返回 409；同目标已有手动指定另一设备的请求时，须先明确取消后重新选择。旧客户端省略设备不能解除已有指定限制。
- GET 原调度视图追加可选 `device_id`，提示明确标出“指定光电”，可切换选项只列该设备；设备访问范围丢失后不返回其标识和名称。读取不会调度。
- `EoManualTrackApiTest` 增补一台忙、一台空闲时指定等待、幂等、停止回执后仅原设备启动及错误设备拒绝；现有 PostgreSQL 继承测试同时执行该场景。
