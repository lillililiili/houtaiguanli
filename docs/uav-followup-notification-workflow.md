# 无人机现场处置后的通知决定

2026-10-16 用户确认：已核实属实的无人机事件在现场处置结束后自动进入内部待办，操作人员决定是否通知既有上级接口。系统不替操作人员发送通知，不管理上级后续处罚办理。

## 进入条件与历史边界

有效的人工不反制决定、系统已冻结且带有效位置的 LEFT 事实、既有停止完成校验通过的处置事实，任一可作为结束依据。未核实、误报、未知位置、仅停止上报均不满足。存在未结束反制、在途/结果不明指令或急停实际停机待核查时不创建。

迁移 `V202610160001` 保存启用水位。新建事件以及部署前在办、部署后才产生新的有效结束事实的事件进入新流程；部署前已经结束的事实不补建，旧交接、旧决定、旧冻结材料不改写。结束时间按证据自身时间判断，不能使用最后更新时间冒充完成时间。多个完成授权取最新有效完成时间。

`V202610160002` 独立加固接收方为空的约束，只允许新内部待办；保留已应用的初始迁移内容和校验值。

内部待办不依赖接收方配置。没有或不唯一的接收方仍可见且可选择不通知；不能猜选目的地。材料容量超限或关联材料不完整等明确业务错误只阻断通知，待办保留明确原因，允许作出不通知决定；不截断材料或伪造空材料发送。数据库故障仍整体回滚，由后台再次扫描，页面在实际创建前只提示待建立。

后台扫描只产生内部待办及冻结事实，使用事件锁与 `handoff_notification_decision.event_id` 唯一约束保障同一事件一条。读取接口不写入。旧自动通知处罚入口委托内部待办创建，不再直接发送或自动补发；普通航线风险通知保持原流程。

## HTTP 契约

保留 `/api/v1`、Bearer、snake_case、`{ok,data,error}`。沿用 `handoff:read`、`handoff:create`、`alarm:read` 与现有机构区域范围，不增设接手、审批或手工办结。

- `GET /handoffs`、`GET /handoffs/{id}` 新增 `notification_decision`。新流程始终有对象；旧交接缺省。对象包含 `state`（`PENDING_DECISION` / `NOTIFY` / `DO_NOT_NOTIFY`）、`version`（0/1）、决定原因、真实操作人及毫秒时间。`field_handling` 只输出完成类型/时间及业务材料受阻原因；完整冻结依据不在列表输出。
- 列表、统计新增 `notification_decision` 精确筛选。指定旧 `delivery_status` 时排除待决定/已不通知，避免当作待发送。统计 `by_delivery` 增加两项新决定状态，原实际投递事实独立保留；报表和导出使用相同通知状态语义。
- `GET /handoffs/{id}/notifications` 保留原资格、尝试次数、投递与签收字段，并新增 `notification_decision`、`can_decline`、`decline_blocked_reason`。缺配置或材料仅使 `can_notify=false`，不隐含禁止不通知。
- `POST /handoffs/{id}/notifications` 沿用 `{ "expected_attempt_no": 1 }` 与 `Idempotency-Key`。第一次人工通知在交接锁内保存 `NOTIFY`、真实操作人、唯一配置接收方及快照、发送占位和审计，然后事务外调用原通道。失败重试仍使用同一交接及原接收方身份，追加尝试。已提交、未知、已送达、已签收时不盲目重发。
- `POST /handoffs/{id}/notification-decision` 接收 `{ "decision": "DO_NOT_NOTIFY", "expected_version": 0, "reason": "1至1000字说明" }` 与 `Idempotency-Key`，返回通知状态。锁内检查决定、版本及全部发送事实；已发出或结果未知不可改为不通知。决定为终态，重复或冲突请求不追加决定、不发送。
- 新流程事件不能通过旧 `POST /handoffs` 直接通知绕过待办决定，返回 `HANDOFF_FOLLOWUP_REQUIRED`。历史手工交接兼容保留。

`auto_handoff` 对新流程追加同一决定摘要。已建待办为 `PENDING_DECISION`，选择不通知为 `DO_NOT_NOTIFY`；`NOTIFY` 下按实际投递显示 `PENDING` / `SUBMITTED` / `FAILED`。没有 `handoff_id` 不表示创建成功。告警“现场处置结束”与当前位置、后续通知是否完成分开显示。

## 通道与验证边界

沿用现有配置与适配器；新待办不会因缺通知配置而回退到模拟成功。模拟仅限既有允许环境、mock/replay 来源与模拟渠道，真实来源不能走模拟通道。真实上级通道仍依赖已有适配与联调，本次不宣称真实上级已收到；接口送达、签收及上级处罚是不同事实。

`V202610169001` 为决定表追加 PostgreSQL 提交后 `punishment` 与 `alarm` 刷新信号，沿用受权限控制的重读接口。测试覆盖 H2、隔离 PostgreSQL/PostGIS、通知/不通知竞争、重复自动创建、启用水位、有效/失效不反制、冻结 LEFT、设备未结束、材料受阻、权限范围、模拟隔离与实时通知。具体运行数量与浏览器结论以本轮交付报告为准，不以静态代码代替验收。
