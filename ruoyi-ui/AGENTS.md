# 管理前端开发约定

2026-10-22 用户确认单位管理员继承单位已明确开放的全部前后台权限（仍由平台控制单位上限），不再与其个人角色取交集，任命不必新增或分配管理员角色。普通人员继续使用本单位角色与单位上限的交集。保留原人员绑定、不自动复制角色；撤任或替换时须为离任人员保留或显式选择启用的本单位角色。数据固定 OWN_ORG，不包含下级单位；平台接口、普通申请不能自审、设备及证据校验保持。直接反制只在单位显式 OP 时有效，后台运维授权不代替前台动作授权。权限收回撤销会话并重验未发送操作，已执行设备停机和回执继续。此条替代旧“管理员本人业务角色由平台单独配置”的在任权限口径。

- 使用 npm 与仓库内 `package-lock.json`，不要引入若依默认 Java 接口或 JWT 响应适配。
- API 固定遵循 `/api/v1`、Bearer 数据库会话、`{ok,data,error}`、snake_case、字符串 ID、epoch 毫秒、幂等键和版本号约定。
- 页面路由由 `/auth/me` 返回的 `menu_keys` 与 `permission_codes` 共同生成；按钮权限只负责界面体验，后端仍是最终授权边界。
- 登录状态仅写入 `sessionStorage`，不得与业务前台共享浏览器会话。
- 提交前至少执行 `npm run lint`、`npm test` 和 `npm run build`。

## 用户管理与单位资料

- 2026-10-21 后续确认：平台单位树“删除单位”采用逻辑删除，只提交单位编号和确认时版本，不要求原因。服务端检查未删除人员、未删除下级单位和未结束业务；删除后退出当前目录，授权失效，历史保留。空角色、历史人员及原授权配置不再阻断。普通删除统一确认/取消，原有必填 reason 契约使用明确标记的系统确认记录；不删改独立证据销毁或处置业务的原因字段。
- 单位树点击继续筛选用户；查看单位与新增、编辑复用基本资料表单，查看字段全部只读，不提供编辑动作或联系人、关联信息页签（2026-10-19 用户确认）。新增下级单位带入上级；联系人、来源映射和计划关联数据及后端逻辑保留。
- 原单位资料菜单与读取权限可进入合并入口，但不授予用户列表读取权限；账号权限与单位资料维护权限独立，后端继续校验。仅有原 users.auth 时保留名称/层级维护，扩展资料按 organizations.auth 控制。
- 移除独立单位档案菜单，旧地址兼容到用户管理；不删除单位、联系人、映射、计划关联或历史快照。
