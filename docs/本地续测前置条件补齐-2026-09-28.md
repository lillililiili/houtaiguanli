# 本地续测前置条件补齐

本次按用户“缺少的补上，继续测试”要求补齐本地测试条件。业务资料通过原管理、目录和模拟输入 API 创建，不向业务库手写数据，不恢复已撤回的通知配置页面。

## 限时模拟通知准备

`GET/POST /api/v1/local-interface-simulator/notification-settings` 默认不存在。只有显式设置 `app.qa.notification-setup.enabled=true`，且使用 `local,qa` 或测试 profile、没有 `prod/production` 时可用。

POST 输入为 `purpose`、`plan_id`、可选 `contact_id`、`expected_version`，沿用 Bearer、snake_case、`{ok,data,error}` 和 `Idempotency-Key`。要求 `interfaces.op`、`notificationSettings.auth`、`organizations.auth` 及 ALL 范围。读取返回配置编号、用途、版本和有效期，不返回电话或凭据。

- 必须提供当前可见的 mock/replay 计划。计划反馈关联该计划的报送单位，处罚和运维关联运营单位；联系人必须属于相同单位、具有相应用途角色且有效。
- 风险通知仍固定“上级”。短信/电话仍从实际关联计划读取执行飞手，不把单位联系人替代为飞手。
- 仅写 MOCK 配置，固定有效期为准备成功后 20 分钟；不接受 URL、真实通道或任意有效期。没有启用后台模拟发送组件时，仅有配置不会宣称已经发送。
- 禁止覆盖非 MOCK/NONE 通道或已启用的非 QA 配置。保留乐观版本、幂等冲突和追加审计。
- 该接口只准备通道和接收关系，不产生告警、审批、设备执行结果、通知送达、签收或处罚结果。通知后续仍由原有业务流程与模拟适配器处理，mock/replay 标记保留。
- 三个全局配置在 20 分钟窗口内适用于符合原规则的模拟业务。测试结束后到期阻断后续发送，已有历史快照保持。

## 设备前置条件与实测修复（21:05 更新）

新增 `POST /api/v1/local-interface-simulator/countermeasure-device`，输入 `plan_id`，具有相同的 local+qa/test、非生产、默认关闭门禁，另需 `app.qa.device-setup.enabled=true`。要求 `interfaces.op`、`devices.auth` 和 ALL 范围；只接受可见模拟计划，固定注册 `QA-LOCAL-CM4`、本机 `127.0.0.1:10006`、四通道既有协议和模拟标记。复用设备注册、来源启用、范围与审计用例，不写在线/健康状态，不授予反制资格。再次注册不覆盖既有设备。

实测发现新 TCP 设备首包因缺少状态行而抛出 `DEVICE_STATE_MISSING`。现在在处理实际回包或连接失败时锁定设备并补 UNKNOWN 初始状态，随后按协议事实更新；连接失败仍为 OFFLINE/UNKNOWN。协议状态、历史和趋势保留来源的模拟标记，修复原先固定 false 的问题。42 项 H2/PostgreSQL、门禁和相关 TCP 测试通过，已在实际本机协议链复核 ONLINE/GOOD→OFFLINE/UNKNOWN→ONLINE/GOOD。

另发现光电结束跟踪和相机状态指令已完成，但通用回执表为空。现在在命令条件更新成功的同一事务保存原始协议控制回包，重复终态回包不重复写，控制回包不进入融合感知队列。开始跟踪失败也保留失败回执。新增结束跟踪回归先复现 0 条回执，修复后 38 项光电/MQTT、PostgreSQL 与人工跟踪测试全部通过；首次运行的 2 项 Windows 临时路径环境错误在配置 ASCII 临时目录后消除。
