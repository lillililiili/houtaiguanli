# 桌面演示：气球、鸟群各关联一个任务

用户要求：桌面启动演示后，融合感知的航线风险显示气球、鸟群各一条，每条关联一个飞行任务。

## 范围与实现

- 修改桌面快捷方式实际调用的启动包中的 `30分钟正式演示场景.json`。`demo_launcher.py`、Python 模拟器和 Java 业务逻辑本轮均未修改。
- 鸟群从 5 只调整为 25 只，以满足现行鸟群风险规则；单鸟仍作为非风险感知对象保留。
- 两个模拟风险的目标路径和各自配套航线同步放到两处独立演示位置，与旧演示重叠航线分开。不是偏移页面图标，也不修改已经保存的事件位置。
- 鸟群风险明确关联鸟群目标及其配套计划；气球风险保留明确的气球目标与配套计划。沿用稳定计划标识、原报备资料和每天的任务窗口，重复启动复用既有模拟接口的任务回执。
- 原配置备份为 `30分钟正式演示场景.双风险调整前.json`。旧任务、风险、核验与通知历史保留。未开启 dev-seed，未执行核验、通知、审批或反制。
- 为清理旧重复模拟任务而尝试添加的 Java 接口改动已撤回，未编译部署。不撤回此前修复实时模拟航线风险漏显的代码。

## 验证

- 启动包原有测试 7 项通过；新增场景测试 2 项通过，覆盖两类风险与航线独立性、改变计划编号/位置/日期后重复启动的稳定任务身份。
- 按原桌面启动包启动批次 `sim-1011233546-6fe5`。真实已登录业务浏览器显示“航线风险 2”，其中“鸟群风险 · 关联 1 条任务”和“气球风险 · 关联 1 条任务”；两类发现位置均标为模拟。目标异常仍属于单独页签，不计入这两条航线风险。
- 停止后再次按同一启动包启动 `sim-1011233741-f07c`。两份实际保存的 manifest 回执逐项比较：鸟群任务 `c5a8487e-f5a1-44ce-a6e5-fdc5f2a3cfcd`、气球任务 `ace26da6-a577-4ea1-8c33-a8129815e8b6` 均相同，每类只有一个任务 ID。未增加重复关联任务。
- 第二次启动后用户已切换已登录页面；未再切换其当前页面，第二次复用验证依据为模拟接口保存的实际回执，不冒称再次完成浏览器截图验收。

这是固定演示场景的配套结果，不把真实业务的多任务风险强行缩为一条。修改报备资料、航线或日期后，平台仍按既有业务契约创建/关联任务。
