# 光电自动追踪一期方案

确认日期：2026 年 9 月 28 日

本方案适用于现有告警、合法性研判及风险详情页面。目标是让有明确观察需要的目标由后台自动申请光电，并在三个页面共用同一任务；人员只在需要补充观察、暂停或恢复时操作。保持现有页面布局与核实、通知、反制权限规则。

## 一 交付范围

一期包括自动需求判断、同目标共享任务、设备排队与占用控制、真实任务状态、人工补跟踪、暂停并结束、恢复自动追踪。复用现有设备协议、指令回执和视频播放链路。

一期不包括云台人工控制、多设备接力、自动抢占和新增管理策略页面。一期复用现有 UAV（无人机）和 BIRD（鸟类）引导协议。其他类别缺少明确引导协议时显示不支持，不将其伪装为无人机下发。实际设备覆盖能力、持续跟随效果及真实视频仍须现场联调确认。

气球的未接入提示统一为“暂未接入气球自动追踪，暂无该目标的跟踪画面。”；其他不支持的类别使用对应通用提示。类别不支持且没有进行中任务时，状态接口不提供暂停或恢复操作，已有暂停标记也不掩盖未接入原因。已有 OPEN/ENDING 任务及结果未知的历史任务保留原停止与核查入口。告警、研判、风险页面统一消费该接口，不按提示文字判断按钮资格。

此调整已通过 `EoManualTrackApiTest`、`EoTrackingPolicyTest`、`EoTrackingCommandSafetyTest` 共 58 项回归及 `package`；新增覆盖 live/replay、气球/未知类别、位置新鲜/过期、旧暂停标记和已有任务后的类别变化。实际业务账号在风险详情刷新后已显示新提示，暂停、恢复按钮均不存在。验收服务保持 `app.dev-seed.enabled=false`；此次不新增任何目标类别的设备控制能力。

## 二 告警页面规则

| 当前情况 | 系统自动行为 | 人员操作 |
| --- | --- | --- |
| 无人机告警进入待核实，关联目标有效 | 申请光电追踪，提供观察画面 | 看画面；仅按既有业务规则处理需要人工核实的事项 |
| 告警已确认，目标仍在有效观察范围 | 保留观察需求，核实完成不直接停止 | 必要时暂停或补充观察 |
| 短信、电话通知后仍需观察 | 持续跟踪，通知状态不代替目标状态 | 查看跟踪和业务进度 |
| 判为误报 | 撤销该告警需求；其他业务仍有需求则继续 | 如有新的观察理由可人工发起 |
| 历史告警、位置过期或没有实时目标 | 不用旧位置重新下发 | 查看历史依据，等待新鲜观测 |

光电丢失目标不能直接判定飞离；看见目标也不能直接赋予反制资格。既有反制授权与执行条件保持不变。

## 三 合法性研判页面规则

| 当前情况 | 系统自动行为 | 人员操作 |
| --- | --- | --- |
| 当前违法或异常研判，已有相关告警 | 与告警共享同一目标跟踪任务 | 本页查看画面，核实入口仍按原分工 |
| 当前异常行为需要观察，尚未有关联告警 | 根据已保存的研判事实申请追踪 | 处理确实需要复核的信息 |
| 不可判定，怀疑需要补看目标或行为 | 当前研判协议未定义明确视觉补证原因，一期不据此自动触发 | 在位置、类别、设备及权限满足时人工补跟踪，结合原始数据核对 |
| 仅缺计划、身份线索、规则参数、时间或高度基准 | 不因这些缺口自动追踪 | 核对对应数据；有额外观察需要时人工发起 |
| 已明确合法且没有其他观察需求 | 默认不占用光电 | 需要抽查或发现新的异常时人工发起 |
| 旧研判或被新结果替代的研判 | 不由打开历史记录触发追踪 | 查看历史依据或最新结果 |

合法性复核仍只在算法依据不足、需要人工核对时进行；本次不增加对明确合法或明确违法结论的逐次人工确认。视频不能替代报备计划、实名身份或可信高度基准。

## 四 风险详情规则

| 风险情况 | 系统自动行为 | 人员操作 |
| --- | --- | --- |
| 空中异物进入走廊或机场保护区，需要确认实物 | 在类别与引导协议支持时自动追踪；高风险优先 | 自动未启动且具备条件时补跟踪 |
| 仅邻近航线且低风险、已有依据充分 | 默认不持续占用设备 | 核验人员需要补看时发起 |
| 飞行作业风险关联实时目标，存在偏离航线等可观察异常 | 按保存的风险原因申请追踪 | 规则未覆盖但有观察需要时人工发起 |
| 空域风险关联实时目标，正在接近或进入关注空域 | 按当前风险需求申请追踪 | 需要额外观察时人工发起 |
| 仅为计划、时段或空域资料冲突，无实际目标 | 不申请目标追踪 | 核对业务数据 |
| 气象风险 | 保持现有页面，不显示目标追踪面板 | 查看气象依据，办理核验及通知 |

一期自动观察原因包括航线偏离、空域冲突、进入走廊或机场保护区、禁飞空域重叠及碰撞风险；高风险和严重风险也可贡献观察需求，但气象与仅缺数据的原因除外。风险从待核验进入待通知、已通知或已回执，不单独证明风险解除。已排除的风险不再贡献跟踪需求；实时目标过期则停止使用过期位置下发，不能宣称已解除。

## 五 共享任务与人工操作

同一个目标在告警、研判和风险中共用任务。后端根据当前有效业务事实计算观察需求，并在页面显示需求原因。一条业务完成，只撤销自己的需求，不能直接终止其他业务正在使用的任务。

| 页面状态 | 显示与操作 |
| --- | --- |
| 等待设备或正在锁定 | 显示真实进度，不重复发起 |
| 已有有效跟踪回报 | 显示跟踪中，可查看视频或暂停并结束 |
| 无自动需求但人员需要观察 | 显示人工补跟踪 |
| 明确失败且允许安全重试 | 显示重试追踪，服务端重新校验 |
| 发送或停止结果未知 | 显示待核实，不自动释放设备或盲目重发 |
| 已人工暂停 | 保持暂停，直到人员选择恢复自动追踪 |
| 无权限、位置过期、缺少目标、设备不可用 | 显示具体原因，不通过人工点击绕过 |

“暂停并结束”是目标级操作，会暂停该目标各页面共用的自动追踪需求，并申请结束当前任务。暂停状态持久保存，刷新页面或重启服务不解除。暂停期间人工补跟踪属于单次人工任务，不自动恢复后台调度；该次人工任务仍可通过“暂停并结束”停止，并继续保留自动暂停。恢复自动追踪只恢复该目标资格，不开启系统总开关，也不直接宣称设备已开始跟踪。

## 六 设备与回执约束

平台下发前检查目标权限及范围、当前位置时效、类别协议支持、模拟与真实模式、设备状态和任务占用。无空闲设备时保留等待需求，下次调度重新检查当前条件。一台设备同时承接一个任务，一期不抢占其他目标任务。

排队、已发送、设备受理、有效跟踪回报及视频可用分别处理。结束超时或开始结果不确定时保留设备占用，等待可信回执或状态核实；不靠等待固定秒数生成成功。重复、过期及迟到回报不能恢复旧任务或污染新任务。旧版本留下的“已发送但超时”任务也按未确认占用处理；原设备已有更新任务时，旧任务的停止操作不得误停新任务。

自动调度由后端执行，不依赖页面打开。三处页面查询均只读；视频收起只停止播放，不停止后台追踪。查看视频和发起设备动作使用各自接口，视频无法播放不等于没有跟踪。

## 七 页面与实施安排

告警页沿用视频位置，移除重复的旧跟踪按钮区；合法性页在原视频区补充统一状态与操作；风险详情保留原适用范围并复用公共面板。不调整菜单、地图、业务核验入口、风险通知目的地或反制办理流程。

后端统一解析自动开关并兼容旧配置，提供只读状态与暂停恢复接口。自动开关继续使用部署环境的显式配置；实现代码不等于已启用真实设备自动动作。时效参数为工程配置，不能当作已通过硬件标定的指标。

## 八 验收与交付记录

验收范围包括自动触发与排除、三个入口共享任务、人工暂停恢复、重复请求、并发占用、过期位置、来源模式隔离、越权、未知执行结果、迟到回执和重启后的持久状态。008/009 迁移和新增 SQL 已在隔离 PostgreSQL/PostGIS 执行验证。前端构建、173 个文件扫描、API 模块语法检查及项目外组件挂载交互测试通过。

真实浏览器已验证告警页暂停、合法性页同目标同步与恢复、风险页暂停、位置过期阻断，以及收起视频不结束后台任务。页面保留原布局，控制台未发现错误。独立代码审查发现的人工改判候选遗漏与暂停后人工任务无法直接结束两项问题均已修复，并补充对应后端测试。后端专项回归共 89 项通过：状态与控制 H2 10 项、PostgreSQL 10 项、策略 5 项、指令安全 6 项、MQTT H2 19 项、PostgreSQL 19 项、认证 9 项、视频接口 11 项。上述为本次分轮专项回归，未宣称全仓全量测试。

部署环境的自动总开关仍保持关闭，未擅自启用真实设备自动动作。真实光电设备、镜头跟随、覆盖范围及现场视频尚未验收；本地模拟与接口测试不能替代现场验收。
