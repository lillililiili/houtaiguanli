# 目标视频查询接口契约

日期：2026-09-22。首批仅接内部模拟链路，真实现场视频源与转流未接入。

## 只读查询

`GET /api/v1/targets/{targetId}/video`，标准 Bearer 会话与 `ok/data/error` 信封。要求现有 `devices.op`、目标读取资格和目标范围；有关联设备时同时检查该设备业务范围。未登录 401；权限不足 403；不可见/不存在目标沿用目标接口 404；服务读取失败保留错误，不包装成 NO_TASK。

响应字段：`target_id`、可选 `task_id/device_id/command_id`、`checked_at`（epoch 毫秒）、`status`、`playback_type`、`simulated`、面向用户的 `reason`。

| status | 含义 |
| --- | --- |
| NO_TASK | 目标无关联任务；`reason` 同时说明目标所在机构、区域的光电设备状况：没有光电设备、光电设备都不在线（停用、离线、异常或状态未知，附台数），或光电在线只是没在跟这个目标（2026-10-06 ZT-18） |
| QUEUED | 跟踪指令排队 |
| WAITING | 已发送/受理，等待有效完成回执 |
| ENDING / ENDED | 任务结束中/已结束，停止当前画面 |
| FAILED / TIMED_OUT | 执行失败/回执超时，不可播放 |
| RECEIPT_UNAVAILABLE | 任务关联指令或匹配回执不足 |
| NOT_INTEGRATED | 已确认跟踪但未满足明确模拟源条件；真实视频流未接入 |
| AVAILABLE | 明确模拟任务及有效模拟回执，允许现有模拟画布播放 |

`playback_type` 仅 NONE 或 SIMULATED_CANVAS。只有 AVAILABLE 返回 `simulated=true`；无任务时 task/device/command 字段省略。查询优先当前 OPEN/ENDING 任务，再取最新终态任务，排序稳定。

## 可播放依据

任务为 OPEN；begin_command_id 指向同设备 EO_BEGIN_TRACK 指令且 SUCCEEDED；target、指令和光电绑定均为 mock/replay，指令显式 simulated=true。设备回执必须属于该指令，receipt_kind=PROTOCOL_C、device_result_code=200，载荷 BeginTracking、edgeId、deviceId、taskId 和 codeStatus=200 均匹配。只检查业务系统已接收的回执，不由前端伪造成功。

查询不触发跟踪、反制、历史证据写入。已有真实协议回执不代表取得真实视频流；不猜测拉流地址或厂商协议。

## 前台生命周期

共享 TargetLiveVideo 消费接口；告警、反制办理、合法性研判原有入口复用，融合感知原占位按钮打开同组件。模拟画面持续标识“非设备实拍”。目标/任务变化、收起、离页、权限丢失、请求失败清理画面；取消请求并以代次校验拒绝迟到结果。设备跟踪任务不会因为收起页面而被结束。

## 验证

EoManualTrackApiTest 覆盖只读无写入、权限/范围、排队、待回执、无匹配/错误回执、模拟可播放、真实源未接、超时失败及终态。TargetVideoPostgresTest 在限定 advisory_verify_* 数据库随机 schema 重跑相同端点测试。前台 tools/targetVideoContract.test.cjs 验证响应门槛、目标/任务变化、权限和错误、迟到响应与卸载释放。上述结果仅证明内部模拟查询与画面生命周期，不是实际设备实拍验收。

## 2026-09-28 统一光电追踪状态与控制

告警、合法性研判、非气象风险共用目标级任务。页面 GET 只读；自动调度独立于页面生命周期。详细业务规则见[一期方案](光电自动追踪一期方案-2026-09-28.md)。本节与[当前视频接入契约](designs/acceptance-cleanup/video-integration.md)共同适用；上文 SIMULATED_CANVAS 为历史实现，当前视频播放以媒体服务契约为准。

- `GET /api/v1/targets/{targetId}/eo-tracking-status`：设备读取权限、目标读取资格及范围；关联任务还检查设备范围。返回 `target_id/status/message/auto_enabled/auto_paused/demand_reasons/task/allowed_actions`。`demand_reasons` 为 `{code,label}` 数组；可选 `task` 含 `task_id/status/origin/device_id/device_name/command_status`，`origin` 为 AUTO 或 MANUAL。
- 状态枚举：IDLE、WAITING_DEVICE、STARTING、TRACKING、LOST、ENDING、END_UNCONFIRMED、FAILED、PAUSED、BLOCKED、DISABLED、ENDED。TRACKING 要求当前任务的有效光电跟踪报告与新鲜目标/设备状态，旧开始成功回执不足以证明持续跟踪。视频可用性独立判定。
- `POST /api/v1/targets/{targetId}/eo-tracking-pause` 与 `eo-tracking-resume`：设备操作权限及目标/关联设备范围，必填 8–128 字符 `Idempotency-Key`，返回同状态对象。同用户同键不能跨目标或动作复用。暂停持久保存，并申请结束当前任务；恢复不改变全局开关，也不直接创建任务。
- 人工补跟踪沿用 `POST /api/v1/targets/{targetId}/eo-tracking-tasks`，安全重试也复用该接口。服务端重新校验当前位置、设备、权限和来源模式；暂停中的人工任务不清除自动暂停。
- `allowed_actions` 是 BEGIN、PAUSE、RESUME、RETRY 的子集。前端仅显示服务端允许的动作，读取失败隐藏动作；提交后重新读取。PAUSE 无活动任务时为“暂停自动追踪”，有活动任务时为“暂停并结束”。
- 旧 `POST /eo-tracking-tasks/{taskId}/end` 保留兼容，并持久暂停所属目标；旧任务结束请求不能结束新任务。发送或停止结果未知时不盲目重新开始，不自动释放占用。收起视频不调用结束接口。
