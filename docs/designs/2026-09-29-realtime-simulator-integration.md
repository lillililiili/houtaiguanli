# 数据模拟器实时接入方案

## 用户目标

2026-09-29：平台直接连接数据／设备模拟器，由模拟器持续产生符合协议的数据来模拟真实情况。停止依赖后端 MOCK 成功返回、预置业务样本和手工数据库注入。设备上报、平台研判、通知请求和接收回执形成可观察的实时链路。

用户重新登录后继续实施。代码已落地，具体运行验证记录见运行说明。

## 当前验证结果

- 业务后端监听 8081；主要设备模拟器监听 8766；另一个模拟器 8767 指向隔离后端 18091，不应混用。
- 8766 当前保存场景为“QA电话未接通与发送重启”，运行状态 STOPPED，mqtt_ready=false。平台 MQTT Broker 连接成功不能证明模拟设备正在发送。
- 调用 8766 的连接操作后，真实后端返回 401，确认旧登录会话已失效；模拟器已清除失效的内存登录状态。
- 通知目录六项设置均为 MOCK 且已过期。LocalQaNotificationService.prepare 每次设置 20 分钟有效期。
- LocalAdvisorySmsAdapter / LocalAdvisoryVoiceAdapter 目前通过后端模拟器实现短信和电话结果。
- MockSuperiorHandoffChannel 对有绑定的风险／移送请求可进入外部消息通道，但没有绑定时会直接返回模拟送达／签收。
- 当前 notification_inbox.py 主要读取平台已保存的业务事实，不等于模拟器接收了独立通知请求。
- 既有 Runtime.run 已通过真实 MQTT 连接发布设备报文并等待 PUBACK；设备身份和业务来源使用 replay，不能把模拟设备改标成现场 live 设备。

## 实施方案

### 一、统一入口和设备连接

使用 8766 模拟器和 8081 后端。登录状态、MQTT 实际连接、当前上报任务分别显示，并携带最近成功验证时间。失效会话显式要求重新登录，不能仅凭内存中存在客户端对象显示“已连接”。

沿用模拟器正常设备注册 API、真实 MQTT 发布和平台数据接入链。持续模式在明确启动后保持上报，直到用户停止、会话失效或连接失败。场景恢复必须经过当前登录与设备归属检查，不自动续播旧异常测试。停止和断连不得生成新观测或认定飞离。

计划、空域、天气等配套输入使用现有受权 API，不走 Prerequisites 的数据库直写路径，不预置事件、研判、通知成功或反制结果。

### 二、独立通知请求和回执

复用既有 API 通道类型，以 endpoint_ref=local-data-simulator 明确区分独立接收端；运行环境设置 app.notifications.transport=simulator 与 app.handoff.channel=simulator，停用 MOCK 成功回退。来源标识保留 simulated/replay 以便追溯。

复用既有持久化消息与受权回执设计，补齐短信、电话、计划反馈、风险上级、处罚移送和运维通知。每条请求包含稳定的逻辑通知标识、发送尝试标识、关联业务、接收对象快照、内容／录音引用和提交时间。

模拟器后台接收进程持续拉取当前账号有权处理的请求；接收与回执不依赖浏览器页面是否打开。平台先保存提交事实，只有收到匹配请求和尝试的回执才推进送达、接通、播放完成或签收。模拟器支持接收失败、拒接、延迟和不回执；无回执保留未知，不伪造成功、不盲目重复发送。

电话接通与播放完成分开，短信送达与电话播放完成分别启动 3 秒和 10 秒观察。目标是否撤离仅根据模拟器之后实际上报的有效位置判断。

### 三、连接时效与配置有效期

用接收端后台心跳／租约表示模拟器当前在线。模拟器在当前有效会话、权限和启用配置下续租，断开后租约过期。配置不再通过每次准备 20 分钟 MOCK 通道维持运行。

在线租约不替代联系人有效期、通知动作权限、数据范围或反制授权。更新配置不覆盖已冻结接收对象和历史结果；旧 MOCK 历史只读保留。

### 四、来源与兼容

使用独立模拟器生成动态协议输入，不在后端生成业务结果。历史 simulated／replay 来源信息保留用于追溯，界面可表达为“数据模拟器”，不能冒充真实短信运营商、现场设备或真实射频操作。

新增 Flyway 版本承接必要的通道／消息字段和约束，不修改已应用迁移。鉴权沿用 Bearer 数据库会话、既有接口操作权限和数据范围；消息不得跨账号、跨事件或跨发送尝试处理。

## 验证与切换

1. 回归设备持续上报、暂停、停止、连接失败、会话失效；验证发布计数、平台接收计数和最新观测时间持续变化。
2. 独立 PostgreSQL/PostGIS 验证迁移、消息幂等、错误对象、越权、重复及迟到回执、服务重启恢复。
3. 验证平台提交后无模拟器回执时不得成功；模拟器确认后推进对应状态；断开后不回退 MOCK。
4. 验证短信 3 秒、电话 10 秒观察及新位置判断；停报保持未知。
5. 构建并重启受影响服务，核对 8081、8766 及受影响页面 HTTP 200，实际运行一个用户选定场景。

## 操作前置条件

- 用户已在 8766 模拟器重新登录当前 8081 系统；独立接收进程复用其内存会话，不读取或传递密码。
- 当前旧场景包含电话失败／重启测试；实时运行使用的场景仍待用户选择，不默认启动它。

## 方案取舍

- 采用：持久化请求＋独立模拟器接收回执。可验证完整链路并保留异常事实，需扩展当前通知适配器和消息类型。
- 不采用：仅延长 MOCK 设置。仍然由后端自行返回结果，不能达到本次目标。
- 不采用：将模拟来源直接改成 live。改变标签不能产生外部通知或设备事实，而且会破坏来源隔离。
