# 设备异常通知与运维待办

代码状态：已实现，按用户要求未运行测试、构建、数据库迁移或运行验收。

## 用户操作

业务前台的飞行计划设备检查列表、地图设备悬停卡片都使用“通知设备异常”。当前有异常或尚未关闭告警的设备才显示此操作；只有历史已关闭告警时保留信息，不发起新通知。

点击后，后端重新核对可见计划、可见设备、航线附近范围和设备异常事实，保存一条运维待办。页面得到 `task_id` 才提示成功。待办不是短信、邮件、外部消息或重启指令。

管理端进入“运维管理 → 设备实时监测 → 运维待办”查看。待办随监测总览的既有刷新节奏读取，也可手动刷新；支持待处理、已反馈、全部和分页。具备操作权限者填写处理结果后，待办进入“已反馈”，保留报告人、报告时刻、通知时设备状态及处理人/时刻/内容。此操作不关闭设备告警、不下发重启，也不把设备自动标成恢复。

## API 与权限

- `POST /api/v1/flight-plans/{planId}/device-maintenance-tasks`：请求 `{ "device_id": "设备ID" }`，带 `Idempotency-Key`（8–128 字符）。需要 `handoff:create`、`flight:read`、`devices.read`、`monitoring.read`；新建时读取附近检查还需 `route:read`。沿用已有独立通知权限，不给只读用户增加写权限。
- `GET /api/v1/device-maintenance-tasks?status=PENDING&page=1&size=20`：需要 `monitoring.read`；`status` 为 `PENDING/HANDLED/ALL`，页从 1 起，size 为 1–100。返回 `items/page/size/total`。
- `POST /api/v1/device-maintenance-tasks/{taskId}/handling`：请求 `{ "expected_version": 1, "note": "处理结果" }`，带幂等键，需要 `monitoring.read` + `monitoring.op`；处理结果为 2–1000 字。版本或状态变化返回 `409 MAINTENANCE_TASK_CHANGED`，同键重放沿用既有 `409 IDEMPOTENCY_REPLAY`。

所有接口沿用 Bearer 数据库会话、snake_case 和 `{ok,data,error}`。待办包含 `task_id/device_id/device_no/device_name/reason/connectivity/health_code/observed_at/last_heartbeat_at/simulated/status/reported_by_name/reported_at/handled_by_name/handled_at/handling_note/version/can_handle/reused`；可省略未知时间及未处理字段。`plan_id/plan_no` 仅在仍有该计划读取权限和范围时返回。

待办按上报计划的组织/区域限制数据范围，同时保留 MQTT 设备的显式归属限制；被逻辑删除的设备待办暂不展示，数据库记录保留。`can_handle` 是界面提示，提交仍重新校验权限、范围与版本。

同一计划、同一设备在未处理时仅有一条待办。设备行锁和 `active_key` 唯一约束共同控制并发。每个提交键与操作者、原请求对应的待办持久关联；相同键重试返回原结果，跨计划或设备复用键返回 409。再次点击已有待办返回 `reused=true`。已反馈后的再次通知生成新记录，不覆盖原记录。所有写操作和审计在同一事务中。

## 部署前提

服务实现位于 `houtaiguanli/server`；业务前台和管理端必须连接这一个 API 与同一数据库。两个前端各自登录，不共享浏览器 sessionStorage 或复制令牌。

此会话的业务前台源码位于 `dongyiwurenji/dongying-vue`，其 Vite 代理默认仍为 8080；管理端后端默认 8081。不要只把单个通知接口代理到另一个后端，否则前台登录会话与计划/设备 ID 会不一致。

部署时使用 `APP_API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev`（在业务前台目录）或既有 `APP_PUBLIC_API_BASE_URL` 配置统一 API 地址，再重新登录。生产反向代理同理。这里记录配置要求，本次没有改动已有代理默认值、启动服务或迁移旧库数据。

新增迁移 `V202609150001__device_maintenance_tasks.sql` 创建待办与提交去重表；需由新版后台正常启动时应用。旧版本接口不存在会明确报错，不退回模拟成功。
