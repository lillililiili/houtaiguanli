# 设备运维接口契约

版本：V1.6；日期：2026-09-09。

2026-09-10 补充：启用的 MQTT/EO MQTT 设备在曾收到有效心跳后超时离线，会生成 `MQTT_HEARTBEAT_TIMEOUT` 异常；同设备同类未恢复事件不重复创建。该协议没有重启定义，事件 `POST /device-incidents/{id}/reboot` 返回 409 `REBOOT_NOT_SUPPORTED`，详情 `allowed_actions` 为 `VERIFY_RECOVERY`。`POST /device-incidents/{id}/recovery-checks` 可从 PENDING 核验：必须在线、事件发生后取得新心跳且心跳新鲜，通过后 RECOVERED，否则保留原阶段。这只证明连接恢复，不推定其他健康指标。其他设备异常继续沿用原重启及回执流程。

本契约对应“运维管理”下设备管理、设备实时监测、设备接入调测三页。运行中的运维台账不再预置开发模拟设备；`mock` 适配器仅保留给隔离测试。已按资料实现 `RADAR_TCP_V3_0_0` 与 `COUNTERMEASURE_TCP_4CH_V2_0` 两种 live 协议能力。适配器按 `source_mode + protocol_code` 路由；live 连接或协议失败不会回退为 mock 成功。

## 1. 通用约定

- 根路径：`/api/v1`。前端默认同源访问 `/api`，本地 Vite 代理至 `127.0.0.1:8080`，可用 `APP_PUBLIC_API_BASE_URL` 覆盖 API 根路径。
- 认证：`Authorization: Bearer <session_id>`。`session_id` 存在浏览器 `sessionStorage`；刷新通过 `GET /auth/me` 校验，401 清理会话并返回登录页。
- 字段：snake_case；所有业务 ID 均为字符串；时间为 Unix epoch 毫秒。
- 信封：成功 `{ "ok": true, "data": ... }`；失败 `{ "ok": false, "error": { "code": "...", "message": "..." } }`。
- 空值：Jackson 忽略 null。字段缺失表示未知或没有事实，前端不得补成 `0`、在线、正常或通过。
- 模拟：模拟对象返回 `source_mode: "mock"`、`simulated: true`；live 对象返回 `source_mode: "live"`、`simulated: false`。界面只对前者显示“模拟回执”“模拟通过”。协议模拟器通过不等于已完成甲方现场联调。
- 权限：`*.read` 控制读取，`*.op` 控制写操作。`ROLE-ADMIN` 固定拥有全部权限；其他账号仅依据超级管理员配置的自定义角色权限访问，未知或未授权角色拒绝。

## 2. 设备台账

### `GET /devices`

参数：

| 参数 | 约定 |
| --- | --- |
| `page/size` | 默认 1/20；size 为 1–100 |
| `keyword` | 匹配设备编号或名称，最长 100 字符 |
| `type_code/channel/region/vendor` | 精确筛选 |
| `connectivity` | `ONLINE/OFFLINE/ABNORMAL/UNKNOWN` |
| `enabled` | `true/false` |
| `sort` | `priority`、`device_no_asc/desc`、`name_asc`、`type_asc`、`owner_asc`、`vendor_asc`、`connectivity_asc`、`last_heartbeat_desc` |

默认 `priority` 顺序为异常、离线、未知、在线，再按设备编号。结果为 `{items,page,size,total}`。列表摘要包含台账 `version`、启停状态、最新连接/健康状态、告警标志与最后心跳。

### 其他台账接口

| 方法与路径 | 行为 |
| --- | --- |
| `GET /devices/options` | 返回 `types/channels/regions/vendors` 当前可用筛选项 |
| `GET /devices/{device_id}` | 台账详情、最新指标与连接配置可见性；无 `devices.op` 时 `connection_visible=false` 且不返回连接对象 |
| `POST /devices` | 创建设备；设备编号、名称、类型名称和通道必填 |
| `POST /devices/onboard` | TCP：一次接入一台 live 设备。MQTT：`LINGYUN_MQTT_V8_6` 登记雷达/5G-A/TDOA/AOA/协议破解/RemoteID；`EO_EDGE_MQTT_20250826` 登记光电边端（`edge_id` + 外部 `deviceId`）。须带 `Idempotency-Key` |
| `PUT /devices/{device_id}` | TCP：乐观锁更新台账与连接配置。MQTT：只能改名称/厂家/型号，接入身份不可变 |

### MQTT 连接（协议 A P1）

写接口须 `Idempotency-Key`（8–128）与 `interfaces.op`；读接口 `interfaces.read`。配置与 API **不返回密码**，只存 `credential_ref=env:变量名`。`source_mode` 为 `replay`（模拟回放）或 `live`（真实来源，待联调）；启用 live 必须有用户名和凭据。回环地址仅 local/test 的 replay 可用。修改配置前必须先停用。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /mqtt-brokers` | 当前数据范围内的连接列表，含 `connection_state`，不含密码 |
| `GET /mqtt-brokers/scopes` | 可登记的组织/区域 ID |
| `POST /mqtt-brokers` | 新增，默认停用 |
| `PUT /mqtt-brokers/{id}` | 停用后方可改主机/端口/TLS/凭据；来源模式与组织区域不可改 |
| `PATCH /mqtt-brokers/{id}/enabled` | `{enabled,version}` 启停 |

设备详情对 MQTT 返回订阅状态、最近工参/目标报文时间、重复/冲突/疑似缺报。工参维持在线（30 秒无有效工参离线）；目标报文写入 `inbox_message`，`source=lingyun:<type>:<内部设备ID>`，`source_msg_id=<ptTime>:<msgCnt>`。内部设备 ID 在首次登记时分配且更新不改号；无 `taskId` 的雷达/TDOA/AOA/协议破解/RemoteID 用该 `source` 串作融合会话键，删除重登或迁库改号会使同一台设备的目标分叉。本轮不提供重启、控制或调测成功。

光电边端（`EO_EDGE_MQTT_20250826`）订阅 `iot-reporting/cmlc/edge/{edgeId}`，下发 `iot-dispatcher/cmlc/edge/{deviceId}`。HeartBeat（默认 3 秒无心跳离线）更新在线态与 `cameraStatus`；`workState` 0 空闲 / 1 工作 / 2 自主探测，0 不是离线。跟踪上报写入 `inbox_message`，`source=eo-edge:<edgeId>`，`source_msg_id=<timestamp>:<event>:<deviceId>:<taskId或'-'>`。BeginTracking / EndTracking / CameraStatus 走 `device_command`。角度移动、home 点、辅助识别开关标「设备协议未提供」，不实现。有效告警或高风险目标会自动选择同机构、同辖区的在线空闲光电设备；本地 `local` profile 默认开启，生产默认关闭并由 `app.eo-edge.auto-track.enabled` 显式开启。人工补跟踪：`POST /api/v1/targets/{targetId}/eo-tracking-tasks`（`Idempotency-Key`，可选 `device_id`/`reason`）→ 202；`GET` 同一路径查进行中任务（有任务返回任务对象；无任务 `200` 且 `data` 省略，不是 404）；`POST /api/v1/eo-tracking-tasks/{taskId}/end` 停止。权限 `devices.op`，目标须 `target:read` 可见。无经纬度 422 `TARGET_POSITION_UNAVAILABLE`；无在线空闲光电 422 `EO_DEVICE_UNAVAILABLE`；已有任务 409 `TRACK_ALREADY_OPEN`。雷达 TCP 与四通道反制不改。

本地 `local` profile 会幂等登记名为 `local-lingyun-replay` 的 replay 连接（`127.0.0.1:1883`，匿名、仅回环）以及 NDJSON 回放设备 `S85R1`/`S85T1`/`S85A1`/`S85G1`/`S85D1`/`S85I1`/`S85E1D1`/`S85Y1`/`S85F1`/`S85B1`（诱骗/干扰/驱鸟炮）。`S85R1` 不是现场 T02 TCP 雷达；`test` profile 不插入这些设备；inbox `RECEIVED` 不等于融合已出目标。工参成对经纬度仅在台账坐标为空时写入，不覆盖已有坐标、不自动创建设备。控制类只收工参、不写融合 inbox。Compose Mosquitto 与发布步骤见 [后端 README](../server/README.md)「本地 MQTT 模拟」和[凌云回放说明](直连接入计划/凌云回放说明.md)。配置了 replay 或本机发通报文，不等于现场 MQTT 已联调。

`source_id` 与 `external_device_id` 必须同时为空或同时存在；经纬度也必须成对出现。坐标按声明值保存，首版默认 WGS-84，不转换坐标，也不推算 AGL/AMSL。

### 来源与协议专属配置

`GET /device-protocols` 返回协议版本、只读能力、配置字段及默认地址提示。`GET/POST/PUT /integration-sources` 和 `PATCH /integration-sources/{id}/enabled` 维护 live 来源；来源创建后固定为停用，启用时逐台校验协议适配器、TCP 配置、协议配置、凭据引用和 CIDR 白名单。回环、链路本地、云元数据地址及白名单外地址即使能解析也拒绝连接。

设备请求可携带 `protocol_configuration`：

```json
{
  "login_role": "DATA",
  "recognition_code_ref": "env:RADAR_RECOGNITION_CODE",
  "rtk_enabled": true,
  "coordinate_transform_enabled": false
}
```

雷达登录角色固定为数据权限 `0x5`。登录附加数据为权限类型 UINT32 + 识别码 UINT32（共 8 字节）；登录回包先读 4 字节权限类型再读 UINT16 状态码。非零识别码只通过 `env:` 凭据引用解析，不进入响应、日志或报告。

```json
{
  "device_address": 1,
  "wire_encoding": "AUTO",
  "poll_interval_millis": 5000
}
```

四通道设备地址只允许 1–244，广播地址 245 被禁止。查询帧与资料金样一致，为 `55 <地址> 10 00 00 00 01 <累加和>`。设置金样：通 1 开 `55 01 12 00 00 00 01 69`、关 `55 01 11 00 00 00 01 68`；全开/迫降 `55 01 13 00 00 00 0F 78`；全关 `55 01 13 00 00 00 00 69`；驱离掩码 `0x0D`。回码帧头 `0x22`，功能码与请求相同。`AUTO` 按资料“字符格式发送”依次探测 `ASCII_HEX_SPACED/ASCII_HEX_COMPACT/RAW_BYTES`，本次会话识别后固定编码。调测和轮询只发 `0x10`。不实现 `0x14` 及之后、无回码连发。

### 重启

`POST /devices/{device_id}/commands/reboot` 返回 HTTP 202。必须提供唯一的 `Idempotency-Key` 请求头和 `{ "reason": "..." }`。同一键、同一请求返回原命令；同一键、不同载荷返回 `IDEMPOTENCY_CONFLICT`。该路径不推进 `device_incident`。

工作台设备异常处置走异常单（权限 `monitoring.op`，读详情 `monitoring.read`；`Idempotency-Key` 8–96）：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /device-incidents/{incident_id}` | 异常摘要、`reboot_command_id`、最近一次恢复校验、`allowed_actions`（`REBOOT` / `VERIFY_RECOVERY`） |
| `POST /device-incidents/{incident_id}/reboot` | `{reason}` 2–500 字；仅 `PENDING`；内部复用设备重启命令。202 后 stage=`PROCESSING`。非 PENDING 409 `INVALID_TRANSITION`；离线/停用/协议未声明重启 409 `DEVICE_NOT_OPERABLE`，stage 不变 |
| `POST /device-incidents/{incident_id}/recovery-checks` | 仅 `PENDING_VERIFICATION`。规则 `ops-incident-recovery-v1`：`ONLINE && !has_alarm && health_code=GOOD` → `PASS` 并 `RECOVERED`+`closed_at`；连接 `UNKNOWN` → `UNKNOWN` 不关闭；其余 `FAIL` 不关闭 |

回执：`SUCCEEDED` 且该命令挂在异常单上时 `PROCESSING`→`PENDING_VERIFICATION`（模拟仍可把设备状态标回在线，但不得直接 `RECOVERED`）；`FAILED`/`TIMED_OUT` 回到 `PENDING`。指令成功、设备在线、异常关闭是三件事实。

`POST /devices/{device_id}/commands/lingyun-control` 按协议 B 下发控制（HTTP 202）。必须 `Idempotency-Key`，入参 `authorization_id`（2–64）、`operation_type`（0 停止 / 1 开启 / 2 更新定向）、`operation_cmd`、可选 `operation_params`、`reason`。指令码白名单与设备类型必须同族：诱骗 `dec`（50002/50003/50005/50100/50101）、干扰 `ifr`（60002/60003/60100/60101）、驱鸟炮 `bsc`（70001），以及已开放的 radar/oe/aoa/tdoa。类型不符 400 `VALIDATION_ERROR`；尚未映射的码族 400 `PROTOCOL_UNSUPPORTED`。停止指令不得带参数；定向类开启须有 `target_id`。回执 `code 0/1` 对应 `SUCCEEDED/FAILED`，超时 `TIMED_OUT`。急停 `POST /devices/{id}/commands/emergency-stop` 固定 `409 CONTROL_NOT_ENABLED`（设备协议未提供）。配置 live 不等于现场联调完成。控制不写入融合 inbox。处置执行须绑同族设备：COUNTERMEASURE/JAMMING→干扰，DECOY→诱骗，DISPERSAL→驱鸟炮。

`POST /devices/{device_id}/commands/countermeasure-4ch` 按厂家原生 TCP 下发四通道继电器设置（HTTP 202）。权限 `devices.op`，必须 `Idempotency-Key`，入参 `authorization_id`（2–64）、`reason`（2–500）、`action` ∈ `CHANNEL_ON` / `CHANNEL_OFF` / `SET_MASK`。`SET_MASK` 的 `mask` 只允许 `0` / `13` / `15`（全关 / 驱离 / 迫降全开）；单通道带 `channel` ∈ `900M|1.5G|2.4G|5.8G`。仅已启用且 `ONLINE` 的 `COUNTERMEASURE_TCP_4CH_V2_0` live 设备；否则 409 `DEVICE_NOT_OPERABLE`。非该协议 409 `CONTROL_NOT_ENABLED`。Outbox topic `device.control.countermeasure`。四通道**停止**用本接口 `SET_MASK` + `mask=0`（资料全关），不叫急停。回执以设备为准，不代表射频已发射。

命令状态：`QUEUED → SENT → SUCCEEDED/FAILED/TIMED_OUT`；契约同时保留 `ACCEPTED/CANCELLED` 供 live Adapter 使用。`GET /device-commands/{command_id}` 返回命令、模拟标识、结果以及追加保存的 `receipts`。

停用、离线或状态未知设备拒绝重启。当前 mock Worker 从数据库 Outbox 领取任务，使用条件更新租约、指数退避和最大重试次数；超过截止时间或重试上限进入 `TIMED_OUT`。应用重启后继续扫描未完成记录。

两个本轮 live 协议均未声明重启能力，因此即使设备在线也返回 `DEVICE_NOT_OPERABLE`。雷达启停和寄存器写入仍没有 REST/Outbox。四通道继电器设置见上节 `countermeasure-4ch`；调测/轮询仍只发 `0x10`。真实射频发射未验收。

## 4. 接入调测

状态机：

```text
CREATED -> CONNECTING -> CONNECTED -> READY -> RUNNING
                                      |          |
                                      |          +-> PASSED / FAILED / UNTESTABLE
                                      +-> CANCELLED
```

任一非终态可取消；非法跳步返回 `ILLEGAL_STATE`。重新连接必须创建新任务并填写 `previous_task_id`，旧任务和旧报告不覆盖，且前次任务必须属于同一设备。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /commission-tasks` | `{device_id,previous_task_id?}`；创建 `CREATED` 任务 |
| `POST /commission-tasks/{id}/connect` | `{version}`；HTTP 202，进入 `CONNECTING` |
| `PUT /commission-tasks/{id}/configuration` | `version` 加连接配置 DTO；仅 `CONNECTED` 可保存，进入 `READY` |
| `POST /commission-tasks/{id}/start` | `{version}`；HTTP 202，进入 `RUNNING` |
| `POST /commission-tasks/{id}/cancel` | `{version}`；取消非终态任务 |
| `GET /commission-tasks` | 支持 `device_id/status/page/size` |
| `GET /commission-tasks/{id}` | 返回任务详情、版本和配置快照 |
| `GET /commission-tasks/{id}/events` | `after_seq/limit` 增量返回步骤日志 |
| `GET /commission-tasks/{id}/report` | 仅 `PASSED/FAILED/UNTESTABLE` 可查看，返回判据快照、分项结果和模拟警示 |

任务在创建时冻结 `source_mode`、协议代码/版本、协议专属配置、CIDR 白名单及凭据引用；连接配置在 `PUT /configuration` 时冻结。后续编辑设备或来源不会改变历史任务使用的适配器路由和安全边界。

mock 分项仅验证流程接线，不是正式阈值。雷达 live 调测依次验证 TCP、DATA 登录、心跳、工作模式读取、可选 RTK 和点迹/航迹接收；雷达待机无业务数据时为 `UNTESTABLE`。反制 live 调测只验证 TCP、编码探测、状态查询、地址/校验和和四通道映射；`PASSED` 也不包含射频发射验证。

## 5. 雷达与四通道接入约定

- 雷达帧为大端 `0x55AA55AA + frame_length + command + frame_id + payload + CRC16-MODBUS`；live 拒绝调试 CRC `0xCCCC`。TCP 解码器处理拆包、粘包、错误帧头重同步和 1 MiB 帧长上限。
- 雷达每 10 秒发送心跳，连续三个周期无有效帧判离线；连接按 1、2、4…60 秒退避，由 `device_connection_lease` 保证同一设备同一时刻只被一个应用实例持有。
- `UPLOAD_TRACK_V3` 的无符号 32 位航迹 ID 保存为十进制字符串；原始 x/y/z、速度、SNR、两种 RCS、设备分类和选中标志追加保存。超过 3 秒未刷新只转为失活，不删历史。
- 分类 0–5 只映射为待识别、人、车辆、无人机、鸟、未识别，不推导合法性、风险、融合置信度或告警。点迹无稳定目标 ID，只写原始 Inbox 和最新点迹摘要。
- 航迹批在写入 ops 航迹后，可由 `app.fusion.live-promotion.enabled`（默认关）再写一行阶段 2 `inbox_message`（`source=live-radar:<source_code>`）。打开开关不等于现场雷达联调完成；点迹/RTK 不提升。
- RTK 至少 20 帧后形成未人工验证的站点参考；协议声明高度无效，因此不保存或推导 AGL/AMSL。参考值、北向标志和方位基准未全部验证前，经纬度保持缺失，绝不生成零坐标。
- 四通道完整 32 位继电器状态字保存；只把低四位归一化为 900M、1.5G、2.4G、5.8G。设置帧 `0x11/0x12/0x13` 经 REST 与处置通道发送；调测和监测轮询仍只发 `0x10`。迫降掩码 `0x0F`、驱离 `0x0D`、全关 `0x00`。本机 `local` 模拟器只绑 `127.0.0.1`（设备 `CM4-LOCAL`，`simulated=true`），不登记现场 `192.168.0.7`。配置 live 不等于现场射频联调完成。

## 7. Adapter 联调边界

`DeviceAdapterRegistry` 按来源模式和协议代码选择 `DeviceAdapterPort`。`RadarTcpV300Adapter` 与 `CountermeasureTcp4ChV20Adapter` 已承接本轮资料中的只读连接和调测能力；甲方新增协议通过新 Adapter 接入，不改变前端 REST 契约。

1. 厂商字段与平台 DTO/状态枚举映射；未知码保留原值并输出 UNKNOWN 原因。
2. 使用 `credential_ref` 从批准的凭据设施取密钥，不把密钥写入接口、日志或报告。
3. 把认证后的设备回执写入 Inbox，再关联到命令回执；重复来源消息不重复推进状态。
4. 只依据确认后的判据生成真实调测结论；无判据或必要数据缺失返回 `UNTESTABLE`。

本轮不包含真实反制发射、雷达启停/寄存器写入、真实控制授权、融合感知告警联动、Excel/PDF、证据归档和完整组织数据范围。`UAD-GD01` 为三通道资料，不绑定四通道协议；`UAD-GRF-210R/UAD-GRB-578D` 核准证也不作为协议兼容证明。取得现场设备、网络路由和型号确认前，软件验收仅以协议模拟器为准。
