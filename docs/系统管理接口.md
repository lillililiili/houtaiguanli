# 系统管理接口

系统管理接口统一使用 `/api/v1`、JSON `snake_case` 和 `ApiResponse`。登录后的请求携带 `Authorization: Bearer <session_id>`；写操作携带 8–128 位 `Idempotency-Key`，修改或删除已有对象同时提交当前 `expected_version`。重复键但参数不同、或版本落后均返回 `409`。

系统只有一个内置角色 `ROLE-ADMIN`，显示为“超级管理员”。该角色固定拥有全部菜单和动作权限，不允许修改、删除、停用或转移，也不能分配给新用户。其他角色均由超级管理员创建。

## 认证与权限

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/login` | 登录，返回数据库会话 ID 与过期时间 |
| GET | `/auth/me` | 用户、角色、`menu_keys`、原子权限码、权限版本；仍返回内部 `scope_mode` 供授权，用户管理不维护 |
| POST | `/auth/logout` | 注销当前会话 |
| POST | `/auth/change-password` | 修改密码并撤销该用户全部会话 |

会话令牌只由前端保存在 `sessionStorage`，“记住账号”只保存账号。首次登录待改密用户只能访问当前用户、退出和改密接口。密码重置、停用、角色变化、角色权限变化都会撤销受影响用户的旧会话。

权限等级为 `NONE < READ < OP < AUTH`，**模块码**返回形式为 `{permission_code}.read|op|auth`；**动作码**（形如 `disposal:approve`）返回**原文**，等级 ≥ READ 即下发（决策 16-4）——动作本身就是一个动作，没有三级之分，套后缀反而要前端再拆一次。工作台固定可见；菜单入口只有在 `menu_enabled=true` 且权限至少为 `READ` 时返回。用户管理不再维护或展示数据范围；新建用户内部固定为 `ALL`，调整角色时不改写已有范围。

## 用户、组织与区域

| 资源 | 接口 |
| --- | --- |
| 用户 | `GET /users`（`keyword/status/roleCode/orgId/page/size`；`orgId` 含该组织及其下级）、`POST /users`、`GET/PATCH /users/{id}`、`PUT /users/{id}/status`、`POST /users/{id}/reset-password`、`PUT /users/{id}/access` |
| 组织 | `GET/POST /organizations`、`PATCH /organizations/{id}` |
| 行政区域 | `GET/POST /districts`、`PATCH /districts/{id}`、`PUT /districts/{id}/status` |

新增用户请求一次提交账号、资料、自定义角色和 6–32 位复杂临时密码，不要求填写操作原因；事务成功后立即可用，并强制首次改密，审计原因由后端固定记录为“超级管理员直接创建用户”。`PATCH /users/{id}` 一次提交姓名、电话、组织和可选角色，不要求填写操作原因；角色变化时立即撤销目标用户旧会话，审计原因由后端固定记录为“超级管理员直接调整用户角色”。也可继续使用 `PUT /users/{id}/access` 单独改角色。纯数字或不满足复杂度的临时密码返回 `400 PASSWORD_POLICY_VIOLATION`，不创建用户。临时密码只保存哈希，明文和哈希都不进入响应或审计。用户列表、详情、创建和权限调整接口不接收也不返回 `scope_mode` / `scope_grants`。

用户管理页面为左侧组织树、右侧用户列表；点击组织按该组织及其下级筛选用户。修改用户资料时可同时调整角色，更多菜单不再单独提供权限入口。组织可在树中新增、编辑，不提供停用或删除接口；存量停用组织由迁移统一恢复为启用。新增组织只需名称和上级，`org_code` 由服务端自动生成，创建后不可改。行政区域仍可通过接口维护，用户页不再单独展示。禁止通过任何用户接口修改唯一超级管理员的角色或状态。

## 自定义角色

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/roles` | 列表；或一次提交名称、说明和完整权限矩阵创建角色。原因可省略，服务端写入固定审计说明 |
| GET/PATCH | `/roles/{role_code}` | 详情；或按 `expected_version` 修改自定义角色说明 |
| GET | `/permissions/catalog` | 权限目录 |
| PUT | `/roles/{role_code}/permissions` | 按 `expected_version` 和完整矩阵立即更新权限。原因可省略，服务端写入固定审计说明 |
| DELETE | `/roles/{role_code}?expected_version=...` | 请求体提交原因，立即删除未被用户引用的自定义角色 |

自定义角色可配置业务模块的 `READ/OP/AUTH`。`users`、`roles`、`audit`、`countermeasure` 固定为 `NONE` 且菜单不可开启；菜单开启时同模块权限至少为 `READ`。角色权限改变后，该角色所有用户的权限版本增加且旧会话立即失效。仍被用户引用的角色不能删除。

权限目录与当前菜单对齐：工作台固定可见，不进入矩阵；顶栏「数据大屏」对应 `dashboard`/`bigscreen`。其余按侧栏分组排列——感知监测（融合感知）、飞行监管（飞行计划、合法性研判）、事件处置（告警事件、处置与处罚）、分析报告（运行统计、证据管理）、运维管理（设备管理、设备实时监测、设备接入调测）、系统管理（用户管理、角色管理、审计日志）。`airspace`、`risk`、`countermeasure`、`interfaces` 无菜单入口，不出现在角色权限表。

以下旧审批接口在一个兼容版本内统一返回 HTTP `410`、错误码 `APPROVAL_FLOW_REMOVED`，不会创建或执行申请：

- `/users/creation-requests`
- `/users/{id}/access-change-requests`
- `/roles/{role_code}/access-change-requests`
- `/roles/{role_code}/deletion-requests`
- `/access-change-requests` 及其详情、批准和驳回子路径

## 审计日志

`GET /audit-logs` 支持 `from/to/account/module/action/result/objectType/objectId/page/size`；`GET /audit-logs/{audit_id}` 查询详情；`GET /audit-logs/export.csv` 使用相同条件导出，最多 50,000 条。日志只读，不提供修改、删除、附件或虚构的归档策略接口。CSV 对公式前缀做安全处理，密码与令牌不记录。

角色删除和用户逻辑删除等敏感操作必须填写原因；新增用户、新增自定义角色、保存角色权限以及通过资料编辑调整用户角色不要求手工填写原因，由服务端自动生成审计说明。服务在同一事务内完成变更和成功审计，失败尝试也按服务端安全策略留痕。

## 初始化与恢复

本地 `local` profile 只创建 `admin1 / changeme` 合成账号。共享环境关闭 Seeder，通过 `APP_BOOTSTRAP_ADMIN_ENABLED=true`、`APP_SUPER_ADMIN_ACCOUNT`、`APP_SUPER_ADMIN_NAME` 和 `APP_SUPER_ADMIN_PASSWORD` 一次性初始化。初始化后删除密码并关闭开关，但保留账号变量用于启动完整性校验。

忘记超级管理员密码时，运维人员在服务器环境设置 `APP_SUPER_ADMIN_RECOVERY_ENABLED=true` 和 `APP_SUPER_ADMIN_RECOVERY_PASSWORD`，并以非 Web 模式启动。恢复会重置密码、强制改密、撤销会话、记录脱敏审计并自动退出；没有网页恢复接口。
