# 飞行风险模拟场景

从现有模拟器“场景工具”导入，每次只运行一份。先停止上一场景及全部收发，关闭四通道反制接收选项。本组不需要反制设备，也不自动核验风险或创建通知结果。

| 文件 | 输入与预期 |
| --- | --- |
| `15-risk-bird-normalized.json` | 三路标准化鸟类观测，明确 AMSL 与配套航线；平台按当前空间风险规则决定是否产生风险。鸟类不携带无人机 SN。 |
| `16-risk-bird-protocol-a.json` | 协议 A 雷达鸟类报文；不补已知高度基准，与标准化组分批验证。 |
| `17-risk-weather.json` | 独立模拟气象预警接口输入大风、雷暴、低能见度，配套普通天气预报为“模拟多云”；不把预报文字等同风险结论。 |

模板不填飞手、核验依据、审批人、授权或处理结果。日期由既有模拟器按运行时间准备；重复运行按原消息与内容指纹规则处理。设备复用既有 `item2-radar`，不能让两个发布进程同时使用该编号。默认持续发送，完成观察后显式停止。

执行顺序：核对生效空间规则及上级模拟接收通道 → 导入并启动 → 回读当前目标/计划/风险 → 在“全部风险事件”核验 → 使用原“通知上级”入口 → 独立接收器处理真实出站请求 → 核对送达、签收和处理结果。停报、签收均不自动等于风险解除。
