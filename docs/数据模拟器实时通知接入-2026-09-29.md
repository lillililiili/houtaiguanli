# 数据模拟器实时通知接入

本次将 local+qa 的通知切到独立模拟器接收进程。后端提交仅产生持久化 SUBMITTED 请求，不直接返回 MOCK 送达。模拟器通过已有 8766 代理及其有效登录会话获取请求，先落盘，再提交分阶段回执；不读凭据、不直写平台业务库。

## 运行约定

- 当前业务后端 8081，设备模拟器 8766。8767 为其他隔离环境，不参与本次切换。
- `app.notifications.transport=simulator` 选择异步短信、电话适配器；`app.handoff.channel=simulator` 选择风险、处罚、反馈、运维通道。仅 `(local & qa) | test` 且排除 prod/production 可用。
- 接收器以 `POST /api/v1/local-interface-simulator/bindings` 的 `NOTIFICATION_CHANNEL/receiver` 续租，30 秒租约，正常每 5 秒续租；失联停止接收资格，不退回 MOCK。
- 首次连接只转换 enabled=true 且 endpoint_ref=local-qa-expiring-mock 的原测试配置：改为 API / local-data-simulator，移除原20分钟传输截止时间。保留原接收人、单位、联系人资格、版本和历史快照，转换有审计。真实供应商配置不覆盖。
- 接收端须具接口操作、通知设置授权、全局范围；转换配置另检查单位资料授权。普通接口读者保留原 context 读取能力，不获得通知队列。
- `GET /context` 增加 `receiver_messages`。六类请求分别为 ADVISORY_SMS、ADVISORY_VOICE、RISK_NOTICE、UAV_PUNISHMENT、PLAN_FEEDBACK、DEVICE_MAINTENANCE。当前为本机接收器读取全部待处理请求，避免长期无回执的旧消息截断队列；大规模部署前应扩展分页协议。
- `POST /messages/{simn-id}/receipt` 使用原 expected_version 与明确 outcome。短信需 DELIVERED，电话先 ANSWERED 后 PLAYED，其他通知先 DELIVERED 再 ACKNOWLEDGED。重复回执幂等，错误版本、非法顺序、越权拒绝。
- `result.projection_status` 区分 APPLIED 与 IGNORED_STALE_ATTEMPT：后者只保存外部回执事实，不覆盖新发送尝试和原业务结果。发送登记暂未完成返回409，可重新读取后重试回执。
- 短信送达后观察3秒、电话播放完成后观察10秒；时间取实际回执处理时刻。飞离、风险解除及工单完成仍须各自业务依据。
- `simulated` 和旧 `SIMULATED_*` 状态值为既有来源契约保留，表示独立数据模拟器，不表示接通真实运营商或外拨电话。没有凭空生成真实现场事实。

## 接收器

位于 `E:/rwurenji/_rong/tools/device-simulator/realtime_notification_receiver.py`。独立后台运行，不依赖浏览器标签页；8766 代理服务及其系统登录必须有效。

```powershell
python realtime_notification_receiver.py --proxy http://127.0.0.1:8766
```

默认在 `.data/realtime-notifications/` 保存原请求和回执日志。创建该目录的 `stop` 文件可以停止。单实例锁防止重复接收。可通过 `--outcome-file` 按六类 kind 配置 success、failed、timeout、no_receipt，电话另支持 no_answer、answered_only。电话播完由接收器按配置的播放时长模拟，默认3秒；这与播完后平台观察10秒分开。

设备持续连接由同目录 `device_presence.py` 负责，只按当前已注册设备的心跳/健康配置，经 MQTT QoS 1 发送工参或 HeartBeat，并等待 PUBACK。不恢复旧目标、航迹或风险；场景运行、暂停、停止中及状态未知时让出控制。登录失效或 MQTT 断连时停止，状态保存在 `.data/device-presence/status.json`。

用户可在 PowerShell 运行以下脚本启动两个后台进程（需要8766已登录）：

```powershell
& 'E:\rwurenji\_rong\tools\device-simulator\start-realtime-workers.ps1'
```

启动脚本只负责启动，进程存在不等于连接成功。须核对设备保活状态与平台设备更新时间持续推进、接收租约有效，以及实际业务请求的回执结果。
