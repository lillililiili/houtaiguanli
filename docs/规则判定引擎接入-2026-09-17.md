# 规则判定引擎接入（2026-09-17）

## 已落地范围

管理端 `/system/response-plans` 增加“运行记录”。后台独立调度三类已启用条件，保存规则版本、当前观测、来源及逐项判定。无需用户停留页面。配置审核、原处置预案和人工业务动作保持既有实现。

**当前为仅判定部署。没有安装或接通自动反制、通知、跟踪或核实状态迁移适配器。** 判定 PASS 只代表条件满足，不代表已核实违法、已有反制授权或动作成功。真实自动反制发起方式的确认尚未完成。

## 判定与事实

- 同类已启用条件全部满足才 PASS；无已启用条件为 PAUSED。
- 生效时段按北京时间，支持跨午夜，结束时刻不包含。
- 当前事件关联目标必须明确为 UAV，归属有效且与告警的范围、来源模式一致。原始来源需在同一目标及有效时间窗口内。
- 缺失值为 UNKNOWN，等待配置时长后进入 REVIEW；过期、未来时间、失效对象不能自动通过。最新合法性研判必须关联当前告警，不回退到该目标的旧研判。
- 默认事实最长有效期 30 秒，可由 `app.automation-rules.fact-max-age-ms` 配置。条件不得使已经过期的数据通过。
- 持续满足使用不同有效观测的时间推进，同一观测重复轮询不累计。失败、超时断点或规则版本更新会清除或重新开始对应持续窗口。
- 设备健康读取当前匹配授权所指设备。没有可信回执通道就绪依据时，回执条件为 UNKNOWN。
- 空域关系使用现有 SpatialFactPort/PostGIS；非空间环境或高度依据不足时明确未知。

## 调度与事务

`AutomationRuntimeWorker.poll()` 由 `app.automation-rules.enabled` 控制，默认关闭。周期 `app.automation-rules.poll-ms` 默认 2000 毫秒。每轮最多处理 20 页、每页 100 个候选，持久化 keyset 游标。新鲜事件和待收束的 PASS/WAITING 状态均参与扫描，避免旧 PASS 留存。

`AutomationRuntimeService.evaluate()` 以类别行锁串行配置读取及状态写入；事实读取使用独立只读 REPEATABLE_READ 快照。运行快照包含来源和证据变化，同一判定复用已有记录；规则版本变化会产生新运行记录。大规模候选下仍须结合实际吞吐验收，不将本轮功能测试当作容量承诺。

`V202609170050` 新增运行、持续状态、心跳与预留动作记录表；配置迁移 040 不改写。050 包含系统核实来源字段，但本轮没有调用核实写入服务，未改既有人工核实历史。

## API 与页面

`GET /api/v1/automation-rule-groups/{verify|counter|dispose}/runs?page=1&size=20` 返回 `items/page/size/total`，size 最大 100。每条记录含 `run_id/event_id/target_id/group_version/status/reason/evaluated_at/observed_at/source_mode/conditions/actions`。

判定状态：PASS、NOT_MATCHED、WAITING、REVIEW、PAUSED、OUT_OF_SCOPE、OUT_OF_SCHEDULE。缺失对象的时间及来源可能不返回；不能解释成零值或实时。当前 actions 为空，因为没有自动派发动作。

配置接口的 `execution_status` 由后台开关与心跳返回 CONNECTED、STARTING、DISABLED、UNAVAILABLE；CONNECTED 表示判定调度接通，`execution_message` 明确说明“仅判定、不自动派发”。运行记录沿用全局配置的 ALL 范围与 `responsePlans.read`，不向受限范围账户暴露全局记录。

页面保留“变更记录”，新建/编辑弹窗保持简洁。运行记录弹窗支持分页、重新读取、错误提示和过期响应保护。动作状态展示不会把 QUEUED、SIMULATED 或 UNKNOWN 当成真实成功。
