# 气象风险地图与数据接入方案
版本：2026-10-17，方案草案。适用：当前“飞行任务 → 全部风险事件”页面。本文与图片均为设计建议，未修改业务代码、规则、接口配置或运行数据。图片中的天气、航线、站点读数和边界均为示意，不是现场气象。

## 1. 页面定位与方案选择

页面承接上级气象产品、气象设备观测、现有风险与飞行任务，用于看清“哪里、何时、什么天气、依据是否足够、与哪些任务相关”，继续通过现有人工核验和通知回执流程处理。

**推荐：分层显示、按数据精度逐步落地。**

| 方案 | 能看到什么 | 代价及限制 | 建议 |
|---|---|---|---|
| A：只补区域预警 | 行政区域提示、预报文字、关联航线 | 需要权威行政边界；不能精确判断某段航线受影响 | 当前数据即可先补 |
| B：区域/精确预警 + 站点实测 + 任务关联 | 风险范围、实测值、时间、相交航段及依据不足提示 | 需结构化预警接口、站点资料与观测协议 | 推荐主方案 |
| C：完整风场/雷达/能见度网格，进一步三维展示 | 连续分布、不同高度和预报时次 | 依赖专业产品、授权、分辨率、质量和服务器资源 | 数据确实具备后扩展 |

建议先做 A，再在同一页面补齐 B；C 不作为本轮必须建设项。天气展示不新增自动取消任务、自动改航线或自动反制。

### 已确认的当前系统事实

- 当前页面已有左侧风险列表、中间地图、右侧风险详情与“通知与回执”；继续使用这些入口。
- 当前气象事实有两种覆盖依据：`REGION`（区域级预报）和 `POLYGON`（有闭合范围）。
- 截图这类区域预报只有区域和时段，当前地图提示“未提供精确气象边界”，所以只有关联航线。
- 前台已有多边形绘制、范围开关、透明度、图例和与航线交叠的显示能力；现有气象事实尚未提供高度范围。
- 区域预报已有温度、风速、阵风、风向、降水概率、湿度等时段数据；模拟气象设备观测还支持气压、累计降水、能见度。
- 真实气象设备协议和上级正式气象源仍需按供应方资料确认，不能把模拟接口视为已接通的正式接口。
- 当前部分天气风险由摘要关键词和既有规则生成。新正式接口建议提供结构化类型，不以模糊文字作为精确地图或新风险判据。
- 现有模拟纹理只用于明确的模拟源，不能用于绘制真实风场或雷达回波。

### 参考系统及采用的做法

- **美国航空气象中心 GFA**：预警、站点、雷达等图层按需叠加，观测与预报分开，使用时间选择和高度选择。采用其“图层 + 时间 + 高度 + 航线”的交互思路，保持当前系统的米制、北京时间和权限体系。[官方使用说明](https://aviationweather.gov/gfa/help/)
- **Windy**：气象雷达色带来自真实气象数据，可与卫星资料对照。采用“按气象要素选择图层、配套数值色标”的表现方式，不能把静态纹理当观测分布。[官方雷达说明](https://www.windy.com/articles/41513)
- **和风天气预警文档**：区分发布时间、生效时间、预计事件开始时间和失效时间；发布机关所在地不等于影响区域。采用这些时间与覆盖语义，不假设其一定能提供本项目需要的多边形或低空网格。[官方说明](https://dev.qweather.com/docs/api/warning/alert-guide/)
- **CAP 1.2**：参考其消息标识、更新/撤销关系、有效时间、地理覆盖等概念；内部数据不要求原样使用 CAP XML，也不宣称本方案已符合全部标准。[OASIS 正式规范](https://docs.oasis-open.org/emergency/cap/v1.2/CAP-v1.2-os.html)

## 2. 上下游与生命周期

上级预警/预报或设备观测 → 接入适配与质量检查 → 保存原始产品及版本 → 地图按空间和时间显示 → 风险评估关联任务 → 现有人工核验 → 现有通知与回执 → 历史留存。

| 方向 | 具体来源/目标模块 | 传递内容 | 使用方式 |
|---|---|---|---|
| 上游 | 上级气象接口接收适配 | 产品 ID、类型、区域/范围、时间、版本、撤销 | 地图显示原始预警事实 |
| 上游 | 气象设备接入与观测 | 站点身份、位置、高度、实测值、质量、观测时间 | 站点图标、弹窗和可追溯规则输入 |
| 上游 | 飞行任务的航线与任务时段 | 计划 ID、航线版本、空间几何、时间、高度基准 | 判断关联及空间/时段交叠 |
| 下游 | 风险详情与人工核验 | 风险 ID、证据版本、当前有效状态 | 延续已有核验流程，不由看图自动核验 |
| 下游 | 通知与回执 | 核验结论、已有通知对象、依据快照 | 按当前规则通知并回读回执 |
| 下游 | 飞行任务详情 | 同一任务关联的风险和气象依据 | 从风险页跳转到对应任务并返回 |
| 下游 | 历史风险详情 | 当时产品、范围、任务版本及核验记录 | 复现出风险时依据，不用新天气覆盖旧证据 |

成功终点：地图能如实说明气象事实和数据能力，列表、详情、关联任务一致，核验与通知仍可追溯。

## 4. 逐模块逻辑卡

### WX.M01 现有风险统计
目的：知道当前风险量与待办量。出现：有风险读取权限时。输入：现有汇总接口与查询条件。处理：保留现有统计口径；一个气象产品关联多个风险时，产品地图去重不改变风险事件计数。字段：原统计数量及范围说明。动作：原有筛选入口。输出：筛选传给 M02，不写业务数据。页内关系：列表、数量采用一致条件；跨页关系：无新增。异常：无权限不显示受限统计，失败显示不可用，不填零。AI：无。验收：统计仍与现有风险口径相符，显示产品数量时另起明确字段。

### WX.M02 风险列表与筛选
目的：定位待处理风险。出现：原风险工作区。输入：风险 ID、天气类型、平台风险等级、核验状态、来源及当前时效。处理：列表沿用当前排序/分页；多项天气用分项标签说明。字段：主要天气、等级、有效时段、区域、核验状态。动作：选择风险、筛选。输出：risk_id 送 M03/M04/M06；只查询，不核验。跨页：保持现有任务深链。异常：快速切换时旧请求不能覆盖新选择；分页失败保持明确提示。AI：无。验收：地图/右侧详情始终对应所选 ID，不出现上一条范围残留。

### WX.M03 图层、时间、高度控件
目的：让用户明确正在看哪种天气、哪个时点和高度。输入：可用产品目录、当前选择、支持的时次和高度层。处理：默认显示选中风险的范围与关联航线，其他图层按需开启；同一时点选择最近且有效、不过期的对应产品，不能拼接不同模式批次。字段：产品名、实况/预报、北京时间、AGL/AMSL、发布时间。动作：切换图层、时次、已有高度层、透明度。输出：只读地图请求和显示上下文，不改变当前风险状态。跨页：无新增业务命令。异常：无对应高度层显示“无该高度数据”；无网格时风场按钮不启用并说明。AI：无。验收：100 m AGL 不显示成 100 m AMSL；历史时间轴不改变实时待办。

### WX.M04 地图与航线叠加
目的：看清范围、站点与任务关系。输入：M03 上下文、经过校验的区域几何/产品几何、站点、航线版本及后端关联结果。处理：按第 13 节空间规则绘制，地图按来源产品 ID + 版本去重；点击风险自动适配范围和航线，在区域过大时提供“定位航线/区域全貌”。字段：几何、图层类别、数据来源、当前/历史、空间交叠状态。动作：选范围/站点、定位和缩放。输出：对象 ID 送 M05；看图不新增风险或核验。跨页：任务入口传 plan_id 与风险上下文。异常：边界缺失只显示区域文字提示，不造多边形；图层加载失败保留底图并说明。AI：无。验收：一个产品关联三条任务只绘制一份范围；站点图标没有虚构气象覆盖圆。

### WX.M05 信息卡与图例
目的：解释图形意味着什么。输入：选中产品或站点的原始事实、质量信息及关联结果。处理：预警卡与站点卡分别展示；官方预警等级、平台风险等级分开；量测值保留单位、统计时段和高度。动作：查看来源依据、关联任务、关闭卡片。输出：导航上下文/决策信息，不写观测值。跨页：原有飞行任务详情和风险详情。异常：未知数值显示“未提供”，不是 0；过期值保留时间并变灰。AI：无。验收：数值与原始观测一致，卡片更新不覆盖用户当前选中对象。

### WX.M06 详情、核验、通知回执
目的：继续原有处置链。输入：同一 risk_id、气象产品版本、关联任务和当前权限。处理：沿用核验、通知规则；气象范围显示不代表已核实属实，也不构成直接飞行禁令。字段：来源、官方预警、平台等级、影响依据、核验历史、通知回执。动作：现有“人工核验”“查看关联飞行任务”“通知与回执”。输出：原有核验/通知命令、审计与冻结依据。跨页：任务详情回读同一风险。异常：版本冲突先刷新；无权限/不满足条件显示具体原因；重复通知沿用现有防重。AI：无。验收：地图不绕过人工核验与原有通知资格，通知成功以实际回执为准。

### WX.M07 同步、空态、异常与历史
目的：辨别“有风险、缺数据、数据已过期、产品已撤销”。输入：接口可用性、产品生命周期、观测时效和旧证据。处理：气象产品状态、数据质量、平台风险状态分别维护；保留旧事实。动作：重试、查看历史范围/当前天气。输出：可用性提示及读请求；网络故障不自动解除风险。跨页：历史资料沿用冻结版本，实时页面读取当前有效产品。异常覆盖第 12 节。AI：无。验收：停止上报、接口报错、分页不完整时不会显示“天气正常”或“预警解除”。

| 当前模块输出 | 目标具体模块 | 消费方式 | 回流 |

## 9. 状态机与传播

**气象产品**：待生效 → 生效中 → 已到有效期；另可被更新替代或被来源撤销。时间到期只是该产品不再支持“当前”，不等于气象现象实际消失。
**观测数据**：有效 / 可疑 / 无效 / 过期 / 缺失。设备在线状态独立；心跳不能延长旧观测有效期。
**平台风险**：核验、通知、办理继续使用现有状态，不与上面两条合并。

| 事件 | 当前地图 | 风险与历史 |
|---|---|---|
| 收到新版本 | 完整新版本校验成功后一次替换 | 原风险依据冻结；新事实按已有/批准后的规则重评 |
| 收到撤销 | 当前图层注明撤销或移入历史 | 保留撤销消息，不自动伪造已核验/已通知 |
| 超过有效期 | 历史选择中变灰并显示原时段 | 不显示“天气已恢复正常” |
| 接口中断 | 明确更新时间和读取失败 | 不以消失或空数组推断解除 |
| 观测过期 | 站点灰色，旧数值带原观测时间 | 不把旧值当当前风速 |
| 用户核验成功 | 同一 risk_id 标签同步 | 沿用原审计、版本与后续通知规则 |

## 10. AI 边界

本方案的风险计算与地图绘制不依赖生成式 AI。禁止用 AI 猜测天气边界、补造缺失高度、推断实测值或把新闻/预警文字自动画成精确影响区。若未来需要解释文本，仅可生成清楚标识的辅助说明，不能覆盖原始预警或直接触发业务处置。

本次效果图由 imagegen 生成，仅用于讨论交互和视觉，图内地理边界和样例数值不进入业务库。

## 13. 数据与接口契约（建议，供对接方确认）

内部沿用 `/api/v1`、snake_case、字符串 ID、标准响应、权限与来源隔离；时间用 UTC epoch 毫秒保存，页面显示北京时间。下面是归一字段建议，**不是已实现的新接口**。对接方可以发送自有格式，由适配器映射；本轮不虚构真实厂商协议或地址。

### 13.1 上级接口：至少提供三类产品中的实际可供项

| 类别 | 必要数据 | 地图可实现的效果 |
|---|---|---|
| 区域预警/区域预报（最低） | 消息 ID、来源、类型、发布时间、有效时段、稳定行政区代码及代码体系、区域描述、更新/撤销关系 | 行政区域提示、预报图标、文字与时段；只能区域级关联 |
| 精确预警/短临影响范围（推荐） | 上述字段 + Polygon/MultiPolygon 或有依据的圆形范围、坐标系；可提供影响高度及基准 | 实际范围边界、空间相交航段、分时次范围变化 |
| 风/雷达/降水/能见度网格（扩展） | 产品与模式批次、网格或瓦片、坐标/范围/分辨率、变量/单位、时次、层高与基准、NoData/质量、图例 | 风场/回波/数值色带、时间播放和已有高度切换 |

仅提供一串“东营区今天雷雨、大风”的文字，足够做区域提示，不足以做精确范围、移动云团或低空风场。

### 13.2 通用产品字段

| 字段组 | 建议字段 | 要求与用途 |
|---|---|---|
| 身份与版本 | source_id、product_id、message_id、revision、replaces_message_id | 来源内唯一、可幂等、可追更新；同一 ID 不允许悄悄换内容 |
| 产品类别 | product_kind：ALERT/FORECAST/OBSERVATION/GRID；phenomena[] | 区分预警、预报、实测、网格；雷电/雷暴、大风、低能见度等结构化码按源字典映射 |
| 原始预警 | issuer、headline、description、instructions、official_level/code/color | 保留发布机构、原等级、原文；无官方等级则不伪造 |
| 时间 | issued_at、effective_at、onset_at（可选）、expires_at/valid_to | 区分消息发布时间与事件时段；来源未给终止时间时标未提供，不自行伪造时长 |
| 产品状态 | message_type：NEW/UPDATE/CANCEL；关联被更新/撤销消息 | 这是接入协议建议枚举，与正式来源实际码映射 |
| 空间 | coverage_basis、area_codes[]、area_code_system、area_description、geometry | REGION/POLYGON/GRID/POINT 分开；发布单位行政区不能冒充影响区 |
| 几何 | GeoJSON Polygon/MultiPolygon；可选圆心+有依据半径 | 建议内部 WGS84；GeoJSON 顺序为 [经度,纬度]；闭环、洞和多面均校验 |
| 垂直 | lower_m、upper_m、vertical_datum：AGL/AMSL/UNKNOWN | 有则传，没有为空；不能把地面预警自动视为全部低空高度 |
| 质量 | quality_flag、resolution_m、accuracy_m/uncertainty（可提供则传）、confidence/source_probability | 只接受来源给出的质量或有记录的计算结果 |
| 来源用途 | live/mock/replay、simulated、license/use_constraints | 真实/模拟标识由可信接入绑定；地图展示和缓存遵守授权 |

CAP 可作为字段映射参考，但 CAP 的 polygon 使用纬度、经度对，不能直接当成 GeoJSON 的经度、纬度对；CAP 高度按规范使用英尺海拔基准，归一到米之前须保留原单位与基准。[CAP 1.2](https://docs.oasis-open.org/emergency/cap/v1.2/CAP-v1.2-os.html)

### 13.3 气象设备：台账资料和观测报文分开

**设备台账**：device_id、external_device_id、站点名称、经纬度/坐标系、站点海拔、安装位置、每个传感器测量高度 AGL、支持要素、采样/上报周期、精度、校准信息、归属和协议版本。设备负责给事实，不要求设备填写“全区高风险”。

**每次观测**：

| 要素 | 建议字段/单位 | 必须明确的口径 |
|---|---|---|
| 报文身份与时间 | message_id、device_id、observed_at、sequence | 平台另记 received_at；晚到报文不覆盖较新观测 |
| 平均风 | wind_speed_mps、wind_from_degrees、averaging_period_s | 米/秒；风从真北顺时针哪个方向吹来；平均窗口由设备声明 |
| 阵风 | gust_mps、gust_window_s、gust_sample_period_s（若可提供） | 哪个时间窗口内的最大值，不能与平均风混用 |
| 能见度 | visibility_m | 专用传感器有此能力才上报；无值为空 |
| 降水 | precipitation_rate_mm_h 或 precipitation_accumulation_mm + period_start/end | 降水强度与累计降水分开；降水概率也不是毫米值 |
| 温湿度 | temperature_c、relative_humidity_pct | 对应传感器高度和质量 |
| 气压 | pressure_hpa、pressure_reference | 站点气压/海平面订正等口径明确 |
| 可选专业要素 | 雷电位置/时间、云底高度、分层风、湍流/风切变产品 | 仅对应设备或产品确实支持时接入 |
| 每要素质量 | VALID/SUSPECT/INVALID/MISSING、质量原因 | 质量可逐要素不同，未知不能填 0 |
| 健康 | online、sensor_fault、calibration_status | 设备状态与气象观测状态分开 |

风向是“风从哪里吹来”，需要明确相对真北的角度与测量高度；绘制流向箭头时转换为吹向，不直接复用原角度。[WMO 风向变量定义](https://space.oscar.wmo.int/variables/view/wind_direction_near_surface)

**频率建议（不是已确认设备能力或强制标准）**：普通自动站可先按 30–60 秒一条观测讨论；阵风由设备在明确窗口内计算。区域预警按更新推送或源方允许周期查询；雷达/网格严格使用产品实际时间分辨率。超时门槛依据源方承诺与业务需求确认，心跳不补新数据。

### 13.4 风场与栅格的额外要求

- 必须有空间网格数值或可定位的产品：extent/CRS、行列、分辨率、时间、变量、单位、缺测值、质量。
- 风场需要每个格点的 u/v（东向/北向，m/s）或风速/风向，且明确高度；站点 10 m 风不能直接代表航线 100 m AGL 风。
- 雷达优先接入带时间与地理参考的瓦片/栅格及变量说明，例如反射率 dBZ；不能把 dBZ 色标写成降水 mm/h。
- 图片/瓦片只用于展示时，不能凭颜色反推精确数值参与风险规则；量化评估需要源方数值数据或正式查询接口。
- 一个网格产品使用统一色标，NoData 透明或明确缺测；放大不提升原始分辨率。
- 多站插值必须有验证过的模型、适用范围、地形和误差说明；第一期不自行插值成“实测风场”。
- 瓦片/图片格式可按源方供给采用 XYZ/WMTS/WMS/带地理参考栅格；协议、授权、坐标转换后再决定实现。

### 13.6 地图规则与风险关联

| 数据形态 | 地图画法 | 可表达的任务关系 |
|---|---|---|
| 区域预报 | 权威行政边界 + 浅色斜线 + 区域天气图标；明确“预报适用区域，非实测天气边界” | 区域与任务时段关联；不标精确受影响航段 |
| 精确预警多边形 | 官方范围轮廓 + 低透明度填充；图标表示天气类型 | 高亮水平空间相交航段；结合时段、高度后才给更强结论 |
| 气象站 | 点位 + 风羽/箭头或要素小标签；过期变灰 | 点位事实；有已验证适用范围才能外推到航线 |
| 风场网格 | 数值色带 + 可关闭的风向流线 + 单位图例 | 根据格点、时次、高度与规则计算；保留分辨率与误差 |
| 雷达/降水 | 实际栅格/瓦片 + 独立色标与产品时间 | 区分观测回波与短临外推，不把回波直接当雷电 |
| 低能见度 | 有网格画等值/色带，仅站点则画点 | 无网格不由几个点扩成雾区 |

- 官方预警颜色与平台风险等级分开。预警未知等级用中性样式，不自动套橙色。
- 路线基础色用青色，空间交叠段可用紫色；红色不能同时承担“地图交叠”和“已确认不能飞”。
- 两个时间区间采用一致边界定义，建议 `start < other_end && end > other_start`；仅边界相接不算时段交叠。
- 精确评估至少需要空间、有效时段和明确的高度适用范围/规则。未知高度时可保留“空间相交、垂直影响待确认”，不能据此把目标判为安全。
- 任务仅有整体起止时间、没有可靠分段到达时间时，结果为“任务时段内可能相交”；不伪造“17:42 将进入雷暴”。
- 阈值来源于已确认规则、机型限制与业务要求。本地现有代码中的阈值不能直接当所有机型通用飞行安全标准；本方案不自动修改现有阈值。
- 风险建立和处置以后台为准，前端绘图不另算一套正式风险。

### 13.7 服务职责与存储建议

以下是建议职责，路径在接口评审后确定：
1. 上级产品接收/拉取：验证身份和范围、保存原报文、幂等入库、处理更新/撤销。
2. 站点台账与观测：沿用设备身份；按观测时间与质量读最新值。
3. 地图产品查询：按权限、bbox、产品、时次、高度返回图层及可用性。
4. 风险关联查询：按 risk_id 返回冻结产品引用、任务航线版本、关联依据与缺口。
5. 历史产品查询：按 product_id/version 读取，保持当次风险证据可复现。

建议分开保存 WeatherProduct、WeatherProductVersion、StationObservation、RiskWeatherEvidenceRef；现有风险/任务实体继续复用。接入日志与重试记录必须可追踪，但不堆在日常页面。

## 14. 端到端验收

1. **区域级预报**：上级仅给区域码/名称和时段 → 定位行政区域，标“区域级”；关联任务可见，不产生精确风险航段。
2. **精确多边形**：换一份不同 ID、不同区域和不同时段的产品 → 地图显示实际范围；只有符合关联条件的任务进入相交结果。
3. **只有站点**：收到有效风速及测量高度 → 点位显示同值同时间；地图不出现虚构风场或覆盖圈。
4. **低空层差异**：只有 10 m AGL 数据、选择 100 m AGL → 显示该高度无数据，不能沿用 10 m 数值。
5. **历史/当前**：风险冻结 v1、当前已有 v2 → 查看历史仍看到 v1；切当前看到 v2，旧依据不改。
6. **更新/撤销/乱序**：晚到旧消息不覆盖 v2；明确撤销生效；网络错误和未读完分页不会撤销。
7. **质量缺口**：单个能见度值缺失，不填 0，也不影响可用温度展示；过期观测不被心跳续期。
8. **多源/多任务**：同产品关联多个任务只画一层，风险列表仍按原计数；冲突来源明确标注。
9. **核验与通知**：点图形不写业务状态；有权限核验后各处状态一致；通知沿用原资格并以实际回执为准。
10. **真实/模拟/权限**：正式环境不混入模拟源；无权限不能通过地图/瓦片/详情绕过范围；只看得到本人范围内关联任务。
11. **地图交互**：真实浏览器验证列表选中、范围定位、图层/时次切换、站点弹窗、任务跳转和返回；快速切换时旧响应不覆盖新对象。
12. **缺边界**：缺权威行政边界或无法映射区域码时，有清楚的区域卡与缺失提示，不生成猜测几何。

这些是对接资料清单，不是要求用户现在逐一回答。方案中的未确认能力不得写成已经具备。

## 16. 交付边界与分步落地

**第一阶段：让现有风险看得见。** 补权威行政区域提示、区域标签、时间/来源卡、关联航线；精确范围复用已有能力。无需伪造热力图，也不改模拟想定、历史数据或原核验通知流程。

**第二阶段：正式接入与实测。** 确定上级结构化预警/预报和设备协议，补单位、高度、质量、更新撤销和站点观测图层，形成接入→地图→风险→任务→核验/通知的闭环。

**第三阶段：有数据再做网格和分层。** 加真实风场、雷达、能见度等切片与时间轴；是否三维展示根据产品能力决定。

可直接讨论/评审：页面布局、分层原则、字段职责、缺失态和验收项。正式开发仍需确定接口能力与边界数据，不能以效果图代替数据源验收。
