# 设备上报坐标声明校验（2026-10-20）

业务经纬度采用 WGS-84。坐标声明只证明报文满足接口契约，不证明设备厂商提供的数值具有经测绘确认的 WGS-84 来源；系统不根据数值范围猜测坐标基准，也不把 GCJ-02、BD-09、CGCS2000 重新标成 WGS-84。

## 接入规则

- JSON 坐标使用 `coordinate_system: "WGS84"`，设备协议同时接受 `coordinateSystem` 和 `WGS-84` 别名（大小写不敏感）。
- 声明可位于报文根、目标对象或相应位置对象上；上级声明可继承。任一适用层级出现空白、非字符串、其他坐标系或冲突别名，整份位置观测拒收。缺少声明也拒收。
- 凌云工参验证设备经纬度；感知上报同时验证目标和 `extension.pilotLon/pilotLat`。AOA、光电协议 A 的无效目标位置仍按原规则保持未知。
- 光电协议 C 仅将有效跟踪报文的 `aiStatus` 当作目标观测。无效坐标不得进入融合、刷新跟踪观测或设备感知状态；同一报文内真实的命令成功回执仍可结算。失败回执、结束跟踪及停机回执不依赖位置声明。
- `sim-normalized` 的目标、飞手位置和气象站观测必须声明 WGS-84。声明在 API 验证后保留到 Inbox，融合映射时再次校验。
- 二进制 TCP 雷达没有可新增的 JSON 坐标系字段。根据 `docs/backend-stage1/t02-replay-contract.md` 第 8.1 节，只有经批准的 RTK 原点、航向与转换依据才能派生 WGS-84；内部派生 JSON 明确携带声明，没有依据不生成位置。
