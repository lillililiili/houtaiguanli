# 三条业务链模拟资料包

本包用于已有无人机处置、设备运维、鸟情/气象风险上报，以及协议 C 光电和测试视频。所有联系人、号码、上级资料和响应都明确为模拟。上级正式接口尚未提供，本包采用系统**现有本地授权输入契约**，不构造另一套生产同步接口。

## 文件与状态

| 文件 | 用途 | 就绪条件 |
| --- | --- | --- |
| `scene-templates/`：17 个 JSON | 现有模拟器“场景工具”导入 | 模板已备，飞手关联未填；单独导入可能因资料不足正常阻断 |
| `notification-configs/`：8 个 JSON | 现有实时收发配置，含成功、失败、无回执、电话仅接通等 | 登录原模拟器，停止全部收发后切换 |
| `audio/pilot-warning-simulation.wav` | 16.029 秒中文模拟电话语音，PCM 单声道 22050 Hz | 已生成；元数据、SHA-256、文稿见 `audio/recording.json` |
| `material-definition.json` | 联系人、账号权限、来源、语音、场景及当前边界的可读清单 | 无密码、会话或预设业务结论 |
| `prepared-materials.json` | **执行录入成功后才生成**的真实 ID、版本与回读关联 | 原件位于被 Git 忽略的 `server/target/simulation-materials/` |
| `ready-scenes/`：17 个 JSON | **执行录入成功后才生成**，已注入回读得到的飞手与报送关联 | 打包在录入后的压缩包中，不覆盖历史计划 |

压缩包路径：`server/target/simulation-materials/完整模拟资料包.zip`。成功录入后自动更新。`journal.json`、本机服务日志、临时凭据均不进入压缩包；密码仅在本机内存中使用。

## 录入一次，按场景分别运行

1. 后端应运行 `local,qa`，`app.dev-seed.enabled=false`。通过现有 `app.qa.notification-setup.enabled=true` 显式开放本机资料准备接口，配置 `audio/recording.json` 对应的已有电话录音属性。无新依赖、迁移或业务菜单。
2. 在仓库根目录运行 `python scripts/prepare_simulation_materials.py --serve`，打开 `http://127.0.0.1:8767/`。页面列出将创建/启用的资料和权限。使用现有管理员登录，为两名测试账号自行设置临时密码后执行；勿把密码写入脚本或发到聊天。
3. 工具通过已有接口复用验收模拟单位/区域，创建 4 个模拟联系人、1 个报送单位关联、当日配套航线和计划，配置 5 类本机通知通道，启用唯一有效的既有模拟空间风险版本，创建普通申请执行和异人审批账号。DEMO 属性保留，业务核验与审批仍在原入口执行。
4. 工具回读联系人、计划 SN/时段、航线版本/坐标/AMSL、主体关联、通知配置、规则版本及账号权限。遇到同名冲突、权限不足或结果未知则停止，不覆盖已有数据。网络超时后先回读；未确认的写入不会盲目重发。原请求及幂等键保存在 `journal.json`。
5. 两个账号分别在业务前台首次登录并改密。**申请人账号** `sim_acc23_operator` 发起申请 → **审批人账号** `sim_acc23_approver` 审批 → 回到**原申请人账号**执行反制。账号显示名“申请执行员”指的就是申请人，不是第三个人；审批不替代执行，执行仍校验原有权限、当前证据与授权时限。**现有系统新建账号默认 ALL 数据范围**，不是按模拟来源隔离。两者均不授予直接反制和用户/角色管理权限。设备运维仍使用现有授权管理员。
6. 在 `http://127.0.0.1:8766/` 使用原账号登录，导入 `ready-scenes/` 中一份场景。选择已有验收单位/区域和 replay MQTT 连接，先连接再启动。不要同时运行共享设备编号的两个场景。
7. 现有实时收发入口配置独立通知接收器；若使用 API，可向本机模拟器 `POST /api/realtime/config` 发送对应配置 JSON，再通过原页面启停。配置文件不是地图场景，不能从“场景工具”导入。默认关闭四通道收发；协议 B 由地图场景内已绑定设备响应。
8. 每次启动会由原模拟器准备场景专用计划/空域/设备绑定，生成运行批次；当日配套资料计划只用于检查目录及通知资格。观察实际平台结果，在原页面执行核实、申请、异人审批、执行或上报。停止时先停止全部收发，再停止场景。

本工具的通知接收注册只用于配置转换，不持续处理通知。**实际演示前必须在原模拟器启动独立接收器**；离线时平台应阻断。工具不消费通知、不主动提交回执、不改变业务结果。

申请人除 `disposal:execute` 外，还需现有 `devices.op`，审批人仅保留设备查看。2026-10-06 用户确认后，已通过角色管理给本轮申请角色补齐该权限；它允许操作当前可见设备，实际演练限定本机 replay。工具只回读并核对已有角色，不自动扩大不匹配角色权限。修改角色会撤销相关旧会话，需重新登录。

## 固定场景顺序

重复演练业务闭环前，使用准备完成的场景生成独立快照（`--batch` 每次新运行取新值）：

```powershell
python docs/acceptance/simulation-materials/build_rehearsal_scene.py --scene server/target/simulation-materials/ready-scenes/02-normalized-disposal.json --batch uav-20261006-01 --output server/target/simulation-materials/rehearsals/uav-20261006-01.json
```

导入生成文件后再启动。该工具只为标准化无人机观测分配模拟 SN，计划仍由原模拟器按同一目标 SN 准备；设备编号、计划关联和协议 A 字段保持原样。重复请求复用已保存快照，不能在未知提交结果时重新生成批次。旧计划不删除，运行中的同一批次不更换 SN。

| 场景文件 | 输入及演示检查 |
| --- | --- |
| `01-normalized-legal.json` | 合法目标，明确模拟 SN/位置/AMSL，正常计划匹配 |
| `02-normalized-disposal.json` | 禁飞违规主链，实际研判充分后核实、通知、普通申请/异人审批、协议 B、干扰续链及移送 |
| `03-after-sms.json` | 实际短信送达后移动；3 秒观察与有效位置支持飞离 |
| `04-after-voice.json` | 短信后仍在、电话播放完成后移动；10 秒观察 |
| `05-stop-reports.json` | 通知后停报，不能冒充飞离 |
| `06-mqtt-height-unknown.json` | 协议 A 未知高度基准，不能用标准化场景替代其证据 |
| `07-mqtt-no-sn.json` | 协议 A 缺 SN，保持未知 |
| `08-device-fault.json` | 独立设备异常、内部待办、处理及恢复核验阻断 |
| `09-device-offline.json` | 心跳停止离线，恢复心跳与健康恢复分别回读 |
| `10-eo-video.json` | 人工光电任务、协议 C 报告、鉴权 HLS 动态画面、结束及资源清理 |
| `b-failure.json` | 协议 B 失败回执，原授权不能成功 |
| `b-no_receipt.json` | 协议 B 不响应，原超时机制推进 |
| `b-late.json` | 协议 B 迟到回执，保留证据而不改原终态 |
| `b-duplicate.json` | 重复回执，不能重复续链或移送 |
| `15-risk-bird-normalized.json` | 明确模拟高度的鸟类与航线空间风险，核验后通知上级 |
| `16-risk-bird-protocol-a.json` | 雷达协议 A 鸟类输入，未知字段保持原语义 |
| `17-risk-weather.json` | 独立大风、雷暴、低能见度预警；普通天气预报不等同已确认风险 |

`08/09` 的起飞前检查计划仍按原资格入口工作；启动前把模板中的未来检查时段调整为当前北京时间之后。其他模板使用既有 current 时间模式。不能通过修改业务时长或资格条件适应模板。

`03/04` 使用独立的通知撤离禁飞区，初始目标在边界内，后续连续移动到原告警所覆盖的所有空域之外。平台观察的是通知时覆盖目标的空域集合；只离开内层禁飞区、仍在重叠空域内，应保持“仍在”。场景已同步移动飞手位置，避免意外触发超视距。若验收环境另外导入了覆盖撤离终点的空域，应先核对并调整模拟路线，不能修改判断规则。`05` 停报必须同时停止标准化输入和 MQTT 目标观测，设备工参可继续；停报不证明飞离。

空域来源沿用既有“本地外部接口模拟器”。场景内空域通过授权的 `/local-interface-simulator/airspaces` 输入；空域同步生命周期的可运行准备器及说明见 `upstream/`，覆盖新增、修订、撤销和旧版本拒绝。生产上级接口待提供后再做字段和身份映射，不把本机报文宣称为正式协议。

## 三条链的验收证据

分别保存运行批次与下列关联，不混写完成状态：

- 无人机链：计划、SN、目标、研判、告警、短信实际送达、电话接通/播放完成、位置依据、申请人/审批人、协议 B 指令与回执、干扰续链、处罚移送送达/签收。
- 运维链：设备与来源、异常发生、内部待办、处理进展、新心跳/健康、异常恢复、恢复核验及完成时再次检查。已读不等于完成。
- 风险链：计划及航线版本、鸟类或独立气象预警、风险记录、核验、真实出站上报、模拟上级送达/签收、原处理结果。签收不等于风险排除。
- 光电视频：当前任务、Begin 受理、有效跟踪报告、实际 HLS 清单/分片及连续动态画面、End 确认。视频不替代身份或业务依据。

## 当前边界

资料文件就绪、资料已录入、业务闭环已通过是三个不同状态，测试记录只写实际完成的部分。

- 模拟联系方式的核验依据明确写为“模拟上级资料中的核验结果”，不代表真实实名或可拨通号码。
- 空间和合法性规则保留原 DEMO 属性；自动核实/通知规则和处置策略仍需要逐项读回核对，不能把空间规则启用当作全部自动链具备条件。
- 协议 A 恢复工参只证明在线，不能提供足够的可信健康 GOOD。独立受控模拟状态输入已实现，使用方法和环境门禁见 [device-status.md](device-status.md)；完成工单仍须实际恢复验证。包内没有预置 PASS 或已完成工单。
- 两个新账号首次改密、逐次异人审批、设备/策略资格、录音配置生效、原模拟器接收器上线，仍是运行时步骤。资料工具不自动批准申请、生成成功回执、驱动真实设备或发送真实短信/电话。

运行数据原件只保存在忽略目录。测试及实际录入状态见 `verification.md`，不能用文件数量代替业务验收通过。
