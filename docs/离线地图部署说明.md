# 离线地图管理与部署

## 1. 运行方式

地图管理采用“版本目录 + 原子运行指针”，不把 PMTiles 大文件写入数据库：

- 管理端上传 ZIP，后端在临时目录安全解压并校验全部 SHA-256、清单、MapLibre 样式和 PMTiles v3 文件头。
- 校验通过后保存为不可变目录 `map-data/packages/{package_id}/`，上传本身不影响前台。
- 超级管理员执行启用时，后端原子替换 `map-data/control/map-config.json`；上一版继续保留，可一键回滚。
- 业务前台每 30 秒及窗口重新聚焦时检查运行指针，所有共享 `MapView` 的页面自动热切换。
- 城市编码不是业务数据城市（默认 `370500`）时，前台地图叠加层清空显示，但数据库记录不删除；切回业务城市后可恢复。

后台 API 需要对地图目录读写，业务 Nginx 只需要只读。生产环境不要让 Spring Boot 传输 PMTiles 字节，静态服务器必须支持单段 HTTP Range，并返回 `206` 和正确的 `Content-Range`。

## 2. 可上传 ZIP 规范

ZIP 解压后的根目录必须直接包含以下内容，不能再套一层城市目录：

```text
manifest.json
checksums.json
style.json
city-yyyymmdd.pmtiles
fonts/                 可选，样式引用字体时必须包含
sprites/               可选，样式引用图标时必须包含
sources/               可选，建议保存来源和许可证
SOURCES.txt             可选，建议保存数据来源、日期和许可
```

允许的文件后缀为 `.json`、`.pmtiles`、`.pbf`、`.png`、`.otf` 和 `.txt`。ZIP 上限 512 MiB、解压上限 2 GiB、文件数上限 10,000；拒绝绝对路径、`..`、隐藏路径、重复文件名、符号链接式越界和异常压缩比。

`manifest.json` 示例：

```json
{
  "version": 1,
  "coordinateSystem": "WGS84",
  "name": "青岛离线底图",
  "dataVersion": "20260914",
  "cityCode": "370200",
  "cityName": "青岛市",
  "archive": "./qingdao-20260914.pmtiles",
  "style": "./style.json",
  "bounds": [119.5, 35.0, 121.5, 37.2],
  "minZoom": 0,
  "maxZoom": 15,
  "displayMaxZoom": 18
}
```

约束如下：

- 坐标必须是 WGS-84；未知坐标系不能静默转换。
- PMTiles 必须是 v3、MVT 矢量瓦片，至少到 Z15；文件头的 bounds 和 zoom 必须与清单一致。
- `style.json` 必须是 MapLibre Style v8，只能有一个名为 `protomaps` 的本地数据源，不能引用远程 imports。
- 字体、sprite 等样式资源只能用 ZIP 内相对路径。运行时会把 `protomaps` 数据源重写为本版本 PMTiles 地址，因此样式中的旧数据源 URL 不会被使用。
- `checksums.json` 必须登记除自身外的全部文件，格式为 `{ "algorithm":"SHA-256", "files":[{"path":"...","bytes":1,"sha256":"..."}] }`。

## 3. 这些文件从哪里获得

当前东营开发包位于 `../demo-ronghe/map-data/dongying-dev`，其中 `SOURCES.txt` 记录了实际来源和许可，可直接作为制作新城市包的模板。推荐流程：

1. 从合规的 OSM/Protomaps 数据源提取目标城市范围为 PMTiles；生产测绘成果应由项目的数据供应方提供。
2. 使用 Protomaps Basemaps 的 MapLibre 样式和本地字体、sprite 资源，保留相应许可证。
3. 按 PMTiles 文件头填写 manifest 的 bounds、minZoom、maxZoom，不要凭行政区名称估算。
4. 生成全量 SHA-256 清单，再把上述“内容本身”压成 ZIP。

业务前台已有两个一次性开发工具可参考：

```powershell
cd ..\demo-ronghe\dongying-vue
node tools\extract-map.mjs <pmtiles-cli> <目标pmtiles绝对路径>
node tools\package-map.mjs <pmtiles-cli> <目标pmtiles绝对路径> <basemaps-assets目录> <样式json>
Compress-Archive -Path <地图包目录>\* -DestinationPath <城市>-<版本>.zip
```

现有脚本中的东营范围、名称和来源版本是开发样例。制作其它城市时必须改为对应城市的 bbox、名称、日期与来源记录，不能只改 ZIP 文件名。

## 4. 接口与权限

所有接口遵循 `/api/v1`、Bearer 数据库会话、snake_case 和 `{ok,data,error}`：

- `GET /api/v1/map-packages`：查看版本和运行状态，需要 `map:read`。
- `POST /api/v1/map-packages`：multipart 上传，字段 `file/city_code/city_name/reason`，需要 `map:upload` 和 `Idempotency-Key`。
- `POST /api/v1/map-packages/{id}/activate`：传 `expected_version/reason`，需要 `map:activate`；该动作固定仅超级管理员可用。
- `POST /api/v1/map-packages/rollback`：同上，切回保留的上一版。
- `DELETE /api/v1/map-packages/{id}`：传地图包自己的 `expected_version/reason`，需要 `map:delete`；当前版和回滚保留版不可删除。

所有写操作都有审计记录和幂等保护。版本冲突时刷新列表后重试，不要绕过 `expected_version`。

## 5. 部署

Compose 已配置共享目录。若不用 Compose，保持三个位置一致：

```text
Spring: MAP_DATA_DIR=/srv/map-data        # 读写
Nginx:  alias /srv/map-data/              # 只读
URL:    /map-data/control/map-config.json # no-store
```

`/map-data/packages/` 是不可变版本，可长缓存；`/map-data/control/map-config.json` 必须 `no-store`。参考 `deploy/nginx.conf`。后台反向代理还需 `client_max_body_size 513m`、关闭请求缓冲并给上传与校验留足超时。

本地 profile 默认让后端和业务 Vite 共用 `../../demo-ronghe/map-data`。若目录不同，同时给两者设置同一个 `MAP_DATA_DIR`。

## 6. 上线验收

1. 上传东营同城市新版本，确认页面显示“校验通过”，前台尚未变化。
2. 启用后访问运行指针，确认 `revision`、`package_id` 和 manifest URL 已更新且响应为 `no-store`。
3. 前台保持打开，30 秒内确认所有地图自动切换；PMTiles 请求必须返回 `206`。
4. 上传并启用其它城市，确认底图切换、业务叠加层为空、数据库业务表数量不变。
5. 执行回滚，确认上一版恢复且审计日志包含上传、启用、回滚记录。
