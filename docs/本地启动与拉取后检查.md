# 拉取代码与重启后的固定检查

2026-10-13 用户要求。适用于业务前台、管理前端、统一后端和设备模拟器。

## 完成标准

“端口监听”“首页 HTTP 200”“JAR 启动日志”均不是完整验收。每次拉取、构建或重启后都执行 `scripts/check-local-startup.mjs`，退出码为 0 且报告时间属于本次操作，才可报告所选范围的自动启动检查通过。真实账号登录、登录后权限和业务操作须单独验证并记录；自动检查不代替它们。

检查器使用 Node 20+ 自带能力，无额外依赖、无账号密码。读取实际页面内由 Vite 写入的 API 路径，发送空登录表单并验证 HTTP 400 / VALIDATION_ERROR，再检查未登录 `/auth/me` 返回 HTTP 401 JSON。空表单只测试参数校验，不猜密码、不创建登录会话、不累计错误密码尝试。

还检查后端 readiness 的 UP 状态、前后台代码目录标识、预览页面及入口 JS/CSS 与指定目录 dist 内容一致、地图配置及 manifest、前后台地图配置一致、模拟器首页及状态契约。地图已纳管时优先检查已发布指针、no-store、版本清单和两端清单内容；仅指针缺失（204/404）时检查内置地图，已启用资源损坏不能靠内置地图正常掩盖。旧页面无元信息直接失败，不能猜成 `/dev-api` 后放行。检查仅支持同源 API，跨域地址需先配置本地代理。

同源 JS/CSS 资源可以带 Vite 热更新时间戳或版本缓存参数（如 `?t=...`、`?v=...`）。检查器读取完整资源 URL；预览资源仍与去掉查询参数后的本地文件内容逐一比较。API 和地图配置地址仍不接受查询参数，跨源、URL 凭据和片段地址仍会被拒绝。若页面 API 已是 `/api/v1` 或 `/dev-api/v1`，不要仅凭旧检查器的通用“同源地址”提示修改代理或重启服务，应同时核对静态资源 URL。

目录标识证明页面的构建/开发目录，不证明所有未提交代码已构建；因此仍必须先完成下列构建步骤。地图检查不代表每一块瓦片可用；模拟器可处于停止状态，检查不启动场景或制造数据。未覆盖真实设备、推流、持续运行或已登录业务流程。

## 固定顺序

1. **确认版本与本地修改**：分别记录两仓库 `git status --short`、分支、HEAD 和运行进程的绝对代码路径。先保护本地修改，再 fetch/pull；保留用户未提交文件，不用强制覆盖。合并冲突未解决时停止启动流程。
2. **确认运行配置**：记录端口、API 目标、地图来源、数据库名称与服务日志路径，不输出密码或完整环境变量。数据库、数据卷、模拟器历史目录保持原配置；验收固定 `app.dev-seed.enabled=false`。不要整包复制另一个 checkout 的启动环境；明确设置需要的代理变量。确认监听进程归属，不能只按端口杀未知进程。
3. **构建当前代码**：锁文件变化后在对应前端目录执行 `npm ci`；业务前台执行 `npm run build`，管理端执行 `npm run lint`、`npm test`、`npm run build`。后端在 `server/` 用项目要求的 JDK 执行 `./mvnw -DskipTests package`（只打包不等于测试通过）。构建失败不重启成旧包。前端使用 preview 时必须重新 build。
4. **按依赖顺序启动**：数据库/MQTT → 当前代码构建的后端 → 业务前台地图服务 → 管理端 → 模拟器。固定端口，Vite 使用 `--strictPort`。后端记录实际 JAR 路径与 DB，等待 readiness；模拟器正常停止后重启，不删除历史、不自动重播场景。
5. **执行自动检查**：使用下面命令。失败时保留进程与日志，按报告修正，重新运行；不能把跳过项写成通过。
6. **浏览器验证**：刷新原登录页，核对用户实际访问端口。只有使用用户已授权的有效账号完成登录和首屏读取，才报告登录成功。没有账号时明确写“自动检查通过；真实账号登录未验证”，不得为验收重置密码或启用开发种子。

## macOS / Linux：每次重启后必跑

在后台仓库执行，`--business-dir` 必须指向本次拉取的业务前台目录；按实际布局调整，不假定兄弟目录或某个旧 checkout：

```sh
node scripts/check-local-startup.mjs --business-dir /absolute/path/to/dongying-vue
```

本机当前命令（可在任意目录执行）：

```sh
node /Users/frank/Desktop/dongyiwurenji/houtaiguanli/scripts/check-local-startup.mjs --business-dir /Users/frank/Desktop/dongyiwurenji/dongying-vue
```

默认 API 8081、管理端 5175、业务前台 5173、模拟器 8766，均使用 127.0.0.1。可通过 `--api`、`--admin`、`--business`、`--simulator` 传完整 origin，`--admin-dir` 指定管理端目录。仅验收部分服务时显式使用 `--skip-business` 或 `--skip-simulator`，报告会记录范围，不能称为全链路通过。

默认报告：后台仓库 `artifacts/local-runtime/startup-check.json`（忽略提交），含时间、逐项结果、实际 API 路径及构建目录，不含密码或会话。可用 `--report /absolute/path/report.json` 指定位置。退出码 1 代表失败。

## Windows：自动接入现有入口

`一键启动.cmd` → `start-one-click.ps1` → `start-local.ps1` 现在在就绪等待后自动执行同一检查器，检查失败抛错，一键入口不打开浏览器或提示完成。`-SkipWait` 只发起启动，明确警告未检查，不提示启动完成。运行中服务虽可复用，仍须通过指定代码目录与实际 API 检查。

```powershell
.\scripts\start-local.ps1 -WithMqtt -WithSimulator -BusinessRoot 'D:\project\dongying-vue' -SimulatorRoot 'D:\project\tools\device-simulator'
```

地图读写使用同一个绝对目录，并由启动器明确传给后端和业务前台的 `MAP_DATA_DIR`。选择顺序为 `-MapDataDir` → 当前会话已有的 `MAP_DATA_DIR` → 实际 `BusinessRoot` 的 `../map-data`、`../../map-data` 中首个含 `dongying-dev/manifest.json` 的目录；两处都没有时选择第一处，与业务 Vite 的默认规则一致。相对配置按执行启动命令时的目录解析一次，不能让前后端各按自身工作目录解析。没有业务代码目录的单后端安装则使用 `server/data/map-data`；`-SkipBusinessFrontend` 不要求安装业务前台，仍可显式指定地图目录。启动器不复制或删除地图数据，也不会替换数据库、密码或种子配置。

```powershell
.\scripts\start-local.ps1 -BusinessRoot 'D:\项目 空间\dongying-vue' -MapDataDir 'D:\共享 地图\map-data'
# start-one-click.ps1 同样支持 -MapDataDir；也可继承当前会话的 MAP_DATA_DIR。
```

运行清单 `artifacts/local-runtime/services.json` 会记录后端和业务前台的 `map_data_dir`。复用已有服务前，启动器核对地图目录、代码目录、进程身份及实际监听端口归属。旧启动器或手动启动的进程若没有可验证记录，或这次换了目录，启动器明确失败，提示先停止并重启本项目相关服务；不会仅凭 HTTP 200 复用，也不会自动终止进程。即使跳过启动业务前台，若检测到将用于地图代理的现有业务服务，也必须通过同一检查。

旧 `smoke-system.ps1` 也先执行无密码检查；需要额外验证有效账号及设备契约时，继续使用原有受保护的密码输入方式，指定 `-BusinessRoot`。无密码不会跳过前端代理检查。

```powershell
.\scripts\smoke-system.ps1 -RequireBusinessFrontend -RequireSimulator -BusinessRoot 'D:\project\dongying-vue'
```

## 回归验证

```sh
node --test scripts/tests/check-local-startup.test.mjs
```

Windows 地图目录及复用边界的隔离回归（不启动、停止服务，不接业务数据库）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/tests/local-map-directory.test.ps1
```

覆盖不同业务目录布局、中文/空格/引号路径、显式参数与继承环境的优先级、相对路径、单后端默认值，以及旧状态、目录变化、未知进程和错误端口归属的复用拒绝。

覆盖实际 `/api` 404 而 `/dev-api` 正常、SPA 回退 HTML 200、错误 JSON 契约、错误目录、旧静态资源、缺元信息、鉴权拦截缺失、Actuator JSON 及 DOWN 状态，以及开发/预览静态资源缓存参数、真实跨源与错误API参数；管理端的 `previewApiProxy.test.js` 另测真实 Vite 预览转发与构建元信息。
