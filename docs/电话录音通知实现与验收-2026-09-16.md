# 电话录音通知实现与验收（2026-09-16）

本轮代码为短信之外补充电话录音通知。业务前台无人机事件的通知与现场核查位置可分别查看短信、电话录音状态；后端默认关闭电话功能。当前没有启用运行环境、没有拨打真实电话、没有生成业务录音、没有写入业务数据库。

## 触发与结果边界

- 触发数据：事件、已关联目标的当前观测、最新 ACTIVE 研判，以及必要时的近期人工确认；共享现有演示时效（目标/研判 120 秒，事件/确认 300 秒，可沿既有配置调整）。最新合法/未知/过期研判不回退旧确认；数据不足、现场未知或已飞离均阻断。
- 自动动作：独立数据库任务领取、稳定通道幂等键、事务外调用模拟端口、事务内原子保存结果/事件版本/审计。关闭页面不停止后台工作；GET 只读。
- 两种渠道独立防重，先短信或先电话都不压制另一通道。人工联系事实仍阻断重复自动通知。只有明确模拟接通并播完的回执写入成功电话联系记录。
- 人工介入：明确失败且当前触发、录音及权限仍满足时可申请补呼。调用结果未知、只有接通证据或租约过期都保留 UNKNOWN，需通道对账，当前没有对账接口，因此禁止补呼。补呼不改变录音内容且沿用原 provider_key。
- 历史事实：已接通/播完、任务来源及成功记录不因后来关闭配置、录音缺失或观测过期而消失。关闭策略后仅整理过期 CALLING，不新建或拨打。
- 录音来源：只读取部署端配置的已有绝对路径 WAV，校验元数据、真实可读音频帧及长度，实际计算 SHA-256；最大 10 MiB。没有用户录音资料时仍不可用。本轮没有增加上传、制作或管理录音功能。
  - 2026-10-06 补充：后台已可上传、选用录音，选用的上传录音优先于上述启动参数，见[电话通知录音管理](电话通知录音管理-2026-10-06.md)。仍不制作或转码录音。

## 接口

2026-10-08 暂停恢复修正：`BLOCKED` 且 `attempt_count=0` 的电话任务继续参与后台资格检查；每次仍核对短信送达后的 3 秒观察、当前有效位置、事件与最新研判的精确任务关联、执行飞手、通知配置、录音及不反制决定。查询摘要也按当前条件显示原因，GET 不更新任务或拨打电话。条件重新满足时才领取首次外呼，不能永久沿用“尚无精确关联任务”等旧原因。已尝试的 `BLOCKED`、已完成、明确失败和结果未知不因此自动重拨；原幂等键、人工补呼与历史快照规则保留。候选按最近检查时间轮转，防止持续暂停的任务占满批次。

本次验证在 `server/` 执行 `./mvnw.cmd -f target/voice-resume-verify-91bed36ec06c42e784683c31249fc6a4/pom.xml "-Dtest=AutoVoiceApiTest,NotifyFlowTest,AutoVoicePostgresTest" package`。独立源码快照中的四个修改 Java 文件已与工作区逐一校验哈希一致；H2 接口 34 项、通知阶段 5 项、隔离 PostgreSQL 16.9/PostGIS 3.5.2 接口及迁移 35 项，共 74 项通过，失败/错误/跳过均为 0，打包成功。PostgreSQL 使用 `advisory_verify_item36` 内随机 schema 并清理，实际 Docker 端口为 5432。验证途中纠正了旧端口连接配置和违反只追加约束的测试夹具；共享构建目录还曾出现存储组件加载失败，最终独立构建复验通过。未重启验收服务、未修改验收业务数据，也未完成运行页面复验。

GET `/api/v1/uav-events/{eventId}/advisory` 新增 `voice_mode`、`auto_voice`，原 `auto_sms` 保持。`auto_voice` 在原短信摘要字段外增加 `recording_id`、`recording_name`、`answered_at`、`playback_completed_at`；无证据不返回时间。状态包括 DISABLED、WAITING、CALLING、SIMULATED_PLAYED、FAILED、UNKNOWN、UNAVAILABLE、BLOCKED。

POST `/api/v1/uav-events/{eventId}/advisory/auto-voice/retry` 接收 `{expected_version,note}` 与 Idempotency-Key，复用现有 alarm:read、alarm:verify、handoff:create 和事件范围。受理仅排队；同键同请求重放不重复操作。同键用于其他通道/事件/请求会冲突。

完成记录以 `VOICE_SIMULATED` 和 `SIMULATED_PLAYED` 合并到 `records`；后台模拟主体为“自动电话录音服务”，仅使用明确“演示飞手”接收端，没有真实手机号。后续新交接材料冻结这些联系事实，旧快照不回写。`voice_mode=SIMULATED` 保留历史尝试的来源，不能作为“当前已启用”的判断依据。

## 剩余限制

正式电话通知仍需供应商协议/幂等支持、授权且可追溯的号码来源、可信回调认证、接通/播完回执与对账，以及用户实际录音。没有这些资料时保持不可用。本轮模拟回执不表示实际拨号、实际播放、真实接听或目标已飞离；不会自动批准反制或处罚。管理端 ruoyi-ui/src 未发现 advisory 直接消费者，无需添加管理菜单。

## 2026-10-06 调整（验收问题 ZT-19、ZT-44、BUG-12）

- 通知时效（ZT-19，验收用例 TC-EXT-013，待产品确认）：告警建立超过事件时效（`app.advisory.auto-sms.event-seconds`，默认 300 秒）后才满足短信条件的，后台不再自动发短信（`auto_sms.status=BLOCKED`，原因以“事件已超过自动通知时效，需核对最新情况”开头），电话也不自动拨打（`auto_voice.status=BLOCKED`，电话任务本身不写成终态）。有补发权限的人用原补发接口 `POST /api/v1/uav-events/{eventId}/advisory/auto-sms/retry` 登记“核对后发送”（`trigger_source=MANUAL_RECHECK`，审计 `auto_sms_recheck_requested`），之后电话按短信结果照常办理。核对并登记发送之前，事件不进入待反制，处置进度里也没有发起反制，先由人核对最新情况；如果要改成核对后可以不发短信直接进入处置决策，需产品确认。本来就发不了（通道未接通、没有可通知的飞手）的保留原状态，原因前面补上时效说明，通知阶段照旧进入待反制。已经发出的记录不受影响。这一条调整了 2026-09-21“短信不以时效作门槛”的约定。
- 电话后的观察（ZT-44）：判断是否离开时，空域按短信发出时目标所在的位置取，只看录音播完之后的新位置（`PilotDepartureWatch.assess(eventId, smsAcceptedAt, since, now)`）。没有短信发出时间就按“无法确认”处理，不再用播完时刻的位置取空域。
- 误报（BUG-12）：核实为误报且还没有发送记录时，`auto_sms`、`auto_voice`、`auto_handoff` 都返回 `NOT_REQUIRED`，页面显示“不需要”，不再显示等待；已有发送记录的保留原结果。
- 本机复测：后端、数据模拟器和仓库里的接收程序一起跑，告警 5 分钟后核实，短信、电话都没有自动发出，页面显示“需核对最新情况”；点“核对后发送飞手短信”并确认后，短信送达，3 秒后目标仍在禁飞区，电话接通并播完，随后进入待反制。误报事件三项都显示“不需要”。
- 录音提示：电话录音还没选用时，原因改为“还没有选用电话通知录音（在管理端 运维管理 → 接口配置 → 电话通知录音 上传并选用），电话通知不能执行”。
