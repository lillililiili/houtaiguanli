# 告警、合法性研判与移送的目标编号筛选

2026-10-18：三个业务页面增加目标编号输入框，输入后点击“查询”或按 Enter，清空后恢复其他筛选条件下的列表。支持完整编号或部分编号，不区分大小写；页面省略的“目标-”前缀可带可不带。

## 接口

以下 GET 接口支持可选 `target_no`：

- `/api/v1/alarms`、`/api/v1/alarms/export.csv`
- `/api/v1/legality-evaluations`、`/api/v1/legality-evaluations/summary`
- `/api/v1/handoffs`、`/api/v1/handoffs/stats`

去除首尾空白后长度为 1–64；空值、重复参数和超长值返回 400。省略参数表示不按目标编号筛选。`%`、`_` 等字符按字面匹配，不是通配符。筛选使用 `target.target_no`，不以内部 UUID、告警编号、移送编号或材料全文代替。

筛选在计数和分页前执行，告警导出、合法性汇总及移送统计使用同一条件。合法性仍先选定目标最新研判，不能回落到旧研判；其他日期、状态、来源和范围条件保持交集。告警和处罚页顶部全局统计卡保持原口径，合法性顶部统计及处罚下方分布跟随列表筛选。

## 权限与关联

除接口自身权限外，出现 `target_no` 时先检查 `target:read`；移送接口还检查 `alarm:read`，与读取事件关联的要求一致。检查先于参数解析。目标与告警、研判或移送必须属于同一组织及区域，继续执行现有数据范围条件。

移送仅匹配 `UAV_EVENT` 的 `handoff → uav_event → alarm → target` 明确关系，风险通知不通过该参数匹配。无目标、目标关联错误或超出范围不计入匹配结果。不回写历史或冻结材料，无数据库迁移。

## 布局与验证

复用 `UField`、`UFilterBar`。告警工具栏采用可换行网格，目标编号完整换行；合法性沿用现有编号换行，处罚保留清单的局部横向滚动。

回归入口：`TargetNumberFilterApiTest`、`TargetNumberFilterPostgresApiTest`。隔离测试覆盖动态编号、mock/replay/live、完整及部分编号、分页、统计和导出一致性、清空、无结果、字面字符、无权限与错误组织关联。PostgreSQL 测试仅使用 `stage456_verify_*` 隔离库，不连接业务库。
