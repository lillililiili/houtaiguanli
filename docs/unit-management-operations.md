# 单位后台授权：开发与验收约定

本说明记录本轮实现契约与验证方法，不代表已完成运行环境或七流程验收。测试执行结果以对应批次报告为准。

## 授权模型

单位管理员保持前台账号身份，使用独立任命关系进入管理后台。本单位人员、角色管理继续保留；新增后台功能由平台在“用户管理 → 选中单位 → 单位授权”中配置。

| `module_key` | 功能 | 允许级别 | `OP` 对应操作 |
|---|---|---|---|
| `devices` | 设备管理 | `NONE` / `READ` / `OP` | 本单位设备接入、资料和覆盖范围维护、启停及删除，仍受原业务校验约束 |
| `monitoring` | 设备实时监测 | `NONE` / `READ` | 无操作级别；状态、历史、事件及趋势只读 |
| `maintenance` | 设备异常处理 | `NONE` / `READ` / `OP` | 接手与办结等现有异常处置动作 |
| `commissioning` | 设备接入调测 | `NONE` / `READ` / `OP` | 创建、连接、确认配置、开始及取消调测 |
| `statistics` | 报表管理 | `NONE` / `READ` / `OP` | `READ` 可预览与查看明细；`OP` 可下载 PDF、Excel |

`OP` 包含 `READ`；未知模块、重复模块和 `monitoring=OP` 均拒绝。管理授权与前台 `permissions`、`actions` 独立保存，不能据此获得前台审批、执行或直接反制权限，也不改变原 `AccessService` 的业务权限含义。

单位授权请求及响应新增 `management_permissions: [{module_key, level}]`。首次启用时未提供该字段，五项均为 `NONE`；已纳管单位省略或传 `null` 时保留既有管理授权。显式列表为整组替换，未列出的模块为 `NONE`。界面提交完整五项。

## 服务端边界

- 新入口位于 `/api/v1/unit-admin/operations/...`，由服务端建立本次调用的单位上下文。单位从有效任命、当前账号及台账关系确定，不接受客户端扩大单位范围；只包含精确本单位，不包含下级单位。
- `UnitManagementAccessService` 每次读取当前身份及授权。撤任、停用账号或单位、角色失效、离开所属单位、失去 `OWN_ORG` 或要求修改临时密码后，不再允许相关管理操作。后台授权调整纳入版本、快照、幂等、审计及旧会话撤销。
- `/auth/me.management_context` 返回可用管理菜单和权限；业务 `menu_keys`、`permission_codes` 不混入后台授权。共享设备选择器可供已授权的监测、异常、调测页面使用，不因此获得设备修改权限。
- 原平台专属 `BackendOnly` 入口继续限制平台后台身份。接口配置、全局地图启用、规则管理、平台审计及跨单位人员调整不随本轮授权开放。
- 设备列表、数量、详情、监测事件及调测按明确的 `device_business_scope` 单位关系过滤。设备接入固定本单位；单位管理员不能更换为其他单位的来源。影响其他单位设备的共享接入来源交由平台维护。

## 报表与调测

单位报表接口为 `/api/v1/unit-admin/operations/stats/reports/{preview,details,export.pdf,export.xlsx}`。`statistics` 授权不等于所有数据模块已开放：业务数据按单位已开放的前台模块判断，设备及异常数据按相应后台模块判断。未开放分区显示“不可用”及空总数，不伪装为实际零；明细接口仍拒绝读取未授权分区。统计、分页及导出采用同一单位范围，正式／模拟来源标识保持。原业务报表入口仍按原业务权限执行。

单位调测使用台账登记的连接。TCP 调测配置确认只提交版本，不允许临时传入另一套连接；开始及实际执行前核对连接快照。任务保存单位管理来源和真实排队执行人，实际发送前复核任命、调测操作权限、临时密码状态和设备当前归属。撤权后未发送任务不得继续执行，不能伪造成功回执。原已执行设备的停机、重试及回执处理保持既有闭环。

## 页面与角色

单位授权点击“保存并立即生效”时，内部先取得快照凭据，再提交同一单位、版本和冻结请求；不显示独立预览步骤。并发变化或凭据失效时不提交旧请求，结果未知时先重新读取配置。

平台角色管理分为“全局角色”和“单位角色”，单位角色需选择所属单位。平台创建角色可传 `owner_org_id`，必须为已纳管且启用的单位，权限不能超过该单位上限；省略或空白表示全局角色。同名角色可以分别存在于全局及不同单位，角色编号与权限彼此独立。单位管理员仍不能通过修改本人所用角色调整自身业务授权。

2026-10-21 起，启用单位管理、任命或替换管理员不再自动复制角色。平台必须明确选择本单位角色，或在单位授权中手动定义角色并分配人员；新建权限默认为无。已有单位角色继续独立维护，不按同名合并或关联全局角色。“我的权限”独立于角色列表，直接按 `/auth/me` 展示账号实际可用的前台功能、业务动作、后台功能及本单位数据范围。

存量自动副本通过显式人员分配与副本清理操作迁移。只有来源明确、目标同单位、原用户有效权限完全等价、全部引用已清空时才删除副本；禁止修改目标授权凑等价，管理员替换及单位上限调整须另行保存。提交依然使用原角色编号，不重写历史记录。具体请求及操作约定见 `单位管理员与单位授权.md`。

角色查询接口通过可空的 `copy_origin` 返回 `source_role_code`、`source_role_name` 和 `copied_at`；权限计算不使用这些说明字段。历史角色只根据成功单位授权审计中明确的同单位、同人员角色变更补齐来源，缺失、冲突或不匹配时不推断，不按同名或编号猜测。

## 验证方法

1. 建立两个独立单位及一个下级单位，分别验证列表总数、分页、详情、消息和导出只出现精确本单位记录；篡改单位或设备编号应拒绝。
2. 仅授权后台模块、保持管理员前台角色无对应权限：新管理入口按授权可用，旧前台业务接口仍拒绝；普通单位人员不能继承管理员后台授权。
3. 对各模块分别验证 `NONE`、`READ`、`OP`；监测拒绝操作级别，报表只读账号不能导出，未开放分区与实际零数据明确区分。
4. 验证省略后台授权字段不会清空旧授权，显式替换可收紧；旧快照、旧版本和重复请求不能重复修改。收紧后旧会话失效，已排队调测在发送前被限制。
5. 验证临时密码、撤任、账号／单位／角色停用及设备跨单位变动；确认调测连接快照不能临时替换，共享来源越权修改应回滚。
6. 回归全局角色创建、本单位角色创建、同单位重名拒绝、不同单位同名独立及权限上限；报表或运维请求失败后，后续业务请求不能残留管理上下文。

后端覆盖以 `UnitDelegationApiTest` 及 PostgreSQL 子类、单位运维／报表专项测试为主；前端验证菜单、接口路由、一键保存与角色分栏。实际构建和重启后仍须执行仓库启动检查并单独记录有效账号登录及七流程回归，不能以单元测试代替浏览器验收。
