## 5. 业务状态与数据边界

### 5.1 三条流程独立建模

1. 无人机：告警触发 → 人工核实 → 一次人工发起联动反制 → 系统自动执行信号干扰 → 通知处罚部门。保留误报分支；联动是同一共享用例，实际下发和推进必须满足确认后的授权条件并依赖真实回执。交接完成不等于处罚办结，不增加手工归档环节，也不把 Mock `cases` 全量认作正式行政案件。
2. 飞行风险：`待核验 → 待通知 → 已通知`；待核验可转 `已排除`。`已通知/已排除` 保留现有终态语义；发送受理、送达、回执是独立通知记录的状态。真实渠道中何种结果允许进入“已通知”须在 Q4 确认，不能点击按钮即判成功，也不擅自增加“处置完成”风险终态。
3. 设备异常：原因与确认 → 下发重启 → 等待设备回执 → 平台恢复校验 → 关闭异常。前端摘要为 `待处理/处理中/待验证/已恢复`；设备在线、重启指令完成、异常恢复是不同事实，回执成功不直接等于平台恢复。

工作台可发起上述模块的动作，但不另建状态机。每个用例由后端统一检查当前状态、权限、前置条件及并发版本，成功后同步关联记录与审计；失败不得推进成功状态。

### 5.2 标识、来源与规则

- 平台业务主键、外部来源编号、展示编号、前端视图 key 分开。`uav:<targetId>/risk:<id>/device:<deviceId>` 不是持久化事件主键；每次设备故障有独立异常实例，历史记录不被下一次故障覆盖。
- 上报保留来源系统、来源 ID、接收时间与原始发生时间；跨来源 ID 不默认全局唯一。同目标告警的合并窗口、跨设备关联策略由 Q2/Q6 确认，不按空间接近自行合并。
- 数据分别标记真实上报、服务端推导、人工录入或演示来源。人工输入也需记录操作者和依据；推导结果留存输入依据和规则版本。
- 未知、不适用、缺失、过期应能区分，不以 0、合法、在线或成功替代未知。前端中的随机序列、固定演示时间、虚构文件哈希不得成为生产数据。
- 保留坐标系及高度基准。当前地图接入边界为 WGS-84，见[离线地图部署说明](离线地图部署说明.md)；业务接口与地图资源独立，不把旧高德代理作为后端建设前提。不明坐标系不静默转换，AGL 与 AMSL 缺少可靠转换依据时不得直接比较。
- 新增时间字段明确单位和时区，区分设备时间、接收时间、业务更新时间；业务时间通过后端统一时钟获取，测试可控。现有 epoch 毫秒字段保持兼容。
- `RISK_RULE` 高度余量、部分 `COMM_TH`、`EVID_RETAIN` 和演示处罚参数等不能未经确认用于生产判断。证据文件已按与 Demo `EVID_RETAIN` 同口径的**平台缺省**计算到期日，到期且未冻结可人工销毁，不自动清理；正式年限仍待 Q7。规则调整需有版本、影响范围及验证证据。
