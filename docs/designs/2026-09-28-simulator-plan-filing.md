# 模拟计划资料补齐

用户已确认补齐计划上传、保存和关联链路。沿用现有计划表及详情契约，不新增迁移，不改变审批、研判、通知或真实接入流程。

- 在 `PlanInput` 增加可选 `filing`：申报单位/飞手名称、WGS-84 起降点名称与坐标、技术来源及三个目录关联 ID。旧最小报文仍可重放。
- 新增本地模拟计划资料查询/补录入口，要求接口操作权限、计划可见、模拟模式及乐观版本。保留原时间、状态、SN、航线、原消息和历史快照。已有技术来源不允许替换；空来源可补齐。
- 档案关联复用 DirectoryService，继续检查单位管理权限、范围、来源一致、飞手归属/角色/有效性。资料与关联在同一事务保存，失败全部回滚。来源只能选择启用的 mock/replay 来源。
- 模拟器地图工作区的飞行计划输入增加可填写表单，保留同步 JSON；历史接收记录及计划选择器提供补录入口。选择档案时可填入对应名称，允许保留申报时名称，不自动创建或猜测档案。
- 不自动回填截图中的历史数据。通过补录入口提供真实的模拟资料后保存。

实施与验证顺序：先写接口和表单回归用例，确认失败；补 DTO/应用服务/持久化、模拟器代理白名单及表单；跑 H2 与隔离 PostgreSQL/PostGIS、模拟器契约与浏览器检查；打包、重启受影响服务并验证 HTTP 可达。
