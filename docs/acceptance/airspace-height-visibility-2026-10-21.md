# 大范围空域三维高度显示修复

## 根因及范围

用户扩大边界后，水平跨度超过百公里，实际高度仍为百余米。原编辑器对水平和垂直使用同一米制比例，导致高度被压缩到不足一个屏幕像素；不是高度字段丢失。本次在实际登录页面复现：0–150 米上、下手柄只相差约 0.266 像素，显示为近似平面。

本轮为 L2 局部显示和交互修复，仅修改三维编辑组件及新增显示投影适配模块。不修改表单保存逻辑、经纬度/海拔数据、后端或上级下发接口；不重启服务、不启用种子。

## 修复行为

- 默认启用“突出高度”：当投影厚度过薄时，仅放大显示中的垂直轴，让上下层保持至少 100 SVG 单位间隔。倍率随空域范围、视角和缩放计算，不对某个空域编号或坐标特判。
- 显示实际海拔下限、上限及厚度，并明确标注“高度显示放大 N 倍，仅影响画面，保存值不变”。可切换“真实比例”对照；天然足够厚的小范围空域保持原比例。
- 投影、坐标反解、高度拖动使用同一倍率；拖动期间固定坐标框架，拖动结果仍为实际 WGS84 经纬度及 AMSL 米值。缺少高度、零厚度和倒置上下限不制造立体高度。
- 显示适配单独放在只由三维子组件引用的模块中，本轮热更新没有重置父表单已填写的边界和海拔。
