## 准备和启动

1. 确认 8081、5173、5175、8766、MQTT 1883 正常；验收服务种子为 false。先停止上一批次及全部收发，保留原有运行记录。
2. 在模拟器用现有账号登录，检查单位区域、replay 绑定及源模式；不要在场景或聊天保存密码。
3. 导入一个场景，检查北京时间的计划/空域窗口、AMSL、高度范围。业务组使用明确标准化观测，协议组使用协议 A MQTT，不能互相当作证明。
4. 同一空域同一有效期且定义完全一致可复用已受理版本。修改定义时须遵守平台版本及生效时间规则；409 应核对原版本，不能改幂等键盲重试。结果未知时先回读。
5. 点击开始模拟。观察“资料准备”和“回读平台数据”；只有平台实际目标、研判、告警/指令回读才可填写结果。MQTT 发送计数不是业务完成。
6. 结束时停止场景和全部收发；光电任务须先通过既有结束入口核实停止。停止上报不代表飞离或设备恢复，历史记录不清除。

## 场景说明

| 文件 | 用途/注意 |
| --- | --- |
| `01-normalized-legal.json` | 明确合法，三路标准化模拟输入；路径在既有测试禁飞区外 |
| `02-normalized-disposal.json` | 明确违规，进入测试禁飞区；是否可反制由现有平台实时资格决定 |
| `03-after-sms.json` | 只在当前目标实际模拟短信送达后移动，位置继续通过观测进入平台 |
| `04-after-voice.json` | 等到播放完成，不以接通代替；平台仍等待原有 10 秒观察 |
| `05-stop-reports.json` | 短信后停报，预期未知，不能填 LEFT |
| `06-mqtt-height-unknown.json` | 协议 A 不携带可信 AMSL；检验未知高度阻断 |
| `07-mqtt-no-sn.json` | TDOA 缺 SN，型号保留，不能补号 |
| `08-device-fault.json` / `09-device-offline.json` | 独立 radar 在 10 秒时故障/停心跳 60 秒；含独立运维检查计划。导入前把该计划开始/结束时间设为当前北京时间之后，未开始计划才显示起飞前检查。恢复工参不保证恢复 PASS |
| `10-eo-video.json` | 在当前目标页面人工补跟踪，实际报告/媒体就绪后点播放；默认动态测试图 |
| `b-failure.json` / `b-no_receipt.json` | 平台实际下发指令后失败/不回执 |
| `b-late.json` / `b-duplicate.json` | 延迟 120 秒/显式重复回执；超时终态及续链依平台规则 |

模板中的同类设备使用稳定编号，独立观测源带批次身份。不可同时运行相同设备编号的两个模拟器发布进程。旧场景默认仍为一路标准化源。

## 通知接收配置

先停止全部收发，再通过现有收发模式设置调整；也可调用现有接口（模拟器已登录）：

```powershell
$config = Get-Content -Raw -LiteralPath 'D:/沉积岩/demo-ronghe/tools/device-simulator/scenarios/item2/notification-configs/normal.json'
Invoke-RestMethod -Uri 'http://127.0.0.1:8766/api/realtime/config' -Method Post -ContentType 'application/json' -Body $config
```

提供 `normal`、`sms-failed`、`sms-no-receipt`、`voice-answered-only`、`voice-delayed`、`handoff-no-receipt`。默认关闭独立四通道 TCP 接收端，协议 B 仍由场景设备自身配置处理。`play_seconds=3` 是测试录音播放历时，不是平台电话播放后的观察时长；后者仍为 10 秒。

接收端只响应平台已有出站消息。无有效执行飞手/核验/通道/录音时不得主动补送达。收到、送达、接通、播放完成、签收分别核对，签收不是处罚办结。异常、重复、错误关联的正式回归在测试中独立执行，不混入默认正常演示。

## 业务与运维操作顺序

业务：回读 ILLEGAL/SUFFICIENT/无阻断未知 → 人工核实模拟告警 → 核对短信/电话及位置 → 普通申请 → 另一已授权账号审批 → 执行 → 实际协议 B 收发 → 干扰续链 → 移送送达/签收及冻结材料。任何阶段阻断，记录真实原因，不改终态。

运维：独立未开始计划的“起飞前·周边设备检查” → 只选择本轮 radar 的“通知设备异常” → 管理端运维消息“去处理” → 开始处理 → 保存进展 → 提交恢复核验 → 执行恢复核验。仅当平台回读 PASS 且完成时再次检查仍有效才可完成。当前协议 A 路径可能保持 UNKNOWN，属于未完成，不是通过。

视频：有效目标 → 人工补跟踪 → Begin 回执 → 当前报告 → 媒体就绪 → 点击播放 → 核对连续变化和播放时间 → 收起（任务仍在）→ 刷新核对同一任务 → 暂停并结束 → 核对任务和推流停止。不要把截图或注册成功当连续播放证明。
