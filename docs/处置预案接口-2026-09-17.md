# 处置预案配置与空域关联

范围：后台维护处置说明、发布版本、关联空域；业务前台只读查看。`execution_mode=GUIDANCE_ONLY` 表示发布或关联不触发通知、反制或其他设备动作。自动通知仍使用已有策略与渠道，反制仍遵守独立授权及执行回执。此功能不是可执行规则编辑器。

## 使用入口

后台“系统管理 → 处置预案”：新建草稿，填写名称、触发依据与时效、行动说明、人工介入与授权条件、失败处理、有效期和配置来源；保存后发布，再选空域关联具体已发布版本。

业务前台“空域管理 → 选中空域 → 处置预案”：查看当前适用性、发布信息、有效期、关联依据、原文和关联历史。未关联、读取失败和无权限分别展示。

## 数据与状态

- `response_plan` 保存稳定预案身份和归属空域。归属空域用于组织/区域范围校验，不因选择某条预案自动创建关联。
- `response_plan_version` 保存完整版本内容；DRAFT 可以按 `expected_version` 编辑，PUBLISHED 的内容不可改，修订创建新版本，WITHDRAWN 保留内容与停用原因。已存在草稿时不能再建第二个草稿。
- `airspace_response_plan_binding` 保存精确版本关联。关联只允许同组织与区域内空域，替换和解除保留原记录、时间、人员、原因，不自动跟随最新发布版本。
- 每空域最多一个当前关联：空域行锁配合 PostgreSQL 部分唯一索引。`expected_binding_id` 为空表示调用方确认当前未关联；有值必须匹配当前关联，否则 409。
- 有效期使用 epoch 毫秒、左闭右开 `[valid_from, valid_to)`；无结束时间为长期。过期草稿不能发布，过期或未发布版本不能新增关联；已关联但随后过期/停用仍保留原文并显示原因。
- 适用性由服务端业务时钟计算：APPLICABLE、SCHEDULED、EXPIRED、WITHDRAWN、UNPUBLISHED、AIRSPACE_INACTIVE、UNKNOWN、HISTORICAL。空域有效版本重叠时为 UNKNOWN；无有效版本不能显示当前适用。接口返回 `checked_at`，表示本次查询时间，不宣称持续自动刷新。
- `source_mode=live/mock/replay` 是配置来源声明，展示为正式/模拟/回放配置，不等于真实设备执行。
- 所有写入与审计同事务，`Idempotency-Key` 使用已有防重守卫；同键重放返回 409，提示刷新查看，不重复执行。

## 接口

保持 `/api/v1`、Bearer 会话、snake_case、`{ok,data,error}`。分页从 1 开始，size 为 1–100。

| 接口 | 用途与权限 |
| --- | --- |
| GET /response-plans?page=1&size=20 | 按可见归属空域分页查询各预案最新版本；responsePlans.read |
| GET /response-plans/{planId}/versions | 查询该预案所有版本；responsePlans.read |
| GET /response-plans/airspace-options?keyword=&page=1&size=20 | 查询当前管理范围可见空域；responsePlans.read |
| POST /response-plans | 新建预案和首版草稿；responsePlans.auth |
| POST /response-plans/{planId}/versions | 创建新草稿版本；responsePlans.auth |
| PATCH /response-plan-versions/{versionId} | 更新草稿，提交 expected_version；responsePlans.auth |
| POST /response-plan-versions/{versionId}/publish | 发布，提交 expected_version、reason；responsePlans.auth |
| POST /response-plan-versions/{versionId}/withdraw | 停用，提交 expected_version、reason；responsePlans.auth |
| GET /response-plans/airspaces/{airspaceId} | 后台查询当前关联、分页历史；responsePlans.read |
| PUT /response-plans/airspaces/{airspaceId} | 关联/替换/解除，提交 version_id、expected_binding_id、reason；responsePlans.auth |
| GET /airspaces/{airspaceId}/response-plan | 业务前台查询同源关联；airspace:read，不依赖后台菜单权限 |

草稿输入：`airspace_id,name,trigger_basis,action_steps,manual_conditions,failure_handling,source_mode,valid_from,valid_to`。名称最多128字，四项说明各4000字，动作依据1000字；服务端校验必填、长度和有效区间。空域关联返回 `airspace_id,checked_at,execution_mode,current,history`，current 无记录时按现有 JSON 契约省略；history 为 `{items,page,size,total}`。

新菜单权限使用既有 MODULE 矩阵：responsePlans 的 READ 可读，AUTH 可维护。普通角色需要管理员按现有权限流程授予；不批量扩大原角色权限。越权对象与不存在统一404，未登录401，缺动作权限403，冲突409。

## 迁移与运行

新增 V202609170010（表与菜单）及 PostgreSQL V202609170011（当前关联唯一索引），不改旧迁移，不追加正式业务预案。2026-09-17 已在独立 PostgreSQL/PostGIS 验证，并在备份后更新本地8081；管理前端5175和业务前台5173读取同一服务。

测试：ResponsePlanApiTest 7项、ResponsePlanPostgresTest 8项、AuthApiTest 9项通过；后端 package 通过。PostgreSQL 测试仅接受 `response_plan_verify_*` 隔离数据库。管理端 lint、47项现有测试与build通过；业务前台scan与迁移回归通过。浏览器验证及截图见业务前台交付记录。

未实现：预案自动驱动事件动作、事件执行时冻结预案快照、真实渠道与设备验收；不得把当前“预案配置与查询可用”描述为这些能力已完成。
