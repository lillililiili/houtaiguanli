# AGENTS.md

本文件适用于 `server/` 及其子目录，补充[仓库级规则](../AGENTS.md)。业务范围、当前实现与待确认问题以[后端开发基线](../docs/后端开发基线.md)为入口；启动说明见 [README.md](README.md)。

这些是后续开发必须遵守的规则，不表示当前骨架已全部满足。基线中的 G1–G7 是待验证/加固事项，不得照搬为新增代码的标准；只在用户授权的任务范围内修复。

## 1. 技术与范围

- 保持同仓库 `server/`、Java 17、Spring Boot 3.4.5、MyBatis Starter 3.0.4、Maven Wrapper（Maven 3.9.9）、Flyway、PostgreSQL 16/PostGIS 3.5。版本以 `pom.xml`、Wrapper 配置和部署文件为实际依据，不以旧方案推测。
- 不引入新的生产或测试依赖、基础设施、构建工具，不升级版本，除非任务明确授权。不要因某种架构习惯自动引入 Lombok、JPA、Redis、消息中间件或工作流引擎。
- 后端 Java、资源与正式测试只放后端目录；npm 命令只在前端目录运行，Maven 命令只在 `server/` 运行。不要在根目录建立第二套后端构建文件。
- 首期是监管侧业务承接，不把路线图中的任务分派、SLA、完整行政处罚审批或融合算法研发默认加入需求。
- 缺少业务规则或设备协议时，标明待确认和阻塞边界。不得猜造协议字段、受控指令参数、审批记录、处罚结果或统计事实。

## 2. 目录与依赖方向

Java 根包保持 `com.uav.lowaltitude`。保留现有 `modules/identity`、`modules/alarm`、`modules/device`，不为目录整齐重命名。新增模块按已授权业务切片创建，不预建无实现的模块树。

| 位置 | 职责 | 禁止事项 |
| --- | --- | --- |
| `modules/<业务>/api` | Controller、请求响应 DTO、传输层校验与映射 | 直接写 SQL、驱动设备、承载状态机或跨域事务 |
| `modules/<业务>/application` | 用例、授权协调、事务边界、调用领域规则和基础设施 | 绕过来源校验或任意修改其他业务模块的数据 |
| `modules/<业务>/domain` | 业务状态、迁移守卫、规则与领域对象 | 依赖 HTTP、Controller、前端全局对象或模拟定时器 |
| `modules/<业务>/infrastructure` | Mapper、持久化和必要的外部实现 | 把 API 响应形状当作数据库模型；拼接不可信 SQL |
| `platform/` | 通用响应异常、鉴权上下文、审计、配置、时钟、存储和后台任务 | 无关业务规则的堆放区 |
| `integration/` | 设备/外部平台适配、协议归一化和来源隔离 | 直接跨模块改业务表；真实模式回退成模拟成功 |
| `src/main/resources/db/migration` | Flyway 版本化迁移 | 手工改已应用脚本或混入演示业务数据 |
| `src/test/java`、`src/test/resources` | 可重复执行的正式测试及隔离夹具 | 真实凭据、生产数据或依赖人工操作的隐藏前置条件 |

- 调用方向以 API → 应用用例 → 领域规则/基础设施为主；跨模块通过应用接口或明确契约协作，不从 Controller 直调其他模块 Mapper。
- 优先复用已有 `ApiResponse/ApiException/AuthContext/AuditService/AppClock/ObjectStoragePort`，但先核实能力和已知缺口，不另建平行系统。
- 使用构造器注入、明确类型和职责小而清晰的方法，沿用 Java 代码风格。新增请求响应定义 DTO，不扩大任意 `Map<String, Object>` 的业务契约，不直接序列化持久化对象。
- 现有注解 Mapper 可继续使用；复杂 SQL 是否拆 XML 按切片需要决定，不批量改写无关查询。新增 Mapper 包必须检查 `Application` 中的扫描配置，新增迁移/资源必须检查打包位置。

## 3. 接口与前端兼容

- 保留 `/api/v1`、Bearer 会话、`ApiResponse` 的 `ok/data/error` 和错误 `code/message`。现有 `session_id` 是数据库会话 ID，不是 JWT；不得无授权切换认证方案。
- 保留既有 snake_case 字段、字符串 ID、epoch 毫秒会话到期时间及 `items/page/size/total` 分页结构。当前页码从 1 开始，默认每页 20、最大 100；新增接口在该结构下明确筛选、排序和边界。
- 输入校验与业务守卫都必须在服务端执行。错误使用匹配的 HTTP 状态和稳定错误码，不吞异常后返回空列表或 `ok: true` 假装成功；日志不得泄露敏感内部信息。
- 当前 JSON 忽略 null。新接口逐字段明确必填、缺失、未知、不适用、单位、时区和状态枚举；需要显式 null 时在局部 DTO/契约处理，不全局更改现有序列化行为。
- 业务数据变化通过服务端结果驱动前端；前端适配层负责旧模型映射，不能让页面继续写一套与后端竞争的状态。接入时明确 Mock 与真实模式，不将接口失败回退为演示成功。
- 同步维护接口说明和受影响消费者。只改后端且没有影响前端契约时不要求前端构建；变更公共契约需检查 Vue 与 legacy 全部消费者，修改前端时遵守该目录规则。
- 保持业务接口与离线地图资源独立，遵循[地图接入边界](../docs/离线地图部署说明.md)。不以旧高德方案替换当前 WGS-84 数据约定或重建地图。

## 4. 数据、事务与并发

- 用实体关系、约束与查询需求设计持久化，不照搬 Mock 数组、视图 key、随机生成器或派生统计值。新业务表随切片建立，不为未确认路线图批量建空表。
- 已应用 Flyway 迁移不可修改；结构变更新增下一版本迁移，先检查现有版本及并行工作避免撞号。禁止关闭迁移校验或手改历史来掩盖错误。 尚未提交但已在某个验收库应用过的迁移也按此处理：改注释都会变校验和，让那个库起不来；只有确知仅一个库跑过且未推送时，才允许删该版本的历史行重跑（阶段 15 对 0104 的处理），否则加新迁移（0105 是正例）。
- 回放数据集的 `dataset_id` 与已应用迁移同理：内容一经灌入即不可改（`inbox_message` 按 `source_msg_id` + 载荷哈希判重，同 id 不同内容让所有已灌过的库启动即抛 `SOURCE_MESSAGE_CONFLICT`）。要加场景就建新数据集 id，旧文件原样不动；改动回放数据后必须在已灌过旧回放的库上启动一次（决策 16-7）。
- JSON/JSONB 列的读取：不用 PostgreSQL 专有的 `->>`/`@>`（H2 语法错），也不用裸 `LIKE`（PG 无 `jsonb ~~ text`，只在 H2 能跑）；要做字符串粗筛写 `CAST(col AS VARCHAR) LIKE …`，取值交给 Java 解析；插入表达式含拼接或函数时 `CAST(... AS JSON)`（决策 13-15、15-18）。任何 JSON 列的 SQL 改动都必须在真实 PostgreSQL 上跑一次。
- 新写公共件先找同仓既有实现：CSV/文本导出一律走 `platform/export/CsvExport`（BOM、RFC 转义、公式前缀、行数上限），不另写转义；JSON 列粗筛用 `QualityFacts` 那类共用片段。阶段 15 两次撞上"仓库里早有正确写法、新代码另写一份错的"（`LineageRepository` 的 CAST LIKE、`AuditController` 的公式前缀）。
- 事务边界：会写审计、幂等键或任何行的方法不得标 `@Transactional(readOnly = true)`（PG 只读事务禁 INSERT，SQLSTATE 25006；H2 不落实该语义）。改动事务注解或在只读方法里新增写操作，同样必须在真实 PostgreSQL 上跑一次（决策 15-20）。
- `db/postgresql/` 下的可重复迁移（`R__*.sql`）不得引用任何版本化迁移建的表：触发器、CHECK、索引等依赖具体表的 DDL 一律写成该目录下的版本化迁移（先例 `V202609070103__stage13_disposal_pg.sql`），R__ 只放幂等且无表依赖的函数定义。原因：R__ 在"先停在中间版本再前进"的库上会被记为已应用而不再重跑，保护会静默缺失且迁移全绿（阶段 13 决策 13-32 修订）。存量九个 R__（stage2/3/7/8/8.5/9）不追溯：它们引用的表最晚建于 V202609050064，而加载该目录的部分迁移停点最早是 073，现有停点碰不到——这是巧合不是设计，所以新增一律照此，且不得新增早于 073 的加载 `db/postgresql` 的停点。
- 数据关系用适当的外键/唯一约束保障；请求去重、来源消息去重、业务操作幂等要分别明确唯一范围，不能只在 Java 中先查后写。
- 应用服务定义事务边界；成功状态、必要关联记录、成功审计及待发送任务须保持事务一致。外部调用不能被当成本地事务可回滚的操作，也不能长时间占据数据库事务等待回执。
- 涉及重复操作或并发状态更新时明确版本/条件更新等冲突保护；失败或受影响行数不符不得继续写成功结果。幂等重放不能再执行一次受控设备动作。
- 业务状态、设备状态、指令状态、交接状态分开。平台事件 ID、来源 ID、展示编号和前端 key 分开；设备每次异常独立成实例，不覆盖历史恢复记录。
- 保留真实来源、发生/接收/更新时刻及规则版本。通过统一时钟获取业务时间，新逻辑不散落 `System.currentTimeMillis()`；不能以演示固定时间评判生产数据。
- 坐标、距离单位及 AGL/AMSL 高度基准必须明确；缺少转换依据时返回未知/不可判定，不静默估算。不使用 0、在线、合法或成功代替缺失数据。

## 5. 身份、安全与审计

- 服务端从有效会话取得操作者；不信任客户端提交的用户、角色、组织范围、审批人或执行结果。授权必须覆盖动作、对象与数据范围，不能仅检查已登录或是否有某个角色码。
- 列表、详情、聚合统计、文件下载、日志和导出均需范围控制；过滤应发生在返回数据之前，不让前端承担生产隔离。
- 密码校验沿用受支持的密码编码器，禁止明文存储或记录口令。会话凭据、设备密钥、请求授权头不得进入日志、审计详情、源码或文档样例；配置样例只放空值与说明。
- 成功业务与成功审计保持一致提交。失败登录、拒绝授权等失败尝试也必须可靠留痕；设计并验证其事务边界，不能在会被回滚的事务中写完就认为记录保留，更不能给整个业务统一关闭回滚来解决审计问题。
- 审计以追加为原则，不通过普通业务接口编辑或删除历史。纠错留新记录；Mapper 只有 INSERT 不代表数据库防篡改或保管要求已满足。
- 真实受控动作需校验目标、设备、参数、授权依据及当前状态。演示双勾选不等于生产双人复核或审批；未经确认不得启用真实动作。
- 生产认证、配置和权限缺失时拒绝启动相关能力或明确报错，不以默认账号/Mock 兜底。不得将当前 Seeder 缺少环境门禁的做法复制到新增初始化器。

## 6. 业务状态机与外部动作

- 无人机、飞行风险和设备异常保留三套独立流程，精确状态及分支见开发基线。工作台只聚合并委托动作，不拥有另一套状态迁移实现。
- 无人机联动是一项共享用例，后续执行仍受确认后的授权和设备回执约束；通知处罚部门表示交接，不表示处罚办结，不增设手工归档步骤。
- 风险保留 `待核验/待通知/已通知/已排除`，通知发送和回执状态独立记录；何种真实结果允许进入“已通知”需对接确认，不用按钮点击当完成依据。
- 设备重启按原因确认、下发、回执、平台恢复验证推进。指令成功、设备在线、异常恢复不相互替代；验证失败保持未恢复并返回原因。
- 指令区分提交、受理、执行完成、失败和超时。发送尝试与同一逻辑指令关联；超时不证明设备未执行，重试前结合幂等能力及对账规则，禁止盲目重复受控指令。
- 回执校验来源和指令关联，支持去重、迟到/乱序及重启恢复；不允许普通客户端自行提交可信成功回执。不以“等待几秒”推进成功，定时器只可用于调度/超时处理。
- `mock/replay/live` 是已声明模式，不代表三类实现齐备。模拟器显式标记并限制环境；live 缺少适配器/凭据/协议时明确不可用，不降级。原始消息保留必要溯源信息，避免泄露敏感载荷。
- 文件元数据不等于文件已经存在。入库使用真实内容计算哈希，关联业务并控制访问；保留期限、冻结、删除按确认制度实现，不能按演示值自动销毁材料。

## 7. 环境、测试与命令

开发账号、Mock/回放数据和当前本地存储适配仅限明确开发测试环境。保留生产禁止公网依赖的约定；生产存储、部署网络及备份策略另行确认。环境敏感值通过部署配置注入，不读取或输出 `.env.local`。不得仅因文件名叫 `Local` 就假定 Spring 已限制其环境。

以下命令均在 `server/` 内执行；启动前按 README 准备隔离开发数据库，测试不连接生产库。

```powershell
# Windows PowerShell
.\mvnw.cmd test
.\mvnw.cmd package
# 本地启动
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```

```bash
# Linux/macOS：同样在 server/ 执行
./mvnw test
./mvnw package
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

- 当前 `AuthApiTest` 使用 `@ActiveProfiles("test")` 和 H2；这不是自动检测 Docker 后切换数据库。普通 `test` 会发现该类。交付时核对 `target/surefire-reports`。
- 新增普通测试使用默认可发现的 `*Test` 命名；若引入 `*IT` 生命周期，必须在获准的测试配置变更中明确绑定和验收命令。报告列出命令、实际用例数量、失败/跳过及环境，不能只报进程退出码。
- 后端 Java/资源/配置/依赖改动至少运行受影响测试和 `package`；身份、权限或共享安全改动显式跑当前认证测试。无法执行时报告具体缺失条件，不声称通过。
- SQL、空间查询、约束、锁和迁移变更必须在隔离 PostgreSQL/PostGIS 环境验证相关行为及迁移路径；H2 测试不能替代。没有环境时如实标记该项未验收，不偷偷使用现有业务数据库。
- 每条业务链覆盖正常与非法迁移、重复提交、并发冲突、重复/迟到/超时回执、恢复验证失败、服务重启、未知数据和模拟/真实隔离。鉴权覆盖过期、退出、停用、动作/范围越权；失败登录测试检查计数及审计是否实际落库。
- 正式回归测试和必要夹具放入 `src/test` 并纳入版本管理。前端目录的临时文件限制不禁止后端正式测试；一次性诊断脚本放系统临时目录，构建产物放 `target/`，不要提交缓存、日志、凭据或临时结果。
- 纯文档变更只做内容、路径、命令和差异检查，无须为此运行前后端构建；不得因此写“构建通过”。接口/前端变更按影响范围补契约和前端验证，遵循前端 AGENTS。

## 8. 修改与交付纪律

- 开始前检查 `git status`，保留用户的未提交内容和删除状态；只修改本任务范围，不恢复旧方案、不顺手清理缓存或无关文件。
- 搜索先用 `rg`，编辑用补丁；不运行破坏性 Git 恢复，不改全局 Git 安全配置解决单仓库诊断问题。需要删除、迁移数据或扩大依赖时先确认范围与权限。
- 发现代码、需求、规则冲突时说明当前行为和目标行为，不将注释中的“真实回执/已联调”当作验证证据。技术推断与实际复现分开记录。
- 改变公共约定、业务流程或实现状态时同步开发基线及最近的接口/运行说明；没有实际验证不得提升状态为验收完成。
- 交付前执行 `git diff --check`，检查新增文件的空白与链接，并报告实际通过、失败、未运行及剩余阻塞。本目录规则不授权额外功能或无关重构。

## Code Review Rules

- 阻止 Controller/页面私写状态、跨域直写表、事务失败后仍产生成功结果、重复设备指令或未鉴权回执推进状态。
- 阻止仅有登录检查却宣称权限完成、只增 Mapper 却宣称审计防篡改、只建消息表却宣称可靠投递完成。
- 阻止修改已应用迁移、全局接口改名、未知值伪装正常、混入演示账号/数据或真实模式静默回退。
- 阻止凭假文件、假回执、未确认规则及未实际执行的测试宣称交付通过。
