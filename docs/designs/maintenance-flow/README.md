# 运维待办与设备调测衔接设计

设计日期：2026-09-27。此目录为独立交互设计稿，使用示例数据，不调用业务 API、不下发设备指令、不写入业务数据。

## 基于当前页面的调整

- 复用现有管理端基础样式、品牌图形、导航与页签。
- 保留设备接入调测页的左侧设备列表和资料、中间参数配置、右侧实时调测结果、下方联调记录。
- 全局顶部增加运维消息铃铛。消息已读独立于待办处理状态；点击消息按设备 ID、待办 ID 定位。
- 调测页标题下方增加关联待办条，展示上报快照、异常、计划、处理人和进度。
- 原“记录处理结果”调整为“去处理 / 继续处理 / 查看结果”。
- 三栏工作区下方新增处理记录与时间线。保存进展不结束待办。
- 主按钮随状态变化：开始处理 → 提交恢复核验 → 执行恢复核验 → 查看处理结果。
- 核验通过后需填写结论、确认完成；核验失败返回处理中，历史记录保留。

## 演示方式

打开 index.html；也可通过本地静态服务预览。顶部预览状态选择器可直接查看待处理、处理中、待恢复核验和已完成。完整交互从“开始处理”依次体验。

消息跳转不会创建调测任务或执行指令。示例调测只测试界面状态流转。恢复核验弹窗中的情境选择器仅供设计演示，正式产品中不提供用户选择核验结果的入口。

## 实施边界

- 消息接收人需要由当前设备的数据范围、运维职责和权限共同决定，不能广播给所有后台用户。
- 完成状态需要真实服务端核验依据；调测通过不能替代原异常恢复，也不能用模拟结果关闭真实设备事件。
- MQTT 等不支持协议调测的设备保留相同待办条和处理记录，中间展示既有接入诊断信息与恢复核验入口。
- 无操作权限为只读，不显示可执行指令按钮；消息深链继续执行页面权限、设备范围和待办访问校验。
- 调测进行中禁止切换设备与提交恢复核验；已有调测任务应复用，不能因消息点击重复创建。
- 正式实施需要追加状态/关联关系迁移、消息接口和权限验证。本设计稿尚未实现这些业务能力。
