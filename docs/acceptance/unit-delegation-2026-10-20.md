## 已发现并修复的问题

| 问题 | 修复与验证要点 |
| --- | --- |
| 并发撤任可能读取锁前缓存 | 管理员身份在取得单位锁后重新读取并清除 MyBatis 会话缓存，避免撤任后旧请求继续修改。PostgreSQL 并发测试已覆盖。 |
| 旧普通动作 `READ/AUTH` 可能被错误移除 | 普通动作保留原有有效语义，纳管后规范化为 `OP`；直接反制仍须原有显式 `OP`，不把 `READ` 升级为直接反制授权。原共享角色不修改。 |
| 仅修改姓名、电话时审计信息不足 | 人员变更审计记录基本资料与角色的前后值，不记录明文密码。 |
| 预览重复显示“飞行监管” | 按稳定权限代码显示具体功能及级别变化，例如“飞行任务：操作→只读”；菜单关闭、动作移除单独标明。新增 H2/PostgreSQL 回归通过，最终运行页面显示待更新后确认。 |
| 跨单位预览容易被理解为完整业务可操作清单 | 明确其为当前读权限及原数据范围内的范围收缩记录；实际业务访问还受来源及业务状态限制。使用真实关联查询，不生成示例数量。 |
| 旧历史目标测试在空表时直接返回 | 原用例缺少谱系记录时未执行断言，却可能被统计为通过。现自建本次目标合并谱系，验证授权关联当前目标且不关联历史目标，并清理本次夹具；关闭旧回放种子后的 25 项处置授权补测通过。 |

## 操作入口与复验步骤

1. **平台设置**：后台 → 系统管理 → 用户管理 → 选中单位 → 单位授权。选择本单位管理员，配置功能与动作上限，打开预览，核对人员、角色、范围及业务关联变化后确认。
2. **单位人员管理**：单位管理员登录同一后台入口 → 本单位人员。新增或维护人员，选择本单位角色；所属单位与数据范围固定。首次创建账号后按现行临时密码流程改密。
3. **单位角色管理**：本单位角色 → 新增或编辑角色。在单位上限内分配权限；本人正在使用的角色显示平台维护，不允许自行调整。
4. **调整与撤任**：由平台进入单位授权办理。收紧后原账号重新登录，核对前后台入口与业务权限；扩大上限后确认原人员未自动获得新增权限。
5. **异常判断**：预览过期或人员、角色已变化时重新预览；版本冲突刷新后重试。不得通过扩大数据范围、直接修改数据库或使用全局后台角色绕过限制。
