# 设备运行趋势（2026-09-28）

管理端保持设备树、运行信息、告警栏布局。上方显示当前运行信息，下方历史趋势分为感知统计、上报趋势、状态历史三个 Tab；不重复最近目标数、当前连接状态等当前读数。不支持感知数量的设备隐藏感知 Tab。摘要仅保留时段目标峰值、均值或有效报文总量，状态历史直接展示曲线，不填充占位卡片。图表使用真实记录，无数据不生成示例值。

监测页默认收起连接表中的原始工作状态码、设备上报时间和平台接收时间，可展开诊断详情；异常筛选仍检查所有字段。连接表移除无业务含义的“已登记”状态列，各组自动隐藏空说明列。设备工参和感知报文仍保留过期、缺失状态。调测与档案页面不受影响。

## 接口

`GET /api/v1/device-monitor/devices/{device_id}/trends?range=1h`

沿用 Bearer、`monitoring.read`、设备业务范围检查和 `{ok,data,error}`。`range` 仅允许 `1h/24h/7d`，分别按 1/15/60 分钟聚合；无效范围返回 400，不存在或不可见设备返回 404。

`data` 包含 `device_id, protocol_code, range, from, to, bucket_ms, simulated, sensing_supported, metrics, reports`。两组数组按 `code,at` 排序，时间均 epoch 毫秒。每个桶含 `code,at,samples,average,minimum,maximum,latest,last_at,interval_seconds`；无间隔的首条记录省略 `interval_seconds`。缺失桶不返回。

- 指标曲线为桶内均值，感知卡片为所选时段的原始峰值及按样本帧数加权的均值；帧内目标数不是时段去重目标总数。
- MQTT 报文量来自 `mqtt_receive_diagnostic` 的 ACCEPTED，排除重复、拒绝、冲突、忽略记录。报文类型按接入原因划分工参、心跳、感知及其他有效报文。横轴按平台接收时间；合法迟到感知帧仍计入接收量，不等同实时有效目标量。
- 直连雷达计数来自已保存的航迹、点迹、RTK 历史样本；不冒充全部 TCP 帧或心跳总量。控制器来自有效状态回报。接收间隔按同类报文计算，不是网络延迟。
- 凌云感知帧数量、MQTT/EO 连接及工作状态、控制器通道状态为新增历史采集，从部署后开始记录，不回填历史。沿用现有数值历史表，无新增迁移。
- 连接状态图是采样分桶视图，不是完整运行时长账本；同桶混合状态、无采样均为空缺。工作状态展示协议原始码，不推断含义；不计算在线率或在线时长。
- 数据按设备和 simulated 标识隔离；模拟/回放设备页面明确标记。MQTT 诊断表按固定绑定设备隔离。
- 前端每 10 秒刷新，继承页面暂停开关；手动刷新可在暂停期间执行。切换设备、范围或查询失败会清除旧值，过期响应不会覆盖新查询。

## 验证

前端覆盖真实零值与断点、报文分类、混合状态、Tab/时间范围切换、暂停和旧响应隔离。后端覆盖范围/权限、设备隔离、模拟隔离、有效报文计数与间隔。SQL 在隔离 PostgreSQL schema 验证，接入回归覆盖 MQTT、EO、直连雷达和控制器。
